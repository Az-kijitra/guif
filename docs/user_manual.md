# guif ユーザーマニュアル(0.3.0)

guif は、キーボード操作を中心にした Windows 用のファイラーです。このマニュアルは、インストールとアンインストール、設定フォルダー、画面と操作を説明します。概要は [README](../README.md)、変更点は [変更履歴](../CHANGELOG.md) を参照してください。

対象環境は Windows 10 または Windows 11(64 ビット版)です。

## 1. インストール

1. インストーラー `guif_0.3.0_x64-setup.exe` を実行します。
2. 画面の案内に従って進めます。インストールは現在のユーザーだけに行われ、管理者権限は求められません。既定のインストール先は `%LOCALAPPDATA%\guif` です。
3. 終わったら、スタートメニューの「guif」から起動します。デスクトップのショートカットは、完了画面で「デスクトップにショートカットを作る」を選んだときに作られます(サイレント実行の `/S` と `/P` では常に作られます)。

Microsoft Edge WebView2 ランタイムが無い PC では、インストーラーがインターネットから取得して導入します。

### 1.1 SmartScreen の警告

このインストーラーにはコード署名がありません。インターネットから入手したインストーラーを実行すると、Windows の SmartScreen が「Windows によって PC が保護されました」という警告を出すことがあります。次の手順で進めます。

1. 警告の画面で「詳細情報」を選びます。
2. 表示される「実行」を選びます。

入手元が分かっているインストーラーであることを確かめてから実行してください。

## 2. アンインストール

Windows の「設定」の「アプリ」(Windows 11 では「インストールされているアプリ」、Windows 10 では「アプリと機能」)から「guif」をアンインストールします。管理者権限は求められません。

アンインストールの画面に「アプリのデータを削除する」というチェックがあります。

- チェックを外したまま(既定)アンインストールすると、インストール先のファイル、スタートメニューとデスクトップのショートカット、アンインストール情報が消えます。guif の設定フォルダーは残ります。入れ直すと設定が戻ります。
- チェックを入れてアンインストールすると、設定フォルダーと WebView2 のデータのフォルダーも消えます。

## 3. 設定フォルダー

guif の設定フォルダーは `%APPDATA%\dev.guif.app` です。次のファイルがここに置かれます。

| ファイル | 内容 |
|---|---|
| `config.toml` | 設定(キー割り当て、画面のテーマ、外部アプリ。§6、§7)。利用者が書くファイルです |
| `config.sample.toml` | 設定ファイルの見本(§8.3) |
| `navigation.toml` | 訪問履歴とジャンプリスト |
| `ui-state.toml` | 表示状態 |
| `viewer-window.toml` | ビューアのウィンドウの状態 |

- `config.toml` は最初はありません。無いときは既定の設定で起動します。メニューバーの「ファイル」の「設定ファイルを開く」(`Ctrl+,`)を使うと、`config.toml` が無いときは雛形が作られてから開きます(§8)。起動しただけでは作られません。
- `config.sample.toml` は、アプリが起動のたびと「設定ファイルを開く」のときに、無いか内容が違えば書き直します。編集しても元に戻ります。アプリはこのファイルを設定として読みません。設定は `config.toml` に書きます。

アンインストールで「アプリのデータを削除する」を入れなかったときは、このフォルダーが残ります。

## 4. 画面と基本操作

画面は上から、メニューバー、パスバー、本体(ファイル一覧とツリー)、ステータスバーの順に並びます。表示は日本語です。

### 4.1 メニューバー

メニューは左から「ファイル」「編集」「表示」「移動」の4つです。

- 開き方: `Alt` または `F10` を押すとメニューバーに移ります。アクセスキーは `Alt+F`(ファイル)、`Alt+E`(編集)、`Alt+V`(表示)、`Alt+G`(移動)です。
- 操作: `←` `→` でメニューを切り替え、`↓` または `Enter` で開きます。`↑` `↓` で項目を選び、`Enter` で実行します。`Esc` で閉じます。
- 各項目の右側には、現在有効なキー割り当てが併記されます。キー割り当てを変えたときは、併記も変わります。「パスのコピー」と「設定ファイルのチェック」には対応するキーがないため、併記はありません。
- メニューの項目は、元のフォーカスがどこにあっても、ファイル一覧の対象に対して働きます。
- 実行できない項目は灰色で表示され、項目名の下に理由が小さく表示されます。無効の項目は実行できません。

項目は次のとおりです(括弧内は既定のキー)。

| メニュー | 項目 |
|---|---|
| ファイル | 開く(Enter)、OSの関連付けで開く(Shift+Enter)、新規作成…(Ctrl+N)、新しいフォルダー…(Ctrl+Shift+N)、名前の変更(F2)、削除(Delete)、ZIPに圧縮(Ctrl+Alt+Z)、ZIPを展開(Ctrl+Alt+X)、設定ファイルを開く(Ctrl+,)、設定ファイルのチェック、終了(Ctrl+Q) |
| 編集 | 切り取り(Ctrl+X)、コピー(Ctrl+C)、貼り付け(Ctrl+V)、パスのコピー、すべて選択(Ctrl+A)、選択の解除(Esc)、検索(/) |
| 表示 | ツリー(Ctrl+Shift+B)、隠しファイル(Ctrl+H)、サイズの列(Ctrl+Shift+S)、更新日時の列(Ctrl+Shift+T)、並び替え…(S) |
| 移動 | 親フォルダーへ(Backspace)、パス欄へ移動(Ctrl+L)、ファイル検索…(Ctrl+P)、履歴(Ctrl+Y)、ジャンプリスト(Ctrl+J)、ジャンプリストに追加(Ctrl+Shift+J) |

「表示」メニューの上の4項目は、現在の状態をチェックの印(✓)で示します。

「ファイル」の「OSの関連付けで開く」の後には、登録した外部アプリの項目が並びます(§7)。「設定ファイルを開く」と「設定ファイルのチェック」は「ZIPを展開」と「終了」の間にあり、いつでも実行できます(§8)。

### 4.2 ファイルとフォルダーを開く

- フォルダーは、その中へ移動します。
- ファイルは、`Enter` またはダブルクリックで開きます。画像(png、jpg、jpeg、bmp)、Markdown(md、markdown)、テキストはビューアで開きます。そのほかのファイルは、内容がテキストと判定されればビューアで、バイナリと判定されれば Windows の関連付けのアプリで開きます。
- `Shift+Enter` は、種類にかかわらず Windows の関連付けのアプリで開きます。
- 右クリックのメニューにも「開く」と「OSの関連付けで開く」があります。

### 4.3 パスバーとドライブの切り替え

- `Ctrl+L` でパスバーに入力できます。確定は `Enter`、取り消しは `Esc` です。`Tab` `Shift+Tab` `↓` も使えます。`Ctrl+L` で検索バーは閉じます。
- ツリーのドライブの一覧から、ドライブを切り替えます。

### 4.4 削除

「削除」(`Delete`)は、Windows のごみ箱への移動です。`Shift+Delete` は完全削除で、元に戻せません。

### 4.5 右クリックメニュー

ファイル一覧の行または余白を右クリックするとメニューが開きます。項目には「開く」「OSの関連付けで開く」「削除」「パスのコピー」、登録した外部アプリ(§7)などがあります。「パスのコピー」は、Windows のクリップボードの中身を上書きします。Windows のクリップボード履歴や同期が有効な場合は、そこにも残ります。

## 5. ビューア

ビューアはテキスト、Markdown、画像を別のウィンドウで表示します。ビューアにメニューバーはありません。

### 5.1 キー操作

ビューアのキー操作は固定で、キー割り当ての変更の対象ではありません。

| キー | 動作 |
|---|---|
| ↑ / ↓ | 縦に少しずつスクロール(Shift を併用すると大きく) |
| ← / → | 横に少しずつスクロール(Shift を併用すると大きく) |
| PageUp / PageDown | 1画面分スクロール |
| Home / End | 先頭 / 末尾へスクロール |
| Alt+← / Ctrl+PageUp | 前のファイル |
| Alt+→ / Ctrl+PageDown | 次のファイル |
| Ctrl + `+` / `-` / `0` | ズーム(Markdown と画像) |
| Ctrl + `9` / `2` | 画像を全体表示(Fit) / 200% |
| Esc / Ctrl+Q | ビューアを閉じる(Ctrl+Q はアプリを終了しません) |

Ctrl、Alt、Meta のいずれかを伴う矢印キー、PageUp / PageDown、Home / End は、上の表で割り当てたもの以外はスクロールしません。

### 5.2 画像

- 開いたときは全体が収まる大きさ(Fit)で表示されます。
- ズームは Ctrl + `+` / `-` / `0` / `9` / `2`、Ctrl + マウスホイール、ヘッダーの Fit / 100% / 200% のボタンでできます。
- 表示領域より大きい画像は、マウスのドラッグ、矢印キー、PageUp / PageDown、Home / End でスクロールできます。

### 5.3 テキストと Markdown

- シンタックスハイライト(色分け)は拡張子で言語を決めます。本文が 1,000,000 文字を超えるファイル、または 1 行が 10,000 文字を超えるファイルは、色分けせずに表示します。
- 読み込みの上限は、テキストが 2 MiB、画像が 50 MiB です。
- ビューア内の検索(Ctrl+F)やファイル選択(Ctrl+O)はありません。

## 6. キー割り当て

guif は Windows 標準のショートカットキー（Windows like）を基本としつつ、TUI 版の tuif と同様の Vim like なキー操作（H/J/K/L によるカーソル移動など）も既定で併用できるように割り当てられています。

既定のキー割り当ては次のとおりです。

| 操作 | 既定のキー (Windows like / Vim like) | 操作 ID |
|---|---|---|
| 上へ移動 | ↑, K | `move_up` |
| 下へ移動 | ↓, J | `move_down` |
| 左へ移動 | ←, H | `move_left` |
| 右へ移動 | →, L | `move_right` |
| 前のページ | PageUp, Ctrl+U | `page_up` |
| 次のページ | PageDown, Ctrl+D | `page_down` |
| 選択の切り替え / 開閉 | Space, V | `select_toggle` |
| すべて選択 | Ctrl+A, Shift+V | `select_all` |
| 選択の解除 | Esc | `clear_selection` |
| 開く | Enter | `open` |
| 親フォルダーへ | Backspace, Minus(-) | `go_parent` |
| 終了 | Ctrl+Q | `exit` |
| 設定ファイルを開く(§8) | Ctrl+, | `settings` |
| パス欄へ移動 | Ctrl+L | `focus_path` |
| 隠しファイルの表示の切り替え | Ctrl+H, Dot(.) | `toggle_hidden` |
| ツリーの表示の切り替え | Ctrl+Shift+B, T | `toggle_tree` |
| コピー | Ctrl+C, Y | `copy` |
| 切り取り | Ctrl+X, X | `cut` |
| 貼り付け | Ctrl+V, P | `paste` |
| 削除(ごみ箱へ) | Delete, D | `delete` |
| 名前の変更 | F2, R | `rename` |
| 新規作成 | Ctrl+N, A | `new_file` |
| 新しいフォルダー | Ctrl+Shift+N, Shift+A | `new_folder` |
| 検索 | / | `search` |
| 並び替え | S | `sort_menu` |
| 履歴 | Ctrl+Y | `history` |
| ジャンプリスト | Ctrl+J | `history_jump_list` |
| ジャンプリストに追加 | Ctrl+Shift+J, M | `jump_add` |
| ファイルのファジー検索 | Ctrl+P, Ctrl+F | `fuzzy_find_file` |
| サイズの列の表示の切り替え | Ctrl+Shift+S | `toggle_size` |
| 更新日時の列の表示の切り替え | Ctrl+Shift+T | `toggle_time` |
| ZIPに圧縮 | Ctrl+Alt+Z, Z | `zip_create` |
| ZIPを展開 | Ctrl+Alt+X, Shift+Z | `zip_extract` |

- **ファイルのファジー検索 (Quick Open)**: `Ctrl+P` または `Ctrl+F` を押すと、画面中央上部に検索パレットがポップアップします。カレントフォルダー配下の全ファイルを再帰的かつインクリメンタルにファジー絞り込みし、`↑` `↓`（または `Ctrl+P` / `Ctrl+N`）で選んで `Enter` を押すとそのファイルが存在するフォルダーへ移動してフォーカスします。`Esc` でキャンセルします。
- **ツリーでの Space キー**: フォルダーツリー（ドライブ／ツリー）にフォーカスがあるとき、`Space` キー（または `V`）はフォーカス中のフォルダーの開閉（展開／折りたたみのトグル）を行います（ファイル一覧のような複数選択チェックにはなりません）。
- 完全削除(`Shift+Delete` または `Shift+D`)は独立した割り当てではなく、「削除」のキーに Shift を加えた操作です。復元できません。

`Ctrl+,` は「設定ファイルを開く」(操作 ID は `settings`)です。`Ctrl+,` は `Ctrl+Q`(終了)と同じく固定のキーで、ほかの割り当てより先に働きます。`settings` に別のキーを書くとそのキーでも開けますが、`settings = ""` と書いても `Ctrl+,` は無効になりません。検索バーの入力中、ダイアログの表示中、パスバーの編集中にも働きます。右クリックメニューやメニューバーを開いているときは、それを閉じてから開きます。

この版では、F5(再読み込み)、F1(キー割り当ての案内)に対応する機能はありません。

### 6.1 キー割り当てを変える

キー割り当ては、設定フォルダー(`%APPDATA%\dev.guif.app`)の `config.toml` を手で編集して変えます。編集する画面はありません。`config.toml` は「設定ファイルを開く」(`Ctrl+,`。§8)で開けます。

`config.toml` に `[input_keymap_custom]` の表を書き、操作の ID を左辺、キーを右辺に書きます。

```toml
[input_keymap_custom]
copy = "Ctrl+Shift+C"
zip_create = ""
move_down = "ArrowDown,J"
```

- 既定を上書きするには、操作の ID にキーを書きます。
- 空の文字列(`""`)を書くと、その操作は無効になります。
- カンマで区切ると、1つの操作に複数のキーを割り当てられます。
- 修飾キーは `Ctrl`、`Alt`、`Shift`、`Meta` の順に並べ、`+` でつなぎ、最後にキー本体を書きます(例: `Ctrl+Shift+N`)。修飾キーの名前は大文字と小文字を区別しません。
- キー本体は、英数字1文字(大文字と小文字を区別しません)か、次の名前です: `ArrowUp`、`ArrowDown`、`ArrowLeft`、`ArrowRight`、`Enter`、`Escape`、`Delete`、`Backspace`、`Tab`、`Space`、`Home`、`End`、`PageUp`、`PageDown`、`F1`〜`F12`、`Comma`、`Plus`、`Minus`、`Dot`。名前の大文字と小文字は区別しません。
- `,` と `+` はそのままでは書けません(`,` は複数のキーの区切り、`+` は連結に使うため)。`Comma` と `Plus` と書きます。例: `Ctrl+Comma`、`Ctrl+Plus`。スペースは `Space`、`-` は `Minus`、`.` は `Dot` と書きます。
- 上の一覧にない名前は、キー割り当てとして受け付けられません。
- 操作の ID は、`move_up`、`move_down`、`move_left`、`move_right`、`page_up`、`page_down`、`select_toggle`、`select_all`、`clear_selection`、`open`、`go_parent`、`exit`、`settings`、`focus_path`、`toggle_hidden`、`toggle_tree`、`copy`、`cut`、`paste`、`delete`、`rename`、`new_file`、`new_folder`、`search`、`sort_menu`、`history`、`history_jump_list`、`jump_add`、`toggle_size`、`toggle_time`、`zip_create`、`zip_extract`、`fuzzy_find_file` です。
- `config.toml` はアプリの起動時に1回だけ読み込みます。変更は再起動で反映されます。
- `config.toml` が無いときは、既定のキー割り当てで起動します。読み込めないとき(書き方の誤りなど)は、既定のキー割り当てで起動し、その旨がステータスバーに表示されます。
- 起動時の表示には、誤りのある設定項目と `config.toml` の行番号が入ります(例: `config.toml の不正なキー割り当て 2 件を無視しました: copy(12 行目), undo(13 行目)。`)。読み方は §8.4 を参照してください。

### 6.2 配色・フォント・配置

画面の配色(`[theme]` / `[colors]`)、メイン画面のフォント(`[font]`)、画面の配置(`[layout]`)を設定できます。

#### 配色([theme] / [colors])

画面全体(メイン画面とビューア)の配色を決めます。Windows のアプリのテーマ設定(ライト / ダーク)には従いません。明るい配色か暗い配色かは、背景色(`bg`)から自動で決まります。タイトルバーの明暗もこれに従います。

`ui_theme` 設定は廃止されました。書いても使われず、不明な設定として通知されます。配色は `[theme]` の `preset` で指定してください。

```toml
[theme]
preset = "nord"
```

- `preset` に指定できる名前: `nord`(既定)、`default`、`monokai`、`catppuccin`(別名 `catppuccinmocha`)、`solarized`(別名 `solarizeddark`)、`light`。
- 大文字・小文字は区別せず、「`-`」「`_`」と空白は無視して比較します(例: `"Solarized-Dark"` と `"solarized"` は同じです)。
- `light` だけが明るい配色で、それ以外は暗い配色です。
- `[colors]` 表で、プリセットの各項目を個別に上書きできます(上書きした項目のみが変わり、未指定の項目はプリセットの値が保たれます)。

```toml
[colors]
bg = "#2E3440"
border = "#88C0D0"
border_inactive = "#4C566A"
cursor_fg = "#2E3440"
cursor_bg = "#8FBCBB"
folder = "#81A1C1"
file = "#ECEFF4"
executable = "#A3BE8C"
selected = "#EBCB8B"
status_bar_fg = "#E5E9F0"
status_bar_bg = "#3B4252"
menu_bar_active_fg = "#2E3440"
menu_bar_active_bg = "#88C0D0"
tree_current = "#88C0D0"
tree_cursor = "#EBCB8B"
```

- 色の書式: `"#RRGGBB"`、`"#RGB"`、0〜255 の色番号(例: `"208"`)、色名(例: `"red"`、`"dark_gray"`、`"light_blue"`。大文字小文字は区別しません)、`"reset"`(背景では黒、他は文字色)。
- キーの別名: `background` は `bg`、`selected_mark` は `selected` と同じです。

#### フォント([font])

メイン画面のすべての文字(メニュー、パス欄、ステータスバー、検索バー、右クリックメニュー、ダイアログ、ファイル一覧、フォルダーツリー)のフォントと大きさを設定します。ビューアのウィンドウには影響しません。

```toml
[font]
family = "JetBrains Mono"
size = 12
```

- `family`: フォントの家族名を文字列または文字列の配列(例: `["Consolas", "BIZ UDGothic"]`)で指定します。指定した名前から順に試され、利用できない名前はスキップされて次の名前が使われます。末尾には既定の並び(`JetBrains Mono`, `JetBrainsMono NFM`, `JetBrainsMono NF`, `Cascadia Mono`, `Consolas`, `BIZ UDGothic`, `monospace`)が続きます。
- `size`: 文字の大きさ(px)です。10〜24 の整数で、既定は `12` です。メイン画面のすべての文字がこの大きさになります。行の高さは文字の大きさに合わせて自動決定されます(12 のとき 16px)。

#### 画面の配置([layout])

```toml
[layout]
min_col_width = 24
tree_width_percent = 24
```

- `min_col_width`: ファイル一覧の1列あたりの最小の幅を文字数(10〜80 の整数、既定 `24`)で指定します。サイズ列表示時は +10文字、更新日時表示時は +20文字が加算されます。
- `tree_width_percent`: フォルダーツリー表示時のツリーパネルの幅の割合(10〜50 の整数%、既定 `24`)を指定します。

- 変更は再起動で反映されます。

## 7. 外部アプリで開く

選択したフォルダーやファイルに対して、あらかじめ登録したアプリを起動します。登録は `config.toml`(設定フォルダー `%APPDATA%\dev.guif.app` の中。§6.1)に書きます。編集する画面はありません。

### 7.1 起動のしかた

次の3つの入口があります。

- キー: 登録ごとに決めたキーを押します(既定の登録のキーは §7.2)。ファイル一覧またはツリーにフォーカスがあるときに働きます。検索バーの入力欄に入力しているときは働きません。キーを押し続けても、起動は1回だけです。
- メニューバー: 「ファイル」の「OSの関連付けで開く」の後に、登録したアプリの項目が並びます。項目の右側に、その登録のキーが併記されます。
- 右クリックメニュー: 行を右クリックすると「OSの関連付けで開く」の後に、余白を右クリックすると「貼り付け」の後に、登録したアプリの項目が並びます。

対象は次のように決まります。

- キーとメニューバーでは、ファイル一覧のフォーカスのある行です。複数の行を選択していても、フォーカスのある1行だけが対象です。行が無いとき(空のフォルダーなど)は、現在のフォルダーが対象です。
- 右クリックメニューでは、右クリックした行です。余白を右クリックしたときは、現在のフォルダーが対象です。
- 対象がフォルダーのときは、そのフォルダーを渡します。対象がファイルのときに何を渡すかは、登録の書き方(`{path}` と `{dir}`。§7.3)で決まります。

起動に成功すると、ステータスバーに `「{名前}」を起動しました` と表示されます。起動したアプリの中で起きたことは、guif には分かりません。起動できなかったときは、次のように表示されます。

| 表示 | 意味 |
|---|---|
| `「{名前}」を起動できませんでした。実行ファイルが見つかりません: {実行ファイル}。` | 登録の `program` のファイルがありません。 |
| `「{名前}」を起動できませんでした。対象が見つかりません。` | 対象のフォルダーやファイルが、消えたか種類が変わりました。 |
| `「{名前}」を起動できませんでした。 詳細: {Windows の文言}` | アクセスが拒否された、管理者の権限が要るなど、Windows が起動を断りました。 |
| `「{名前}」を起動できませんでした。パスが正しくありません。` | 対象のパスが正しくありません。 |

### 7.2 既定の登録

`config.toml` に `external_apps` を書かないときは、次の4つが使われます。

| 名前 | キー | フォルダーが対象 | ファイルが対象 |
|---|---|---|---|
| ターミナルで開く | `Ctrl+Alt+C` | そのフォルダーで Windows Terminal を開く | ファイルのあるフォルダーで開く |
| VS Codeで開く | `Ctrl+Alt+V` | そのフォルダーを VS Code で開く | そのファイルを開く |
| エクスプローラーで開く | `Ctrl+Alt+E` | そのフォルダーを開く | ファイルのあるフォルダーを、そのファイルを選んだ状態で開く |
| GitHub Desktopで開く | `Ctrl+Alt+Shift+G` | そのフォルダーで GitHub Desktop を開く | ファイルのあるフォルダーで開く |

- GitHub Desktop は、フォルダーが Git のリポジトリかどうかを確かめずに起動します。
- アプリが入っていない PC では、その項目を使うと「実行ファイルが見つかりません」と表示されます。

既定の4つは、`config.toml` に次のように書いた場合とまったく同じです。一部だけを使いたいとき、キーや並びを変えたいときは、これを書き写して直します。

```toml
[[external_apps]]
name = "ターミナルで開く"
program = "wt.exe"
args = ["-d", "{dir}"]
key = "Ctrl+Alt+C"

[[external_apps]]
name = "VS Codeで開く"
program = "%LOCALAPPDATA%\\Programs\\Microsoft VS Code\\Code.exe"
args = ["{path}"]
key = "Ctrl+Alt+V"

[[external_apps]]
name = "エクスプローラーで開く"
program = "%SystemRoot%\\explorer.exe"
args = ["{dir}"]
args_for_file = ["/select,", "{path}"]
key = "Ctrl+Alt+E"

[[external_apps]]
name = "GitHub Desktopで開く"
program = "%LOCALAPPDATA%\\GitHubDesktop\\GitHubDesktop.exe"
args = ["{dir}"]
key = "Ctrl+Alt+Shift+G"
```

エクスプローラーの `args_for_file` は `"/select,"` と `"{path}"` の2つの要素に分けて書きます。1つの要素(`"/select,{path}"`)にすると、パスに空白があるときに正しく渡りません。

### 7.3 登録の書き方

1つの登録を `[[external_apps]]` の見出しの後に書きます。上から順に、メニューに並びます(最大20件)。

| 項目 | 必須 | 内容 |
|---|---|---|
| `name` | 必須 | メニューの項目名と表示に使う名前 |
| `program` | 必須 | 起動する実行ファイル |
| `args` | 任意 | 引数の配列。書かなければ引数なし |
| `args_for_file` | 任意 | 対象がファイルのときの引数の配列。書かなければ `args` を使う |
| `key` | 任意 | キー。書き方は §6.1 と同じ(カンマで区切って複数書けます)。書かなければキーなし |

- `external_apps` を書くと、書いた登録だけが使われ、既定の4つは使われません。登録を1つも使わないときは `external_apps = []` と書きます。
- `external_apps = []` のように `=` で書くときは、`[input_keymap_custom]` などの見出しより前(ファイルの先頭の側)に書きます。見出しの後に書くと、その表の中の項目として扱われます。`[[external_apps]]` の見出しで書く登録は、ほかの表の後に書いてかまいません。
- 正しくない登録(必須の項目が無い、型が違う、21件目以降など)は使われず、起動時にステータスバーに番号が表示されます。`external_apps` 全体の型が違う(配列でない、配列の中に表でないものがある)ときは、既定の4つが使われ、その旨が表示されます。
- `config.toml` はアプリの起動時に1回だけ読み込みます。変更は再起動で反映されます。

引数の中では、次の書き方が置き換えられます。

| 書き方 | 置き換わるもの |
|---|---|
| `{path}` | 対象のパス(フォルダーならそのフォルダー、ファイルならそのファイル) |
| `{dir}` | 対象のフォルダー(フォルダーならそのフォルダー、ファイルならファイルのあるフォルダー) |
| `{{` / `}}` | 文字の `{` / `}` |

- 置き換えは要素の一部でもかまいません(例: `"--folder={dir}"`)。1つの要素は、空白を含んでいても1つの引数として渡ります。
- 上の表に無い書き方(`{cwd}`、`{PATH}` など)や、対にならない `{` `}` を含む登録は正しくない登録になります。
- 引数の中の `%` は展開されず、そのまま渡ります。

`program` は次のどちらかで書きます。

- 絶対パス(例: `C:\Tools\app.exe`)。
- 区切りの無い実行ファイルの名前(例: `wt.exe`)。環境変数 `PATH` のフォルダーから探します。現在のフォルダーや guif のフォルダーは探しません。
- 実行ファイルは `.exe` に限ります。`.bat`、`.cmd`、`.ps1`、ショートカット(`.lnk`)は使えません。
- `program` の中の `%名前%` は、起動時に環境変数の値に置き換えます(例: `%LOCALAPPDATA%`)。名前は英字・数字・`_`・`(`・`)` で、先頭は英字か `_` です。それ以外の `%` は文字のまま残ります。定義されていない環境変数を使った登録は使われません。
- TOML の文字列の中では、`\` を `\\` と書きます(例: `"C:\\Tools\\app.exe"`)。

キーについて:

- 次のキーは登録では使えません。使えないキーは、起動時にステータスバーに表示されます。
  - 固定のキー(`Ctrl+Q`、`Ctrl+Comma`、`Shift+Enter`、`Shift+Delete`、`Tab`、`Shift+Tab`、`F10`、`Alt+F`、`Alt+E`、`Alt+V`、`Alt+G`)。
  - 現在のキー割り当て(§6)で使われているキー。
  - 先に並ぶ登録が使っているキー。
- キー割り当ての側でキーを変えると、空いたキーを登録で使えます。例: `[input_keymap_custom]` で `zip_create = "Ctrl+Shift+Z"` と書くと、`Ctrl+Alt+Z` を登録で使えます。
- `Ctrl+Alt+E` は、メニューバーの `Alt+E`(編集)とは別のキーです。
- AltGr を使うキーボード配列では、`Ctrl+Alt+文字` のキーが届かないことがあります。その場合は `key` を別のキーにしてください。

### 7.4 注意

- コマンドプロンプト(`cmd.exe`)や PowerShell(`powershell.exe`)などのコンソールのプログラムを `program` に直接書くと、ウィンドウは開きますが入力を受け付けません。Windows Terminal を経由して登録してください(下の例)。
- `cmd.exe` を経由して引数を渡す場合、フォルダー名に `&` や `%` などがあるとコマンドプロンプトがそれを解釈し直します。その結果の責任は登録した人にあります。
- 対象のフォルダー(起動するアプリの作業フォルダー)のパスが260文字を超えると、起動できません(Windows の文言が表示されます)。

### 7.5 例

Windows Terminal で PowerShell を開く:

```toml
[[external_apps]]
name = "PowerShellで開く"
program = "wt.exe"
args = ["-d", "{dir}", "powershell.exe"]
key = "Ctrl+Alt+P"
```

Windows Terminal のプロファイルを指定して開く(プロファイル名は Windows Terminal の設定に合わせます):

```toml
[[external_apps]]
name = "Ubuntuで開く"
program = "wt.exe"
args = ["-p", "Ubuntu", "-d", "{dir}"]
```

全ユーザー向けにインストールした VS Code で開く:

```toml
[[external_apps]]
name = "VS Codeで開く"
program = "%ProgramFiles%\\Microsoft VS Code\\Code.exe"
args = ["{path}"]
key = "Ctrl+Alt+V"
```

## 8. 設定ファイルを開く・チェックする

設定は `config.toml`(設定フォルダー `%APPDATA%\dev.guif.app` の中。§3)に書きます。設定を変える画面はありません。メニューバーの「ファイル」の次の2つの項目で、`config.toml` を開いて編集し、書き方を確かめます。

| 項目 | キー | 動作 |
|---|---|---|
| 設定ファイルを開く | `Ctrl+,` | `config.toml` をエディターで開きます(§8.1) |
| 設定ファイルのチェック | なし | `config.toml` の書き方を確かめ、結果をステータスバーに表示します(§8.5) |

### 8.1 設定ファイルを開く

「設定ファイルを開く」は次の順に動きます。

1. 見本 `config.sample.toml` を書き出します(無いか、内容が違うときだけ。§8.3)。
2. `config.toml` が無ければ、雛形を作ります(§8.2)。
3. VS Code を探します。探すのは、利用者ごとにインストールした VS Code の場所 `%LOCALAPPDATA%\Programs\Microsoft VS Code\Code.exe` だけです。見つかれば、VS Code で `config.toml` を開きます。
4. 見つからなければ、`config.toml` を Windows の関連付けで開きます。`.toml` に関連付けが無いときは、Windows がアプリを選ぶ画面を出します。

- 全ユーザー向けにインストールした VS Code(`%ProgramFiles%\Microsoft VS Code\Code.exe`)や、`PATH` の `code` は使いません。その場合は関連付けで開きます。`config.toml` の `external_apps` の登録(§7)も使いません。
- 既にある `config.toml` は、内容が空でも、書き方に誤りがあっても、書き換えずにそのまま開きます。
- 開いても、今の設定は変わりません。編集した内容は、guif を再起動したときに反映されます。

結果はステータスバーに表示されます。

| 表示 | 意味 |
|---|---|
| `config.toml を VS Code で開きました` | VS Code で開きました。 |
| `VS Code が見つからないため、Windows の関連付けで config.toml を開きます` | VS Code が見つからないため、Windows の関連付けで開きます。 |
| `config.toml を作成しました。`(前に付く) | `config.toml` が無かったため、雛形を作りました。例: `config.toml を作成しました。config.toml を VS Code で開きました` |
| `config.toml を開けませんでした。 詳細: {Windows の文言}` | VS Code または関連付けのアプリを起動できませんでした。 |
| `config.toml を作成できませんでした。 詳細: {Windows の文言}` | 雛形を作れなかったため、開きませんでした。 |
| `config.toml を開けませんでした。ファイルではありません。` | `config.toml` という名前のフォルダーなど、ファイルでないものがあります。 |
| `config.sample.toml を書き出せませんでした。 詳細: {Windows の文言}`(後ろに付く) | 見本を書き出せませんでした。`config.toml` を開く処理は続けます。 |

### 8.2 雛形

`config.toml` が無いときに「設定ファイルを開く」を実行すると、雛形の `config.toml` が作られます。雛形には、すべての設定項目(`[theme]`、`[colors]`、`[font]`、`[layout]`、`[input_keymap_custom]`、`[[external_apps]]`)の説明、取り得る値、既定の値がコメントで書かれています。

- 行の書き分けは次のとおりです。
  - `## ` で始まる行は説明です。
  - `# ` で始まる行は設定の行です。右辺の値が、書かないときに使われる既定の値です。
- 設定を変えるときは、変えたい設定の行の先頭の `# ` を消してから値を書き換えます。表の中の設定(`[theme]`、`[colors]`、`[font]`、`[layout]`、`[input_keymap_custom]`、`[[external_apps]]`)は、その表の見出しの行の `# ` も消します。`# ` を消していない行は、書いていないのと同じです。
- 作った直後の雛形は、すべての設定の行がコメントのため、`config.toml` が無いときと同じ設定になります。
- `external_apps` の行の `# ` を消すと、書いた登録だけが使われ、既定の4つは使われません(§7.3)。
- 雛形は作るだけで、アプリがその後に書き換えることはありません。

### 8.3 見本ファイル

設定フォルダーの `config.sample.toml` は見本です。雛形と同じ内容(先頭の説明の数行だけが違います)で、アプリの版で使える設定がすべて書かれています。

- アプリは、起動のたびと「設定ファイルを開く」のときに、`config.sample.toml` が無いか、内容がアプリの持つ見本と違えば書き直します。同じなら書きません。
- 編集しても、次の起動で元に戻ります。設定は `config.toml` に書いてください。
- アプリは `config.sample.toml` を設定として読みません。
- 新しい版で設定項目が増えたときは、見本から必要な部分を `config.toml` に書き写します。アプリは既にある `config.toml` に項目を書き足しません。

### 8.4 起動時の表示

起動時に `config.toml` を読み、書き方を確かめます。誤りのある項目だけが既定の設定になり、正しい項目はそのまま使われます。ファイル全体を TOML として読めないときは、すべて既定の設定で起動します。誤りがあると、ステータスバーに次のように表示されます。

- 誤りのある設定項目と、`config.toml` の中の行番号(1 から数えます)を表示します。例: `config.toml の 4 行目の [theme] の preset を解釈できないため、nord を使います(使える値: "default"、"nord"、"monokai"、"catppuccin"、"solarized"、"light")。`
- 一覧は先頭の 5 件までを表示し、残りは `ほか {件数} 件` と表示します。ステータスバーに収まらない部分は省略されます。マウスのポインターを重ねると全文が表示されます。
- guif が知らない設定(綴りの誤りや廃止された設定など)は無視し、その旨を表示します。対象は、最上位の `[theme]`、`[colors]`、`[font]`、`[layout]`、`[input_keymap_custom]`、`[[external_apps]]` 以外の名前と、各表の規定外のキーです。例: `config.toml の不明な設定 2 件を無視しました: ui_theme(2 行目), external_apps の 2 番目の agrs(18 行目)。`
- `config.toml` に誤りか知らない設定があるときは、表示は 15 秒続きます。それ以外の起動時の表示は 6 秒です。
- `config.toml` が無いときは何も表示しません。起動時に `config.toml` が作られることもありません。

### 8.5 設定ファイルのチェック

「設定ファイルのチェック」は、その時点の `config.toml` を読み、起動時と同じ確かめ方をして、結果をステータスバーに表示します。

- 結果を表示するだけで、設定は変わりません。キー割り当て、テーマ、外部アプリの登録、メニューの項目は起動したときのままです。編集した内容は、guif を再起動したときに反映されます。
- 結果は、次に起動したときにどう扱われるかを表します。表示の先頭に `設定ファイルのチェック(次の起動での扱い): ` が付きます。
- `config.toml` を作ったり書き換えたりせず、見本も書き出しません。
- 何度でも実行できます。新しい結果は、表示中の前の結果や起動時の表示を置き換えます。

表示の例:

| 表示 | 意味 |
|---|---|
| `設定ファイルのチェック(次の起動での扱い): 問題はありません。変更は再起動で反映されます` | 誤りも知らない設定もありません。 |
| `設定ファイルのチェック(次の起動での扱い): config.toml がないため、既定の設定を使います。` | `config.toml` がありません。 |
| `設定ファイルのチェック(次の起動での扱い): config.toml の不正なキー割り当て 1 件を無視しました: copy(12 行目)。` | 誤りがあります。表示の書き方は起動時(§8.4)と同じです。 |

誤りがあるとき・読めないときの表示は 15 秒、問題が無いとき・`config.toml` が無いときの表示は 2.5 秒続きます。
