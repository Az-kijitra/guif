## 準備

### P-1 設定フォルダー `%APPDATA%\dev.guif.app` の退避と復元

実機の確認は普段の設定フォルダーを使うため、始める前に退避し、終わったら元に戻す。「設定ファイルを開く」は `config.toml`(無いとき)と `config.sample.toml` を作るので、作られたものを残すかは確認者が決める(2026-10-22 は発注者の判断で残した)。

1. guif を終了する。
2. 退避する(PowerShell)。

   ```powershell
   Rename-Item "$env:APPDATA\dev.guif.app" "dev.guif.app.bak-settings-check"
   Get-FileHash "$env:APPDATA\dev.guif.app.bak-settings-check\*" -Algorithm SHA256   # 退避時の記録
   ```

3. 確認の終わりに、確認で作られた `dev.guif.app` を削除(または別名に保存)し、退避した名前を `dev.guif.app` に戻す。戻した後、`Get-FileHash` が退避時の記録と一致することを確かめる。
4. `config.toml` が元から無かった場合は、戻した後に `config.toml` が無いこと(確認で作られたものが残っていないこと)を確かめる。

### P-2 開発版を起動するときの注意(ELECTRON_RUN_AS_NODE)

- Claude Code など VS Code の拡張機能から起動したシェルでは、環境変数 `ELECTRON_RUN_AS_NODE=1` が引き継がれる。そのシェルで `npx tauri dev` を起動すると、アプリが起動した `Code.exe` が Node.js として動き、VS Code の画面が出ない(アプリの不具合ではない。2026-10-22 の 1 回目はこれで開かなかった)。
- 開発版は次のように環境変数を外して起動する。

  ```bash
  env -u ELECTRON_RUN_AS_NODE -u VSCODE_ESM_ENTRYPOINT -u VSCODE_HANDLES_UNCAUGHT_ERRORS -u VSCODE_CRASH_REPORTER_PROCESS_TYPE npx tauri dev
  ```

- インストールした guif をスタートメニューから起動する場合は、この変数が無いので問題ない。
- 開発版はテスト用の範囲の指定なし(`REFLEXFILES_CONFIG_DIR` なし)で起動し、普段の設定フォルダーを使う。範囲が有効だと VS Code・関連付けは起動されず W-A7(`config.toml を開けませんでした。テスト用の範囲の外です。`)になる。

### P-3 VS Code を入れていない作業用のアカウント(ISS-0234 (i))

- SET-10〜SET-13 は、VS Code が利用者ごとの場所 `%LOCALAPPDATA%\Programs\Microsoft VS Code\Code.exe` に無いアカウントで行う。
- `LOCALAPPDATA` を書き換える方法は、WebView2 のデータの場所も変わるため使わない(AC-1609)。
- 用意: VS Code を入れていない Windows のアカウントを用意する(SPEC-0600-0001 AC-1470 で使った作業用アカウントが使えるかは、確認者が確かめて備考に書く。ISS-0234 (i))。そのアカウントで、`Test-Path "$env:LOCALAPPDATA\Programs\Microsoft VS Code\Code.exe"` が `False` であることを確かめてから始める。
- そのアカウントでは guif をインストールして(`/S` でも可。AC-1470 の手順)スタートメニューから起動する。開発版は使わない(リポジトリ・Node の環境が無いため)。
- `.toml` の関連付けは、エクスプローラーで `.toml` のファイルを右クリックして「プログラムから開く」「既定のプログラムの選択」で確かめる。関連付けがある状態(SET-10)と無い状態(SET-11)を作る。関連付けを消す場合は、確認の前の状態を記録しておき、確認の後に戻す。
- VS Code がシステム全体(`%ProgramFiles%\Microsoft VS Code\Code.exe`)に入っている状態(SET-12)は、確認者が入れて確かめ、確認の後に元に戻す。
