## 0. 経緯・出典

### 0.1 発注者決定(2026-10-14、変更不可)

**起票の前の決定(ISS-0218)**

- **【確定 #1】旧製品(ReflexFIles 0.2.0。`productName` = `ReflexFIles`、`identifier` = `com.toshi.reflexfiles`)は新製品で置き換える。** 新製品は、旧製品を利用者が削除してから入れる前提とする。
  - **【確定 #1-1】** インストーラーは、旧製品が入っていたら案内してインストールを中止する。**旧製品を自動で削除しない。**
  - **【確定 #1-2】** 設定フォルダは `identifier` が別なので引き継がない(旧製品の設定は残る)。
    - 【承認後の追補 2026-10-15・記録】旧製品の設定フォルダは実際には `identifier` ではなく `%APPDATA%\ReflexFIles\` だった(§1 の追補)。新製品の設定フォルダと別の場所であることは変わらず、決定の内容(引き継がない・旧製品の設定は残る)は不変。
- **【確定 #2】インストーラーは NSIS(`.exe`)のみとする。ユーザーごと(管理者権限なし、`%LOCALAPPDATA%` 配下)にインストールする。インストーラーの言語は日本語。**
- **【確定 #3】最初の配布のバージョンは 0.3.0(旧製品 0.2.0 の後継)。**
- **【確定 #4】アイコンは旧製品のアイコンを使う。** 旧 `main` の `app/src-tauri/icons/` 一式のうち、Windows で使うもの(`32x32.png`、`128x128.png`、`128x128@2x.png`、`icon.ico` 等)を持ち込む。android / Store 用の要否は T-01。
- 先行の決定: **発注者決定 2026-10-02**(ISS-0183): `productName` は `ReflexFiles` に変え、配布前に旧製品との衝突を確認する(SPEC-0300-0017 R-993 の承認時の追記)。

**レビューの後の決定(ISS-0219)**

- **【確定 M-1】発注者の普段使う Windows アカウント(作業用アカウント)には旧製品は入っていない(発注者の申告)。** それでも作業用アカウントでインストーラーを動かす前に、HKCU と HKLM(64 bit / 32 bit の両方のビュー)に旧製品の情報が無いことを確かめる。確認の後は新製品をアンインストールして元の状態(アンインストール情報・ショートカット・インストール先が残っていないこと)に戻し、その手順と結果を記録する(AC-1470)。旧製品を入れる確認とデータを消す確認は、従来どおり確認用の環境(別アカウント・Windows サンドボックス・VM)で行う。
- **【確定 M-2】旧製品はアンインストール済みだが、インストール先に旧製品のファイルが残っている場合は、上書きしてかまわない。** → R-1445 / R-1462 / AC-1423 / T-14。
- **【確定 S-6】README・変更履歴(CHANGELOG)・ユーザーマニュアルは日本語のみとする。** → R-1490。ISS-0009 の「対応言語」をこの範囲で決定として記録する。
- **【確定 T-01〜T-15】起票時の【提案 T-01〜T-15】は推奨案をすべて採用する。** ただし T-13 は M-1、T-14 は M-2 の内容で置き換える(§16)。

- **旧製品の版の値の食い違い(既存調査。SPEC-0500-0001 §2 R-04 の根拠)**: 旧リポジトリのルート `CHANGELOG.md` は 0.2.0 まで、`docs/CHANGELOG.md` は 0.4.0 + Unreleased、`app/package.json` は 0.5.0(既存調査は `new-feature-experiment` 基準。ISS-0010 によれば 0.5.0 は `new-feature-experiment` 側)。旧 `main` の `tauri.conf.json` は 0.2.0。旧製品として実際に配布された版は確認していない(ISS-0220 (b))。

- コード署名は無い(未署名の配布)。

### 0.4 Tauri 2 の NSIS に関する前提(【要確認】。設計工程で Tauri のバージョンに合わせて確かめる。ISS-0220)

spec-writer の知識による。本仕様の要求はこれらに依存しないように書いたが、AC の手順・期待値の一部はこれらを前提にしている。

**【レビュー S-4】前提と事実が違う場合は、要求に書いた結果(何が起きるか・起きないか)を優先する。Tauri の既定の手段で要求を満たせない場合は、人間の判断に付す。** 前提に依存するため、設計工程で事実を確かめた後に見直す値は次のとおり: AC-1400 の「`installMode` が `currentUser` 相当」、R-1401 / AC-1402 のインストーラーのファイル名、R-1461 の削除の範囲と AC-1440 / AC-1441 の「アプリのデータを削除する」チェック、R-1460 のスタートメニューのアンインストーラー、R-1471 / AC-1403 の実行ファイル名の手段、R-1480 / AC-1480 の WebView2 の導入、R-1443 の非対話の実行の種類。

- (a) `bundle.windows.nsis.installMode` に `currentUser`(既定とされる)/ `perMachine` / `both` がある。`currentUser` は管理者権限を求めず、`%LOCALAPPDATA%` 配下にインストールする。
- (b) アンインストール情報のキー名・インストール先のフォルダ名・スタートメニューのショートカット名は `productName` から作られる。発行者(Publisher)の既定は `identifier` から導かれる(旧製品と新製品で異なる可能性がある)。
- (c) 同じキーのアンインストール情報が既にあると、インストーラーは「既にインストールされている」ことを前提にした処理(版の比較、既存のアンインストーラーの呼び出しの提案など)を、インストールの開始より前に行う。**旧製品のアンインストール情報が新製品のものと同じキーに見える場合、旧製品が新製品の古い版として扱われ、旧製品のアンインストーラーが呼ばれうる。**
- (d) `installerHooks` には `NSIS_HOOK_PREINSTALL` / `NSIS_HOOK_POSTINSTALL` / `NSIS_HOOK_PREUNINSTALL` / `NSIS_HOOK_POSTUNINSTALL` がある。いずれもインストール(アンインストール)の処理の中で呼ばれ、(c) のページより後になる可能性がある。テンプレート自体を差し替える設定(`bundle.windows.nsis.template`)もある。
- (e) アンインストーラーに「アプリのデータを削除する」チェックがあり(既定はオフとされる)、オンのとき `%APPDATA%\<identifier>` と `%LOCALAPPDATA%\<identifier>` を消す。
- (f) WebView2 ランタイムの導入方法 `webviewInstallMode` の既定は `downloadBootstrapper`(ランタイムが無い場合だけ取得して導入)。
- (g) インストール時に同じアプリが実行中なら閉じるよう求める。インストーラーのファイル名は `<productName>_<version>_<arch>-setup.exe`。サイレント(`/S`)のほか、パッシブ(`/P`)・更新用(`/UPDATE`)等の非対話の実行の指定がある。スタートメニューにアンインストーラーのショートカットを作るかは版による。
- (h) 実行ファイル名は、既定では Cargo の実行ファイル名(`reflexfiles-successor.exe`)のままで、`productName` からは作られない(release ビルドの結果と一致)。名前を変える設定(`mainBinaryName`)の有無・効く範囲(配布物だけか、`target/release` の出力名も変わるか)は Tauri のバージョンによる。

### 0.4.1 【承認後の追補 2026-10-15】前提の確認結果(設計 `docs/architecture/proposals/SPEC-0200-0001.md` §3.15、guardian §28。生成された `installer.nsi` で裏取り)

- (a) インストール先は `%LOCALAPPDATA%\ReflexFiles`(ユーザーごと)。
- (b) アンインストール情報は `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\ReflexFiles`。ほかに `HKCU\Software\reflexfiles\ReflexFiles`(前回のインストール先と `Installer Language`)を書く。`Installer Language` は MUI2 が対話の実行と `/P` で書く。
- (c) `PageReinstall` は同じキーの旧製品を新製品の古い版として扱い、既定で旧製品のアンインストーラーを `ExecWait` で実行する(R-1441 の懸念は事実)。
- (d) フックはすべて `Section` の中で呼ばれる(ページより後)。`/S` ではページが実行されない。
- (e) アンインストーラーの「アプリのデータを削除する」チェックの既定はオフ。オフのときは `HKCU\Software\reflexfiles\ReflexFiles` も消さない(`installer.nsi:820-829` で消すのはチェックがオンのときだけ)。
- (g) スタートメニューにアンインストーラーのショートカットは作られない(R-1460 の【要確認】を確定)。
- **検出の手段(R-1441)**: 先頭の `Page custom` と最初の隠しセクションで行う。テンプレートの差し替えは不要(フックの `Section` より前、`PageReinstall` より前に検出できる。`/S` ではページが実行されないため隠しセクションで受ける)。
- 前提 (f)(h) と終了コード、ユーザーごとの MSI の情報の場所は ISS-0220 のとおり。

### 0.5 本仕様を新規に起こした理由(【導出】)

配布物・バージョン・インストーラーの振る舞い・配布前の確認は、ファイラーの機能(0300)でも、技術スタック(0200)・テスト戦略(0400)・ドキュメント(0500)の一部でもない。ISS-0183 が SPEC-0300-0017 R-993 の追記として残した論点を正本として扱う置き場所が無いため、新しい領域 0600(配布・リリース)を設け、新規の Spec ID とした。

## 5. 旧製品の検出と中止

- **[R-1440]【確定 #1-1】インストーラーは、旧製品がインストールされている状態を検出したら、案内を出してインストールを中止する。旧製品を自動でアンインストールしない。**
- **[R-1441]【導出。#1-1 と §0.4 (c) から】検出と中止は、インストーラーがシステムに何かを変更する前に行う。** 「変更」には、ファイルのコピー・削除、レジストリへの書き込み、ショートカットの作成、**旧製品のアンインストーラーの呼び出し**、WebView2 の導入を含む。Tauri の既定の「既にインストールされている」ことを前提にした処理(§0.4 (c))が旧製品に対して働く前に検出しなければならない。実現の手段(フック、テンプレートの差し替え等)は設計工程で決める。テンプレートの差し替えが要る場合は、新しい依存を追加せず、差し替えたテンプレートの Tauri の版との対応を設計文書に記録する。
  - **【レビュー S-1】** インストーラー(NSIS)が自身の動作のために一時フォルダ(`%TEMP%` の配下)へ展開し、終了時に消すもの(プラグイン等)は「変更」に含めない。
- **[R-1442]【確定 T-07、レビュー S-5 で改訂】案内は1つのダイアログで、次を日本語で示す。** (1) 旧製品 ReflexFIles がインストールされていること、(2) 新製品は旧製品を置き換えるもので、先に旧製品をアンインストールする必要があること、(3) アンインストールの方法(Windows の「設定」の「アプリ」から。Windows 11 では「インストールされているアプリ」、Windows 10 では「アプリと機能」)、(4) 旧製品の設定は引き継がれないこと、(5) インストールを中止すること。ボタンは「OK」の1つとし、押すとインストーラーは何も変更せずに R-1443 の終了コードで終了する。文言は §16 T-07。
- **[R-1443]【導出。レビュー S-1 で改訂】利用者の操作を伴わない実行すべて(サイレント `/S`、パッシブ `/P`、更新用 `/UPDATE` ほか、Tauri の NSIS が受け付ける非対話の指定。【要確認】§0.4 (g))では、ダイアログを出さずに中止し、終了コード `2` で終わる。** 何も変更しない。対話の実行で R-1442 の「OK」で終了した場合も終了コードは `2` とする。`2` は NSIS の慣例で「スクリプトによる中止」を表す値【導出】。
  - **【再レビュー S-2】終了コード `2` は「インストールを中止した」ことだけを表し、中止の理由が旧製品であることまでは示さない**(Tauri のテンプレートや NSIS が他の理由の中止でも `2` を返しうる)。そのため、旧製品による中止かどうかの判定(AC-1422)は、終了コードと、システムの状態が変わっていないことの確認とを合わせて行う。実装では中止の箇所で終了コードを明示的に設定する(`SetErrorLevel 2`。§13)。
- **[R-1444]【確定 T-06。レビュー M-3 で改訂】旧製品の判定は次による。**
  - **[R-1444-1] 判定する場所**: 次の3か所のアンインストール情報の下位キーすべて。(i) `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall`、(ii) `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall` の 64 bit のビュー、(iii) 同じキーの 32 bit のビュー(`HKLM\Software\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall`)。旧製品の MSI のアンインストール情報(製品コードのキー)もここに含まれる(ユーザーごとに入れた MSI のアンインストール情報の場所は ISS-0220 (b) で確かめる)。**インストールを実行している Windows アカウントの HKCU だけを調べ、同じ PC の他の Windows アカウントにユーザーごとに入った旧製品は検出の対象外とする**【導出】(他のアカウントのインストール先・アンインストール情報とは衝突しないため)。
  - **[R-1444-2] 比べる項目と相手**: 各下位キーの (a) キー名と (b) 値 `DisplayName` を、旧製品の `productName` の固定値 `ReflexFIles` と、**大文字小文字を区別せずに**完全一致で比べる。(a)(b) のどちらかが一致した下位キーを「同名の情報」とする(新製品自身のアンインストール情報も同名の情報に当たる)。
  - **[R-1444-3] 新製品の印**: 新製品のインストーラーは、自分が書くアンインストール情報に、新製品の `identifier` を値に持つ項目(値の名前は設計工程)を書く。同名の情報のうち、その項目の値が `dev.reflexfiles.successor` と一致するものを新製品とみなす。
  - **[R-1444-4] 判定**: 同名の情報のうち、R-1444-3 の印が無い(項目が無い、または値が一致しない)ものが1つでもあれば、旧製品が入っているとみなし R-1440 に従う。
  - 判定の誤りの扱い【導出】: 印の無いものを旧製品とみなす安全側とする。新製品の上書きインストールを旧製品と誤って中止することは、AC-1430(R-1450)で検出する。旧製品の実際の値(キー名・`DisplayName`)が `ReflexFIles` と一致しないことが ISS-0220 (b) の確認で分かった場合は、§0.4 の冒頭の規則に従い、R-1444-2 の比べる相手を設計工程で見直す(人間の判断に付す)。
- **[R-1445]【確定 T-14(発注者決定 M-2 の内容)】旧製品のアンインストール情報が無く(旧製品はアンインストール済み)、インストール先のフォルダに旧製品のファイルが残っている状態は検出の対象外とする。** インストーラーは通常どおりインストールし、残っているファイルを上書きしてよい。残っているファイルを残すことも消すことも求めない。
- **[R-1446]【確定 #1-2】旧製品の設定フォルダに、インストーラー・アンインストーラー・新製品は書き込まず、読まず、消さない。** 旧製品の設定を新製品へ移す機能は設けない(SPEC-0100-0004 R-02)。
- **[R-1447]【導出。レビュー MINOR】新製品を入れた後に旧製品のインストーラーを実行した場合の結果は対象外とする。** 旧製品のインストーラーは変更できず、新製品のアンインストール情報を旧製品自身のものとして扱いうる。README とマニュアルに「新製品を入れた後に旧製品のインストーラーを実行しない」ことを書く(R-1490)。
