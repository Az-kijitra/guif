### ISS-0001(RESOLVED): MVPの優先順位・開発フェーズ分割
- 関連Spec: SPEC-0100-0001, SPEC-0300-0001
- 経緯: 要件ドラフト §5.3 で TBD とされ、人間レビュー(2026-09-22)で「この場では決定せず、仕様書作成(spec-writer)工程で改めて検討する」とされた。
- spec-writerの判断: 優先順位・フェーズ分割は原資料(ヒアリングメモ)に決定の根拠がなく、発注者の意思決定事項である。spec-writer が断定すると「未決定事項を勝手に確定仕様にしない」原則に反するため、確定せず起票する。
- 判断に必要な論点(参考。いずれも spec-writer の提案であり、原資料に出典はない):
  - a. 全機能を一括で再構築するか、段階リリースするか
  - b. 段階リリースする場合の最小動作単位の候補(例: SPEC-0300-0002 一覧/ツリー + SPEC-0300-0003 キーボード操作 を土台とし、以降に SPEC-0300-0005 ファイル操作等を積む)
  - c. SPEC-0300-0008(ReflexViewer統合)は規模が大きく(既存2,675行)、フェーズ分割の主要な判断対象となる(ISS-0007 と連動)
- 必要アクション: 発注者への確認。
- **【発注者確認 2026-09-22】**: 候補bを採用。SPEC-0300-0002(ファイル一覧/ツリービュー)+ SPEC-0300-0003(キーボードナビゲーション)を最小動作単位(Phase 1)とし、これを土台として以降SPEC-0300-0005(ファイル操作)等を段階的に積む。Phase 1の詳細仕様化(ISS-0006)から着手する。

### ISS-0003(矛盾): 要件の基準ブランチと既存調査の調査対象ブランチの不一致
- 関連Spec: SPEC-0100-0005(R-01, R-02), SPEC-0300-0001〜0008
- 内容: 要件は「既存ReflexFiles = `main` ブランチ」を維持対象の基準と確定している(要件ドラフト §1.1)。一方、既存調査 `existing-20260922-reflexfiles-overview.md` の実装箇所・行数・ファイル構成の記録は、調査時HEAD である `new-feature-experiment`(mainから107コミット先行、未コミット変更29ファイルあり)を対象としたものである。research-verifier は GitPanel / WinMerge / デュアルペインの3ファイルが `main` に存在しないことを確認したが、**基本7機能を含むその他の実装箇所が `main` 上でも同一かは未検証**である。
- 影響: SPEC-0300-0002〜0008 に記載した「既存実装の参照点」が、基準ブランチ `main` の実態と異なる可能性がある。また「README記載の基本7機能」の README 自体も、引用元は調査時HEAD の README.md 6-13行目であり、`main` の README が同一内容であることは未確認。
- spec-writerの判断: 各仕様に注記を残し、断定を避けた。参照点の妥当性判断は人間およびcodebase-researcher再調査に委ねる。
- 必要アクション: `main` ブランチを対象とした既存調査の再実施(少なくとも README と7機能の実装有無)。
- **【追加検証 2026-09-22、オーケストレーターによるgit直接確認】**: FileList.svelte, TreePanel.svelte, keyboard_list.ts, fs_query.rs, zip.ts, viewer/+page.svelte, history.ts の7ファイルが`main`上に存在することを確認した。また`app/src/lib`配下のファイル数は`main`=315、`new-feature-experiment`=320とほぼ同数であり、既存調査3.2/3.3が懸念した「SRPリファクタ前のGod module状態」が`main`で顕著に異なるという事態ではないことを確認した。これにより SPEC-0300-0002〜0008 の参照点が`main`と大きく乖離している可能性は低いと判断できるが、行番号レベルの完全一致は未検証のまま(スポットチェックに留まる)。ステータスは PENDING_HUMAN_REVIEW のまま維持するが、リスクは当初想定より低いと評価する。
