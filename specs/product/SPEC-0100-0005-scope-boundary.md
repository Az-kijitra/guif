## 1. 基準ブランチ

- **[R-01] 「既存ReflexFiles」とは `main` ブランチを指す。** 新プロダクトが維持すべき「既存の基本機能」の判定基準は、既存リポジトリの `main` ブランチ(基本7機能のみを含み、リリース済みと見なす状態)である。
- **[R-02] 実験ブランチは基準に含めない。** 既存調査の実施時にチェックアウトされていた `new-feature-experiment` ブランチ(`main` から107コミット進み、未コミット変更を含む)は、mainに未統合の実験的開発ブランチであり、「既存ReflexFilesの基本機能」の判定基準には含めない。
- 注記1: 既存調査の記述の多くは `new-feature-experiment` を対象に行われている。既存調査を参照する際は、記載された実装箇所が `main` 上に存在するかを都度確認すること(→ ISS-0003)。
- 注記2: `main` の最終コミットは `a62954e`(メッセージ "test", 2026-02-18)であり、「リリース済みと見なす状態」という前提との齟齬が未解消である(→ ISS-0010)。R-01 は発注者の確定判断をそのまま記載したものであり、基準点の同定は本仕様では行わない。

## 2. スコープ外(今回の新プロダクトに含めない)

- **[R-03] Git連携パネル(ビルトイン、Ctrl+G)を含めない。** 今回のスコープ外。ただし将来のロードマップ候補として記録する(SPEC-0900-0001)。
- **[R-04] WinMerge連携(外部差分ツール起動、Ctrl+W)を含めない。** 今回のスコープ外。ただし将来のロードマップ候補として記録する(SPEC-0900-0001)。
- **[R-05] デュアルペイン(2画面)モード / F3切替を含めない。** 完全にスコープ外であり、将来のロードマップ候補としても記録しない。
- **[R-06] Storage Provider抽象化層を含めない。** `storage_provider.rs` に相当する ResourceRef / StorageProviderBackend トレイト抽象化、および `*_by_ref` 系コマンド群(fs_list_dir_by_ref 等9コマンド)は新プロダクトに実装しない。
- **[R-07] Google Drive連携に関する一切を含めない。** 実装・UI・設定項目に加え、以下も新プロダクトに一切持ち込まない。
  - ドキュメント記述(既存 `user_manual.md` および `app/src-tauri/resources/user_manual.*.md` の Google Drive 関連記述:gdrive:// パス、OAuthセットアップ、Real/Stubバックエンドモード、Write-back、Settings > Advanced の認証ブロック等、約80行)
  - 残骸コード全般(`Cargo.toml` の `gdrive-readonly-stub` featureフラグ、`refreshGdriveWorkcopyBadges` のno-opプレースホルダ、`resolveGdriveWorkcopyBadge` プロパティ配線等)
- **[R-08] スコープ外機能の痕跡を残さない。** R-03〜R-07 の対象については、無効化されたコード・featureフラグ・no-opプレースホルダ・命名の残存を含め、新プロダクトのコードベースおよびドキュメントに痕跡を残さないこと(SPEC-0500-0001 と整合)。

## 4. スコープ外機能の追加確定(ISS-0004/ISS-0012解消、2026-09-22)

- `main` ブランチに存在するが「基本7機能」に含まれない機能(ドラッグ&ドロップ、Undo/Redo、外部アプリ起動、設定の診断レポート/バックアップ・リストア等)は、**今回の新プロダクトのスコープには含めない**。発注者確認により「今回は除外し、後日改めて検討する」と確定した(ISS-0004)。
- SPEC-0900-0001(将来ロードマップ)のGit連携パネル/WinMergeとは異なり、「将来必要になる可能性が高い」という積極的な位置づけではなく、単純に今回のスコープ外として扱う。ロードマップ候補としての記録は行わない。
- 本仕様R-03〜R-07(スコープ外機能の痕跡排除)は、この追加スコープ外機能群にも同様に適用する(残骸コード・プレースホルダ・ドキュメント記述を残さない)。
