## 1. 仕様

- **[R-01] ドキュメントは実装と一致した正確な内容とする。** README / ユーザーマニュアル / CHANGELOG は、新プロダクトの実装状態と一致していること。
- **[R-02] 実在しない機能を案内しない。** 実装されていない機能(撤去済み・未実装・スコープ外)の使用方法をドキュメントに記載しない。
  - 特に Google Drive 連携に関する記述は一切含めない(SPEC-0100-0005 R-07)。
- **[R-03] ドキュメント内の参照パスは実在すること。** README等から参照するファイルパス(開発ガイド、保守ガイド、ビューア仕様書等)は、参照先が実際に存在すること。存在しないファイルへのリンクを残さない。
- **[R-04] CHANGELOG は単一の正とする。** 同一プロダクトに対し内容の異なる複数のCHANGELOGを併存させない。配置場所を1つに定め、README から明示的に案内する。
- **[R-05] 実装済み機能をドキュメントに反映する。** ユーザーが利用できる機能は、ユーザー向けドキュメントに記載する(未文書化機能を作らない)。
- **[R-06] 多言語版ドキュメントの内容を一致させる。** 英語版と日本語版など複数言語のドキュメントを提供する場合、記載内容に食い違いを生じさせない。
- **[R-07] 配布物に同梱されるドキュメントを対象に含める。** インストーラ等でエンドユーザーへ配布されるマニュアルリソースも R-01〜R-06 の対象とする。

## 2. 根拠・出典

要件ドラフト §5.4【人間レビュー結果 2026-09-22】「要件に含める。新プロダクトのドキュメント(README/マニュアル/CHANGELOG)は実装と一致した正確な内容とし、実在しない機能の案内やパスの不整合を残さない。確定。」

各条項が是正対象とする既存の不整合(既存調査 3.1):
- R-02: 既存調査 3.1-3。ルート `user_manual.md` 131,249-324行目 および `app/src-tauri/resources/user_manual.en.md` が、コミット `ca2f80c`(2026-03-17)で撤去済みのGoogle Drive機能を約80行にわたり説明したまま残存。
- R-03: 既存調査 3.1-1, 4。README.md 43-45,47行目が参照する `docs/development_guide.md`, `docs/maintenance_guide.md`, `docs/ja/maintenance_guide.ja.md`, `docs/VIEWER_SPEC.md` が実在しない。
- R-04: 既存調査 3.1-2。ルート `CHANGELOG.md`(0.2.0まで、Unreleasedは「TBD」)と `docs/CHANGELOG.md`(0.4.0 + Unreleased)の内容が食い違い、`app/package.json` のバージョン 0.5.0 はどちらにも記載がなく、どちらが正か判別不能。
- R-05: 既存調査 3.1-4。ビルトインGitPanel(Ctrl+G)/ WinMerge連携(Ctrl+W)がユーザーマニュアルに未記載。
- R-06: 既存調査 1.2-3 の research-verifier訂正。デュアルペイン(F3)は日本語マニュアルには記載があるが、README・ルート `user_manual.md`・`resources/user_manual.en.md` には記載がない。
- R-07: 既存調査 3.1-3(`app/src-tauri/resources/user_manual.*.md` はインストーラ同梱でエンドユーザーへ配布される想定)。

**【ISS-0016解消済み・発注者確認 2026-09-22】**: R-05, R-06, R-07はspec-writerが要件ドラフト§5.4の確定文言(「実装と一致した正確な内容とし、実在しない機能の案内やパスの不整合を残さない」)を超えて導出した条項だったが、発注者に提示の上「全て採用する(妥当な提案)」との確認を得た。確定要件として扱う。

## 3. 本仕様では確定しない事項(→ ISS-0009)

- 新プロダクトで提供するドキュメントの種類・構成(README / ユーザーマニュアル / CHANGELOG 以外に開発ガイド・保守ガイド・ADR等を設けるか)
- 対応言語(英語のみか、日本語版も提供するか)
- ドキュメントと実装の整合性を担保する手段(レビュー運用か、自動チェックか)
