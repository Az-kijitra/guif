# Spec ID 台帳

階層構造で仕様を管理する。Spec IDは `SPEC-<領域番号>-<連番>` 形式(例: SPEC-0100-0001)。

## 領域一覧

新しい領域を追加する場合はspec-writerが本表に領域番号を追記する。

| 領域番号 | 領域名 | ディレクトリ | 説明 |
|---|---|---|---|
| 0100 | プロダクト方針 | `specs/product/` | 目的・再構築方式・命名・互換性・スコープ境界 |
| 0200 | アーキテクチャ・技術基盤 | `specs/architecture/` | 技術スタック、モジュール構成、IPC |
| 0300 | コア機能 | `specs/features/` | ファイラーとしてのユーザー向け機能 |
| 0400 | 品質・テスト | `specs/quality/` | テスト戦略、品質基準 |
| 0500 | ドキュメント | `specs/documentation/` | README/マニュアル/CHANGELOG の要件 |
| 0900 | ロードマップ | `specs/roadmap/` | 今回スコープ外だが将来候補として記録する事項(要件ではない) |

## ステータス定義
- DRAFT: spec-writerが作成、未レビュー
- IN_REVIEW: spec-reviewerが検証中、または人間レビュー待ち(PENDING_HUMAN_REVIEW)
- APPROVED: 人間承認済み、ベースライン化(以降の変更は差分管理)
- DEPRECATED: 廃止
