## 0. 改訂の位置づけ

### 0.1 前版との関係

- 前版 SPEC-0300-0006 は「選択した項目から ZIP を作成できる」「ZIP を展開できる」(R-01 / R-02)という粒度に留まり、§3 で「展開時の衝突解決」「ZIP 以外の形式」「パスワード付き ZIP・文字コード」を未確定として ISS-0006 に送っていた。
- 本改訂は Phase 5 として、`main` 基準の詳細調査と 2026-09-26 の発注者確定事項に基づき、実装着手可能な粒度(画面仕様・操作仕様・受入基準)へ詳細化する。Phase 1〜4 で確立した改訂パターン(既存 APPROVED 仕様を新 Spec ID の改訂版として起票する。前例: SPEC-0300-0007 → SPEC-0300-0013 ほか)を踏襲する。
- 前版の確定条項(R-01 / R-02)は §2 に継承する。
- **前版 §2 の記述の誤り**: 前版は `main` のバックエンドを「`zip_create` / `zip_extract` / `zip_extract_list_conflicts`」と記しているが、**`main` に `zip_extract_list_conflicts` は存在しない**(登録コマンドは `zip_create` / `zip_extract` の2本のみ。前版の記述は `new-feature-experiment` 基準の既存調査に由来する誤りであり、ISS-0003 の一例である)。【根拠: 調査§0.1 / main:app/src-tauri/src/bootstrap.rs:41-42、Evaluator所見(`git grep zip_extract_list_conflicts main -- app` 該当なし)】
  - 本仕様は展開前の衝突検出を**新プロダクトの仕様として新規に規定する**(R-371)。その際のバックエンド操作は前版の名称を流用して `zip_extract_list_conflicts` と呼ぶが、これは `main` 由来ではない(§0.2 #1、ISS-0087)。

- **[R-320] 作成はモーダルダイアログを経由する。** ダイアログは少なくとも「対象の件数」「出力ファイルのパス(編集可能)」「作成」「キャンセル」を持つ。【根拠: 調査§3 / main:app/src/lib/components/modals/ZipModal.svelte(作成 = 対象件数、出力先、エラー1行)】

  - **[R-320-2] 出力パス欄は Enter で確定、Escape で取消できる。** ダイアログを開いた時点で出力パス欄にフォーカスを置く。【導出。SPEC-0300-0011 R-61(リネームダイアログ)と同じ操作感に揃える。`main` のダイアログは既定フォーカスが実行側(index 0)であった: 調査§3, §8 #8】→ ISS-0113
    - 本ダイアログは入力ダイアログであり、破壊的操作の確認ダイアログではないため、既定フォーカスを「キャンセル」とする SPEC-0300-0011 R-35 の対象ではない。上書きを伴う場合は別途 R-326 の確認ダイアログを経由する。【導出】
  - **[R-320-3] ダイアログ表示中はファイル一覧 / ツリーのキー操作を発火させず、キーマップ経由の `exit` も評価しない。** ダイアログ自身が処理するキー(Enter / Escape / 入力欄での文字入力 / ボタン間移動)はオーバーレイ内ローカルキー処理とする。【SPEC-0300-0010 第8版 R-13 / **R-14-3** / §3.1 分類 (c) #8 の適用】
- **[R-321] 出力パスの既定値は「現在表示中のディレクトリ\\<既定名>」とし、既定名は、対象が1件なら「対象の名前 + `.zip`」、2件以上なら `archive.zip` とする。** 対象の名前に拡張子があっても置き換えず末尾に `.zip` を追加する(例: `a.txt` → `a.txt.zip`、フォルダ `docs` → `docs.zip`)。【根拠: 調査§1 / main:app/src/lib/actions/zip.ts:14-19】
- **[R-322] 出力パスはフルパスとして自由に編集できる。** 空文字の場合は作成を行わず、ダイアログ内にエラーを表示する。【根拠: 調査§1(モーダルで出力ファイルのフルパスを自由編集可、空はエラー)】
  - **[R-322-1]【第2版で新設・ISS-0114】出力パスに相対パス(ドライブ指定・ルートを持たないパス)が入力された場合は、アプリのプロセスのカレントディレクトリではなく、現在表示中のディレクトリを基準として解釈する。** ファイル名のみの入力(例: `out.zip`)は現在表示中のディレクトリ直下を指す。ドライブ相対パス(`C:x`)・ルート相対パス(`\x`)は解釈が曖昧になるため `invalid_path` で拒否する。【導出】→ ISS-0114
- **[R-323] 確定された出力パスのファイル名が `.zip` で終わらない(大文字小文字を区別しない)場合は、末尾に `.zip` を自動付与する。** 付与後のパスを以降の同名判定(R-326)・作成に用いる。【導出。`main` は拡張子の自動付与・検証を行っていなかった: 調査§1】→ ISS-0113
  - ダイアログ上で付与後の名前を事前表示するか(入力中にプレビューするか)は規定しない。【導出】
- **[R-324] 出力パスのファイル名部分には SPEC-0300-0011 R-62 の名前検証(空文字 / `.` / `..` / 9種の禁止文字)を適用し、違反は `invalid_name` としてダイアログ内に表示する。** 出力パスの親ディレクトリが存在しない場合の扱いは TBD(R-324-1)。【導出。`main` は名前の専用検証を持たない: 調査§1】

### 4.4 一時ファイルと途中失敗

- **[R-328] 作成は、出力パスと同じディレクトリ内の一時ファイルへ書き込み、全エントリの書き込みが成功した時点で一時ファイルを出力パスの名前へリネームして完成させる。**【**発注者確定 2026-09-26(§0.2 #6、ISS-0092)**。`main` は最終名へ直接書き込み、途中失敗で不完全な ZIP が出力先に残った: 調査§1, §8 #5】
  - 一時ファイルを出力パスと同じディレクトリに置くのは、リネームを同一ボリューム内の操作とするためである。一時ファイルの命名規則は architecture-mapper / code-generator 工程に委ねるが、既存ファイルと衝突しない名前とする。【導出】
  - **[R-328-4]【第3版で新設・ISS-0116】一時ファイルの名前は、最終名(出力ファイル名)に依存しない固定長の名前とする。** これにより、名前の長い正当な出力ファイルが、一時ファイル名の長さのために構成要素長・最大パス長の制限を超えて失敗することがない。【設計で確定(guardian MUST-71)、発注者承認 2026-09-27】
  - **[R-328-1] 作成中に1件でも読み取り・書き込みのエラーが発生した場合は、その時点で作成を中断し、一時ファイルを削除したうえでエラーを表示する。** 読み取れない項目をスキップして作成を続けることはしない。【**発注者確定 2026-09-26**(失敗時は一時ファイルを削除)。最初のエラーで中断すること自体は `main` 踏襲: 調査§1(読み取り不能ファイルは即 Err、最初のエラーで全体中断)】
  - **[R-328-2] キャンセルされた場合も一時ファイルを削除し、出力パスには何も残さない**(上書き対象の既存ファイルがあればそれは変更されない。R-326-4)。【**発注者確定 2026-09-26(§0.2 #5 / #6)**】
  - **[R-328-3] TBD: 要確認** — アプリのクラッシュ・強制終了により一時ファイルが残った場合の後始末(次回起動時の掃除等)を行うか。本仕様の提案は「行わない」(一時ファイルは利用者が削除できる通常のファイルとして残る)【導出】。→ ISS-0100
- **[R-329] 作成の成功・失敗は単一の結果として返す**(Phase 2 のバッチ結果〈成功件数・失敗一覧〉ではない)。失敗時の結果は少なくともエラーコード・メッセージ・失敗した対象のパスを持つ。【導出。作成は単一の出力ファイルを完成させるか否かの操作であり、R-328-1 により部分成功が存在しないため】

### 5.2 展開先の既定

- **[R-342] 展開先の既定値は「ZIP ファイルと同じディレクトリ\\<ZIP ファイル名から拡張子 `.zip` を除いた名前>」とする**(例: `C:\work\a.zip` → `C:\work\a`)。【**発注者確定 2026-09-26(§0.2 #3、ISS-0089)**。`main` の既定は現在ディレクトリ直下であり、サブフォルダを作らず既存ファイルと混在した: 調査§2】

### 5.3 展開の実行

- **[R-345] 展開は、事前検証(§6)→ 衝突検出(§7)→ 衝突がある場合の確認 → 実行、の順で行う。** 事前検証で拒否された場合は、衝突の確認を利用者に求めない。【導出。拒否されるアーカイブについて衝突の判断を求めても無意味であるため】
- **[R-346] 展開は ZIP 内のエントリをファイル・ディレクトリとして展開先へ書き出す。** ディレクトリエントリ、およびファイルエントリの親として必要なディレクトリを作成する。【根拠: 調査§2 / main:app/src-tauri/src/fs_ops_archive.rs:111-168】
  - **[R-346-1]【第2版で新設・H-4】ZIP64 拡張を用いたアーカイブ(エントリ数 65,535 超、または 4 GiB 超のエントリ / アーカイブ)も展開の対象とする。** ZIP64 であること自体を理由に拒否しない(上限は R-365 で別に評価する)。【導出。作成側で ZIP64 を用いる(R-327-9)ことと対にする】
  - **[R-346-2]【第3版で新設・ISS-0116】展開したファイル・ディレクトリには、エントリに記録された更新日時を復元する。** ファイルは最終名へのリネーム後(R-348)に、ディレクトリは配下のエントリの書き出しがすべて終わった後に設定する(配下への書き込みでディレクトリの更新日時が変わるため)。展開によって新たに作成したディレクトリにのみ適用し、展開前から存在していたディレクトリの更新日時は変更しない。記録が無い・不正な日時のエントリは復元しない。**更新日時の設定に失敗しても展開自体は失敗にせず、利用者への通知も行わない。**【更新日時の復元は発注者承認 2026-09-27。細部は【導出】】
  - **[R-346-3]【第3版で新設・ISS-0116】ZIP に記録されたファイル属性(読み取り専用・隠し・システム等)は、展開したファイル・ディレクトリに適用しない。**【発注者承認 2026-09-27】
- **[R-347]【第3版で方針を記録】エントリ名の文字コード**: UTF-8 フラグ(汎用ビットフラグの bit 11)が立っているエントリ名は UTF-8 として解釈する。**フラグが立っていないエントリ名は、バイト列が UTF-8 として妥当なら UTF-8、そうでなければ CP932 として解釈する**ことを方針とする。この方針は実験(zip crate の実挙動、代表的なツールで作成した ZIP での確認)の後に確定する(ISS-0099 は実験後に RESOLVED)。【方針は設計で確定・発注者承認 2026-09-27(ISS-0116)。第2版までは TBD。`main` はデコード処理を持たず `file.name()` をそのまま使っており、zip crate 7 の既定挙動に依存していた(実挙動は不明)】→ ISS-0099
  - 本仕様が確定として要求するのは、**どの解釈を採った場合でも、解釈後の名前に対して §6 の検証を適用する**ことである(解釈の結果として生じる `\` や `:` 等も検証対象になる)。【導出】
- **[R-348] 各ファイルエントリは、展開先の最終名とは別の一時ファイルへ書き込み、そのエントリの書き込みが完了した時点で最終名へリネームする。** したがってエントリの書き込み途中でエラー・キャンセルが起きても、書きかけのファイルが最終名で残らず、上書き予定だった既存ファイルもそのエントリについては変更されない。【導出(提案)。`main` は最終名へ直接書き込み、エントリ単位の破損で書きかけファイルが残った: 調査§2, §8 #5】→ ISS-0101
  - 中断時に書きかけだった一時ファイルは削除する。【導出】
  - **[R-348-1]【第3版で新設・ISS-0116】一時ファイルの名前は、最終名(エントリ名)に依存しない固定長の名前とする。** 名前の長い正当なエントリ(R-363 #9 / #10 の範囲内)が、一時ファイル名の長さのために失敗しないこと。【設計で確定(guardian MUST-71)、発注者承認 2026-09-27】
- **[R-349] 展開中、書き込みの各時点で、展開済みデータ量が当該エントリの宣言サイズを超えた場合は、その時点で展開を中断し `zip_corrupt` とする。**(上限 L-4、R-365。第2版で参照誤り〈R-366〉を訂正)【導出】
  - **[R-349-1]【第2版で新設・ISS-0114】エントリの展開を終えた時点で、展開したデータの CRC-32 が当該エントリに記録された CRC-32 と一致しない場合は、当該エントリを最終名へリネームせずに一時ファイルを削除し、展開を中断して `zip_corrupt` とする**(R-350 に従い、それ以前のエントリは残す)。実データ量が宣言サイズに満たない場合も同様とする。【導出】

### 5.4 途中失敗とキャンセル

- **[R-350] 展開は、最初のエラーで中断する。** 中断までに展開(最終名へリネーム)済みのファイル・作成済みのディレクトリは**削除せずに残す**(ロールバックしない)。【**発注者確定 2026-09-26(§0.2 #6、ISS-0092)**。最初のエラーで中断しロールバックしないことは `main` と同じ: 調査§2】
  - 帰結として、上書きを選択して展開した場合、中断までに上書きされた既存ファイルは元に戻らない。【導出。発注者確定 #6 の帰結として明示する】
- **[R-351] 展開がエラーまたはキャンセルで途中終了した場合は、「途中まで展開した」ことを利用者に通知する。** 通知には少なくとも次を含める: 途中終了の理由(エラーのコードとメッセージ、またはキャンセルされたこと)/ 展開済みのエントリ数と総エントリ数 / 展開先のパス / (エラーの場合)失敗したエントリのアーカイブ内パス。【**発注者確定 2026-09-26(§0.2 #5 / #6)**(通知すること)。通知内容の項目は【導出】】
  - **[R-351-1] 通知の手段は、エラーによる途中終了はエラーダイアログ(モーダル)、キャンセルによる途中終了はステータス表示とする。**【導出(提案)。キャンセルは利用者の意図した操作であるため確認操作を要求しない。ただし展開済みファイルが残る事実はステータスで必ず示す】→ ISS-0101
  - 1件も展開する前に中断した場合(先頭エントリでのエラー、事前検証での拒否等)は「途中まで展開した」旨ではなく、単にエラー(またはキャンセル)として通知する。【導出】
- **[R-352] 展開の結果は、少なくとも「展開済みエントリ数」「総エントリ数」「展開先」「途中終了した場合の理由(コード・メッセージ・対象エントリ)」を持つ構造で返す。**【導出。`main` は `Result<(), String>` のみを返していた: 調査§2, §4 の表。R-351 の通知に必要な情報】

### 6.3 展開先の包含検査(リンク経由の脱出防止)

- **[R-366] 各エントリを書き出す直前に、書き出し先の親ディレクトリを正規化(シンボリックリンク・ジャンクションを解決した実パス。canonicalize 相当)し、それが正規化した展開先ディレクトリの配下にあることを検査する。** 配下にない場合は展開を中断し `zip_entry_rejected` とする(R-350 に従い、展開済みは残す)。【**発注者確定 2026-09-26(§0.2 #7)**。`main` は展開先内の既存シンボリックリンク / ジャンクション経由の脱出を検査しない: 調査§2 の「限界」】

- **[R-367] 書き出し先の最終名に既存のシンボリックリンク・ジャンクション(リンク先の無いものを含む)がある場合は、それを辿って書き込まない。** 展開開始前の衝突の事前検出(R-371)でこれを検出した場合は、展開全体を `zip_entry_rejected` として拒否する(何も書き込まない。R-362 #11)。事前検出の後に現れた場合は、書き出し時点で検出して当該エントリで展開を中断する(`zip_entry_rejected`、R-350)。【導出。リンク先の実ファイルを上書きしてしまうことを防ぐ。事前検出での拒否は第2版で追加(ISS-0114)】→ ISS-0101
  - 最終名の既存リンクは「上書き」の選択肢で置き換えられる衝突としては扱わない(R-372-2 の存在判定では存在とみなされるが、確認ダイアログには載せずに拒否する)。【導出】
- **[R-367-1]【第2版で新設・ISS-0114】展開中のアーカイブファイル自身を、エントリの書き出しによって上書きしない。** 書き出し先(正規化後、R-325-1 と同じ同一性判定)が展開中のアーカイブと同一になるエントリがある場合は、事前検証で展開全体を拒否する(`zip_entry_rejected`、R-362 #11)。【導出。例: `C:\work\a.zip` を展開先 `C:\work` へ展開し、エントリ `a.zip` を含む場合】

## 14. 受入基準

Phase 5(ZIP 作成 / 展開)の完了判定に用いる。**【第3版の注記】各 AC に付した「ISS-0094 / ISS-0100 / ISS-0101 確定後に検証する」のゲートは、第2版承認(2026-09-27)と第3版で解消済みであり、確定した条項の内容で検証する(AC-321-1 はリンクをスキップ、AC-332 はエントリ単位の一時ファイル、AC-349-1 は展開全体を `conflict` で事前拒否、AC-367 はリンクエントリを含む ZIP を `zip_entry_rejected` で丸ごと拒否、AC-385 は R-398 のとおり)。ISS-0099 のゲート(AC-329)のみ残る。**すべて「〜できること / 〜であること」形式でテスト可能な粒度とする。

**受入基準の役割分担(ISS-0025 の再発防止)**: 「`zip_create` / `zip_extract` の既定キーを押すと当該アクションが発火する」ことの検証は **SPEC-0300-0010 §9.7 AC-45 を正本**とする(同 AC は前版 SPEC-0300-0006 を参照しており、参照先の更新が必要 → ISS-0096 項目 (a)。同 AC の期待キーは `Ctrl+Alt+Z` / `Ctrl+Alt+X` のみであり、vim キーの扱いの更新は vim プロファイルの廃止〈ISS-0102〉により不要となった)。本仕様の受入基準は**発火後の結果**のみを検証する。フォーカス / 選択状態そのものの検証は SPEC-0300-0009 を正本とする。

### 14.1 起動と操作対象

- **[AC-300]** 複数のエントリを選択した状態で ZIP 作成を起動すると、作成ダイアログに選択した件数が表示され、作成された ZIP に選択した全件が含まれること。(R-307, R-320)
- **[AC-301]** 選択が0件でフォーカスのみがある状態で ZIP 作成を起動すると、フォーカス中の1件が対象になること。(R-307)
- **[AC-302]** 選択もフォーカスも無い状態で ZIP 作成を起動すると、ダイアログが開かず、ステータスに対象が無い旨が表示されること(無反応にならないこと)。(R-307)
- **[AC-302-1]【第2版】** 3件を選択した後、検索の絞り込みで1件だけが表示される状態にして ZIP 作成を起動すると、作成ダイアログの対象件数が1件であり、作成された ZIP に非表示の2件が含まれないこと。選択していたすべての項目が非表示になり、フォーカス中のエントリも非表示の状態では、ダイアログが開かず対象が無い旨がステータスに表示されること。(R-307-1)
- **[AC-303]** 選択が0件で `.zip` ファイルにフォーカスがある状態で ZIP 展開を起動すると、当該 ZIP を対象とする展開ダイアログが開くこと。拡張子が大文字(`.ZIP`)の場合も同様であること。(R-308, R-309)
- **[AC-304]** ZIP 展開を起動したとき、(a) 対象が0件、(b) 対象が2件以上、(c) 対象が1件だが ZIP でない(フォルダ / `.zip` 以外のファイル)、のそれぞれで、ダイアログが開かず、各場合を区別できる理由がステータスに表示されること(3ケース)。加えて、(d) 選択中の `.zip` が検索の絞り込みで非表示になり他に表示中の対象が無い場合は (a) と同じ理由が表示され、非表示の ZIP が展開対象にならないこと(第2版)。(R-308-1, R-307-1)
- **[AC-305]** `.zip` ファイルにフォーカスがあり、別の非 ZIP ファイルを1件だけ選択している状態で ZIP 展開を起動すると、選択中の非 ZIP ファイルが対象として判定され「ZIPファイルではありません」(第4版 承認後の追補で空白なしに統一)相当の理由が表示されること(フォーカス中の ZIP が展開されないこと)。(R-308-2)
- **[AC-306]** 検索入力欄にフォーカスがある状態で ZIP 作成 / 展開の既定キーを押しても、作成 / 展開のダイアログが開かないこと。(R-306-1、SPEC-0300-0010 R-14-2)

### 14.2 ZIP 作成

- **[AC-307]** 対象1件(`a.txt`)で作成ダイアログを開くと、出力パスの既定値が「現在のディレクトリ\\a.txt.zip」であること。対象がフォルダ `docs` の場合は `docs.zip`、対象が2件以上の場合は `archive.zip` であること。(R-321)
- **[AC-307-1]【第2版】** 作成ダイアログ / 展開ダイアログを開いた時点で出力パス欄 / 展開先欄にフォーカスがあり、Enter で確定(作成 / 展開の処理へ進む)、Escape で何もせずに閉じること。ダイアログ表示中に `input_keymap_custom.exit` に割り当てた修飾なしのキー(例: `Q`)を入力欄で押しても、アプリが終了せず文字として入力されること。(R-320-2, R-320-3, R-340-3、SPEC-0300-0010 R-14-3)
- **[AC-308]** 作成ダイアログにパスワード入力欄が存在しないこと。(R-320-1)
- **[AC-309]** 出力パスに `out`(拡張子なし)を指定して作成すると `out.zip` が作成されること。`out.ZIP` を指定した場合は `.zip` が重ねて付与されないこと。(R-323)
- **[AC-310]** 出力パスを空にして確定すると、作成が行われずダイアログ内にエラーが表示されること。出力ファイル名に禁止文字(例: `a?.zip`)を含めると `invalid_name` が表示されること。いずれもダイアログが閉じずに再入力できること(第2版)。(R-322, R-324, R-395-1)
- **[AC-310-1]【第2版】** 出力パスに `out.zip`(ファイル名のみ)を入力して作成すると、アプリのプロセスのカレントディレクトリではなく現在表示中のディレクトリに `out.zip` が作成されること。`C:x.zip` や `\x.zip` を入力すると `invalid_path` がダイアログ内に表示されること。(R-322-1)
- **[AC-311]** 出力パスに既存のファイルがある状態で作成を確定すると、上書き確認ダイアログが表示され、選択肢が「上書き」「キャンセル」の2つであること。(R-326, R-326-1)
- **[AC-312]** 上書き確認ダイアログを開いた時点で既定フォーカスが「キャンセル」にあり、Enter のみを押した場合に既存ファイルが変更されず、作成ダイアログに戻り、出力パス欄に直前の入力値が保持されていること。(R-326-1, R-326-2, R-326-2-1)
- **[AC-313]** 上書き確認で「上書き」を選択すると、既存ファイルが新しく作成した ZIP で置き換わること。(R-326)
- **[AC-314]** UI を経由せず作成処理を直接呼び出し、出力パスに既存ファイルがあり上書きの指示が無い場合、既存ファイルが変更されず `conflict`(ISS-0088 で確定したコード)で拒否されること。(R-326-3)
- **[AC-315]** 対象に読み取りできないファイルを含めて作成すると、作成がエラーで中断し、出力パスにファイル(不完全な ZIP)が残らず、一時ファイルも残っていないこと。(R-328, R-328-1)
- **[AC-316]** 出力パスに既存ファイルがあり「上書き」を選択した作成が途中で失敗またはキャンセルされた場合、既存ファイルが元の内容のまま残っていること。(R-326-4, R-328-2)
- **[AC-317]** 作成の進行中に出力パスを確認すると、最終名のファイルがまだ存在しないこと(一時ファイルに書き込まれていること)。(R-328)
  - 検証方法(第2版): 「進行中」の時点は、バックエンドの単体テストで作成処理の進捗通知(エントリ単位のコールバック)の中から出力パスの有無を検査することで作る(実機の目視やタイミング依存の待機を前提としない)。
- **[AC-318]** サブフォルダ・空ディレクトリを含むフォルダ `docs` から作成した ZIP を展開すると、`docs/` をルートとして元の階層がそのまま再現され、空ディレクトリも存在すること。アーカイブ内のパス区切りが `/` であること。(R-327-1〜R-327-3)
- **[AC-319]** 作成した ZIP のファイルエントリの圧縮方式が Deflate であり、暗号化されていないこと。(R-327-4, R-327-5)
- **[AC-319-1]【第3版】** 更新日時が互いに異なるファイルとサブディレクトリ(例: 2020-01-02 03:04:06 等、偶数秒の日時を設定したもの)を含むフォルダから ZIP を作成し、新しい展開先へ展開すると、展開されたファイル・新たに作成されたディレクトリの更新日時が元の更新日時と一致すること(ZIP 標準の日時フィールドのみを用いる場合は2秒単位の誤差を許容する)。元のファイルに読み取り専用属性を付けていても、展開されたファイルに読み取り専用属性が付かないこと。更新日時の設定に失敗する状況(バックエンドの単体テストで設定処理を失敗させる)でも、展開が成功として完了すること。(R-327-11, R-346-2, R-346-3)
- **[AC-320]** 日本語のファイル名を含む対象から作成した ZIP のエントリ名が UTF-8 で記録され、UTF-8 フラグ(bit 11)が立っていること。(R-327-6)
- **[AC-321]** 隠し属性のファイルを配下に含むフォルダから作成すると、一覧の隠しファイル表示設定に関わらず当該ファイルが ZIP に含まれること。(R-327-7)
- **[AC-321-1]** 配下にシンボリックリンク / ジャンクション(自身の祖先を指す循環リンクを含む)を持つフォルダから作成すると、作成が有限時間で完了し、リンクがアーカイブに含まれず、スキップ件数が完了ステータスに表示されること。(R-327-8, R-396。**ISS-0100 でリンクの扱いが確定した後に検証する**)
- **[AC-321-2]** 出力パスを対象フォルダの内部に指定すると、何も作成されず `destination_inside_source` になること。(R-325)
- **[AC-321-3]** ドライブルート(例: `C:\`)を対象に含めて作成すると `invalid_path` になること。出力パスに既存のディレクトリを指定すると `already_exists` になること。(R-325)
- **[AC-321-4]【第2版】** 対象フォルダ `C:\work\docs` に対し、出力パスを (a) 大文字小文字のみ異なる表記(`C:\WORK\DOCS\x.zip`)、(b) `docs` を指すジャンクション経由の表記(`C:\link\x.zip`)で指定した場合も、いずれも何も作成されず `destination_inside_source` になること。(R-325-1)
- **[AC-321-5]【第3版】** 出力パスに、既存のシンボリックリンク(またはジャンクション、リンク先が存在しないものを含む)を指定して作成を確定すると、上書き確認ダイアログは表示されず、何も作成・変更されずに `invalid_path` が表示され、リンク先のファイルが変更されていないこと。(R-325)

### 14.3 ZIP 展開: ダイアログと展開先

- **[AC-322]** `C:\work\a.zip` の展開ダイアログを開くと、展開先の既定値が `C:\work\a` であること。(R-342)
- **[AC-323]** 展開先を別のパスに変更して展開すると、指定したパスに展開されること。存在しない展開先を指定した場合は作成されてから展開されること。(R-343)
- **[AC-324]** 展開先に既存のファイル(ディレクトリでないもの)を指定すると、展開が行われず `destination_not_dir` になること。(R-343-1)
- **[AC-325]** 既定の展開先 `a\` が既に存在し、その配下に ZIP のエントリと同名のファイルが無い場合、確認ダイアログを表示せずに `a\` の配下へ展開されること。(R-344, R-373)
- **[AC-326]** 展開ダイアログに「上書きの可能性を理解した」確認チェックボックス、パスワード入力欄、試行回数の表示がいずれも存在しないこと。(R-340-1, R-340-2)
- **[AC-327]** 展開先を空にして確定すると、展開が行われずダイアログ内にエラーが表示されること。(R-341)
- **[AC-327-1]【第2版】** 展開先に `sub`(相対パス)を入力して展開すると、現在表示中のディレクトリ直下の `sub` に展開されること。展開先に `newdir\..\..\x` のように `..` を含む存在しないパスを入力した場合は、何も作成されずにエラーになること。(R-341-1, R-343-2)
- **[AC-328]** サブフォルダ・空ディレクトリを含む ZIP を展開すると、アーカイブ内の階層どおりにファイル・ディレクトリが作成されること。(R-346)
- **[AC-328-1]【第2版】** ZIP64 形式の ZIP(例: 70,000 エントリ、または 4 GiB 超のエントリを含むもの。上限 L-1 / L-2 の範囲内)を展開でき、ZIP64 であることを理由に拒否されないこと。(R-346-1)
- **[AC-329]** 非 ASCII のエントリ名(UTF-8 フラグなし、CP932 で記録)を含む ZIP を展開すると、エントリ名が CP932 として解釈された正しい名前で展開されること。UTF-8 フラグなしでもバイト列が UTF-8 として妥当なエントリ名は UTF-8 として解釈されること。(R-347。第3版で期待値を方針に合わせて記載。**方針は ISS-0099 の実験で確認した後に確定し、その時点で本 AC の期待値を最終化する**)

### 14.4 ZIP 展開: 途中失敗

- **[AC-330]** 途中のエントリで書き込みエラーが発生する ZIP(例: 途中のエントリのデータが破損している)を展開すると、そのエントリで展開が中断し、それより前のエントリは展開先に残り、それ以降のエントリは展開されていないこと。(R-350)
- **[AC-331]** AC-330 の状況で、途中まで展開した旨・展開済み件数 / 総件数・展開先・失敗したエントリのパスとエラーがエラーダイアログで通知されること。(R-351, R-351-1)
- **[AC-331-1]【第2版】** 先頭のエントリでエラーになる ZIP を展開した場合(1件も展開する前に中断した場合)は、「途中まで展開した」旨ではなく、エラーのみが通知されること。(R-351)
- **[AC-332]** 途中で中断した場合に、中断したエントリのファイルが書きかけの状態(最終名)で残っていないこと。当該エントリで上書き予定だった既存ファイルは元の内容のまま残っていること。(R-348。**ISS-0101 でエントリ単位の一時ファイル方式が確定した後に検証する**)

### 14.5 展開時の衝突

- **[AC-340]** 展開先に ZIP のエントリと同名のファイルが1件以上ある状態で展開を確定すると、展開が始まる前に確認ダイアログが表示され、「上書き」「スキップ」「キャンセル」の3つの選択肢と「すべてに適用」チェックボックスが提示されること。(R-373, R-374)
- **[AC-341]** 確認ダイアログに衝突しているエントリのアーカイブ内パスと衝突の総件数が表示されること。(R-374-1)
- **[AC-342]** 確認ダイアログを開いた時点で既定フォーカスが「キャンセル」にあり、「すべてに適用」がチェック済みであること。Enter のみを押すと展開が行われず、展開先のいずれのファイルも変更・追加されていないこと。(R-374)
- **[AC-343]** 「すべてに適用」をチェックしたまま「上書き」を選ぶと、衝突するすべてのファイルが ZIP の内容に置き換わり、衝突しないエントリも展開されること。(R-374)
- **[AC-344]** 「すべてに適用」をチェックしたまま「スキップ」を選ぶと、衝突するファイルが変更されず、衝突しないエントリのみが展開されること。(R-374)
- **[AC-345]** 衝突が2件以上ある状態で「すべてに適用」を外して1件目を「上書き」、2件目を「スキップ」と選ぶと、1件目は上書きされ2件目は変更されていないこと。これらの確認がすべて展開の開始前に行われること(進捗表示の開始後に確認ダイアログが表示されないこと)。(R-374, R-374-2)
- **[AC-346]** 確認ダイアログで「キャンセル」を選ぶと、展開先に何も書き込まれないこと(展開先ディレクトリが新規であった場合はそれも作成されないこと)。(R-374)
- **[AC-346-1]【第2版】** 展開先に同名ファイルがあり、かつ不正なエントリ(例: `../evil.txt`)も含む ZIP を展開しようとすると、衝突確認ダイアログが表示されずに事前検証のエラーが表示され、何も書き込まれないこと。(R-345)
- **[AC-347]** UI を経由せず展開処理を直接呼び出し、衝突があるのに解決指示が無い場合、展開先に1件も書き込まれずに `conflict` で拒否されること。(R-375)
- **[AC-348]** 衝突の事前検出後、展開の実行までの間に別プロセスが展開先に同名ファイルを作成した場合、そのファイルが上書きされず `conflict` で展開が中断すること。(R-376)
  - 検証方法(第2版): 衝突の事前検出(R-371)と展開の実行は別の操作であるため、テストでは「事前検出を呼ぶ → 展開先に同名ファイルを作成する → 事前検出の結果(衝突なし)に基づいて展開を呼ぶ」の順に呼び出して再現する(タイミング依存の競合や専用フックを要しない)。
- **[AC-349]** 展開先に既存のディレクトリと同名のディレクトリエントリがあっても、それだけでは確認ダイアログが表示されないこと。(R-372)
- **[AC-349-2]【第2版】** 大文字小文字を区別しないボリュームで、展開先に `A.TXT` が既に存在し、ZIP にエントリ `a.txt` がある場合、衝突として検出され確認ダイアログに載ること(無断で上書きされないこと)。(R-372-2)
- **[AC-349-3]【第2版】** 展開先の書き出し先に、リンク先が存在しないシンボリックリンク `f.txt` があり、ZIP にエントリ `f.txt` がある場合、展開全体が事前に `zip_entry_rejected` で拒否され、リンクを経由した書き込みが行われないこと。(R-372-2, R-367)
- **[AC-349-1]** ファイルエントリの書き出し先に同名の既存ディレクトリがある場合の扱いが所定の仕様どおりであること。(R-372-1。**ISS-0101 確定後に検証する**)

### 14.6 進捗表示とキャンセル

- **[AC-350]** ZIP 作成・展開の実行中に、進捗がモーダルダイアログとして表示され、処理中のエントリ名と「現在 / 総数」の件数が表示されること。(R-380, R-381)
- **[AC-351]** 進捗表示中に ↑ / ↓ 等の一覧操作キーを押しても、背後のファイル一覧のフォーカス・選択が変化しないこと。(R-380)
- **[AC-352]** 進捗表示中にキャンセルボタンを押すか Escape を押すと、処理がキャンセルされること。Escape で一覧の選択が解除されないこと。(R-380)
- **[AC-353]** ZIP 作成をキャンセルすると、出力パスにファイルが作成されず、一時ファイルも残っておらず、キャンセルした旨がステータスに表示されること。(R-383, R-328-2)
- **[AC-354]** ZIP 展開をキャンセルすると、キャンセル時点までに展開されたファイルが残り、以降のエントリが展開されず、途中まで展開した旨・展開済み件数 / 総件数・展開先がステータスに表示されること。(R-384, R-351, R-351-1)
- **[AC-355]** 複数のエントリを含む ZIP の作成・展開中にキャンセルしたとき、遅くとも処理中のエントリの次のエントリ境界でキャンセルが反映され、それ以降のエントリが処理されないこと。(R-382 の必須部分)
  - **[AC-355-1]** (R-382 の推奨〈エントリ内での検査〉を採用した場合に限り検証する。採否は ISS-0091 の残課題)単一の大きなファイル(例: 1 GiB)の処理中にキャンセルしたとき、当該ファイルの処理完了を待たずにキャンセルが反映されること。
- **[AC-356]** キャンセルによる途中終了がエラーコード `canceled` で報告されること。(R-385)
- **[AC-357]** 進捗表示中に ZIP 作成 / 展開、コピー等の別の操作を開始できないこと。(R-386)
- **[AC-358]【第2版】** ZIP 作成・展開の実行中(大きなアーカイブで数秒以上かかる処理)に、進捗表示の件数が処理の完了前に更新され、キャンセルボタン / Escape の操作が処理の完了を待たずに反映されること(画面が固まらないこと)。事前検証・衝突の事前検出の実行中も画面が応答すること。(R-388)
- **[AC-358-1]【第2版】** 呼び出し元が生成した `operation_id` で進捗イベントの購読を開始してから実行を呼び出した場合、最初のエントリの進捗イベントを受け取れること。(R-387-1)
- **[AC-358-2]【第2版】** ある `operation_id` に対するキャンセル要求を、その実行を呼び出す前に送った場合、その実行は `canceled` で終了し、作成では出力パス・一時ファイルのいずれも残らず、展開では1件も書き込まれないこと。(R-387-2。バックエンドのコマンド単位で、キャンセル → 実行の順に呼んで検証する)
- **[AC-358-3]【第2版】** 2つの実行(ZIP 操作とファイル操作、または ZIP 操作どうし)が異なる `operation_id` で存在するとき、一方へのキャンセル要求が他方の処理に影響しないこと。(R-387-3。バックエンドの単体テストで検証する)

### 14.7 対象外事項

  - **[AC-360-1]【第2版】** AES 暗号化エントリ(圧縮方式の番号 99)を含む ZIP のエラーコードが `zip_unsupported` ではなく `zip_encrypted` であること。(R-362 #3)
- **[AC-361]** ソースツリーにパスワード入力 UI・試行回数・ZIP の暗号化 / 復号処理・`ZIP_BAD_PASSWORD` に相当する文字列が存在しないこと。判定方法は、**リポジトリの `app/` ディレクトリ配下(`app/src/`・`app/src-tauri/src/`・`app/src-tauri/Cargo.toml` を含む。`specs/`・`docs/` 等の文書は対象外)**に対する文字列検索(`ZIP_BAD_PASSWORD`、`aes-crypto`、`with_aes_encryption`、`by_index_decrypt`)の結果が0件であることとする(第2版で検索範囲を定義)。(R-390-1)
- **[AC-362]** Deflate / Stored 以外の圧縮方式(例: BZIP2、LZMA)のエントリを含む ZIP を展開しようとすると、展開先に何も書き込まれずに `zip_unsupported` のエラーが表示されること。(R-362 #2, R-392)
- **[AC-362-1]** 拡張子が `.zip` だが中身が ZIP でないファイルを展開しようとすると `zip_corrupt` のエラーが表示されること。(R-309, R-362 #1)

### 14.8 展開の安全性

- **[AC-363]** 次のエントリ名をそれぞれ1件だけ含み、他は正常なエントリから成る ZIP を展開しようとすると、いずれの場合も展開先に何も書き込まれず(展開先ディレクトリも作成されず)`zip_entry_rejected` のエラーが表示されること: `../evil.txt`、`a/../../evil.txt`、`a\..\..\evil.txt`、`/abs.txt`、`\\server\share\x.txt`、`//server/share/x`、`\\?\C:\x`、`\\.\COM1`、`C:/x.txt`、`C:x.txt`(10ケース。第2版で3ケース追加)。(R-360, R-361, R-363 #1〜#3)
- **[AC-364]** 次のエントリ名についても AC-363 と同じく拒否されること: `CON`、`nul.txt`、`nul.tar.gz`、`CON .txt`、`dir/COM1.log`、`LPT9`、`CONIN$`、`CONOUT$`、`COM¹`、`LPT³.txt`、`a.txt:stream`、`name.`、`name `(末尾スペース)、`a?b.txt`(14ケース。第2版で6ケース追加)。(R-363 #4〜#7)
- **[AC-364-1]【第2版】** 名前が空のエントリ、区切りのみ(`/`)のエントリを含む ZIP も、AC-363 と同じく拒否されること。(R-363 #8)
- **[AC-364-2]【第3版】** 次の ZIP をそれぞれ展開しようとすると、何も書き込まれずに `zip_entry_rejected` で拒否されること: (a) 構成要素が 256 UTF-16 コード単位のファイル名を持つエントリ、(b) 展開先と連結した長さが 260 UTF-16 コード単位になるファイルエントリ、(c) 展開先と連結した長さが 248 UTF-16 コード単位になるディレクトリ(ディレクトリエントリ、またはファイルエントリの親として暗黙に作るもの)。構成要素がちょうど 255、ファイルのフルパスがちょうど 259 の場合は拒否されず展開でき、その際に一時ファイル名の長さが原因で失敗しないこと。(R-363 #9 / #10, R-348-1)
- **[AC-364-3]【第3版】** ペアの無いサロゲートを含む名前のエントリ(UTF-8 フラグ付きで不正なバイト列を持つもの等、テスト用に生成した ZIP)を展開しようとすると、何も書き込まれずに `invalid_path` で拒否されること。作成側でも、ペアの無いサロゲートを含む名前のファイル(テストで作成できる場合)を対象に含めると、何も作成されずに `invalid_path` になること。(R-363 #11, R-325)
- **[AC-365]** 不正なエントリがアーカイブの**最後**に位置する場合でも、それより前の正常なエントリが1件も書き込まれていないこと。(R-360)
- **[AC-365-1]【第2版】** 中央ディレクトリには正常な名前(例: `ok.txt`)、ローカルファイルヘッダには不正な名前(例: `../evil.txt`)が記録された ZIP を展開すると、展開先の外に何も書き込まれず、書き込まれる場合は中央ディレクトリの名前(`ok.txt`)でのみ書き込まれること。(R-361-1)
- **[AC-366]** `./a.txt` のように `.` の構成要素を含むエントリは拒否されず、`a.txt` として展開されること。(R-363)
- **[AC-367]** シンボリックリンクとして記録されたエントリを含む ZIP の扱いが所定の仕様どおりであること。(R-362 #6, R-368。**ISS-0101 確定後に検証する**)
- **[AC-368]** 展開先の内部に、展開先の外を指すジャンクション(またはシンボリックリンク)`link` を事前に作成し、エントリ `link/x.txt` を含む ZIP を展開すると、展開先の外に `x.txt` が書き込まれず `zip_entry_rejected` で中断すること。(R-366)
- **[AC-369]** 展開先の内部に、展開先の外のファイルを指すシンボリックリンク `f.txt` があり、エントリ `f.txt` を含む ZIP を展開しようとすると、リンク先のファイルが変更されず、展開全体が事前検出の段階で `zip_entry_rejected` として拒否されること(衝突確認ダイアログに「上書き」の選択肢として載らないこと)。(R-367。第2版で事前検出での拒否を明記)
- **[AC-369-1]【第2版】** `C:\work\a.zip` を展開先 `C:\work` へ展開し、ZIP がエントリ `a.zip`(または大文字小文字のみ異なる `A.ZIP`)を含む場合、展開全体が事前に `zip_entry_rejected` として拒否され、`a.zip` 自体が変更されないこと。(R-367-1)
- **[AC-370]** エントリ数が上限(L-1、ISS-0094 で確定した値)を1件超える ZIP を展開しようとすると、何も書き込まれずに `zip_too_large` のエラーが表示されること。上限ちょうどのエントリ数の ZIP は拒否されないこと。(R-365 L-1)
- **[AC-371]** 宣言された非圧縮サイズの総和が上限(L-2、ISS-0094 で確定した値)を超える ZIP を展開しようとすると、何も書き込まれずに `zip_too_large` のエラーが表示されること。(R-365 L-2)
- **[AC-372]** 宣言された非圧縮サイズの総和が展開先ボリュームの空き容量を超える ZIP を展開しようとすると、何も書き込まれずに `insufficient_space`(ISS-0094 / ISS-0097 で確定したコード)のエラーが表示されること。(R-365 L-3, R-365-1)
  - 検証方法(第2版): 小容量のボリューム(例: 数十 MiB の仮想ディスク〈VHD〉や RAM ディスク)を展開先として用意し、宣言サイズの総和がその空き容量を超える ZIP を用いる。または、空き容量の取得処理を差し替え可能にしたバックエンドの単体テストで検証する。
- **[AC-372-1]【第3版】** 展開先ボリュームの空き容量の取得に失敗する状況(空き容量の取得処理を失敗させたバックエンドの単体テスト)で、L-1 / L-2 以内の ZIP を展開すると、`insufficient_space` で拒否されずに展開が行われ、空き容量を取得できなかったことを示すステータス・ダイアログが表示されないこと。同じ状況で書き込み中に容量不足が起きた場合は、`io_error` として中断し途中まで展開した旨が通知されること(AC-380-1 と同じ検証方法)。(R-365-6)
- **[AC-373]** ヘッダに宣言された非圧縮サイズより実データが大きいエントリを含む ZIP を展開すると、当該エントリで展開が中断し `zip_corrupt` となり、宣言サイズを超えるデータが書き込まれていないこと。(R-349, R-365 L-4, R-365-2)
- **[AC-373-1]【第2版】** エントリのデータは正常に伸張できるが、記録された CRC-32 と一致しない ZIP を展開すると、当該エントリで `zip_corrupt` として中断し、当該エントリのファイルが最終名で残っていないこと(それより前のエントリは残ること)。(R-349-1)
- **[AC-374]** 宣言上の圧縮率が上限(L-5)を超える Deflate エントリを含む ZIP を展開しようとすると、何も書き込まれずに `zip_corrupt` のエラーが表示されること。(R-365 L-5, R-365-4)
- **[AC-374-1]【第2版】** 圧縮サイズ 0・非圧縮サイズ 0 の Deflate エントリ(空ファイル)は拒否されずに空ファイルとして展開されること。圧縮サイズ 0・非圧縮サイズ 1 以上と宣言された Deflate エントリを含む ZIP は、何も書き込まれずに `zip_corrupt` で拒否されること。(R-365-4)
- **[AC-375]** 既知の「重複エントリ型」zip bomb(複数のエントリが同一の圧縮データを参照し、宣言サイズの総和が L-2 を超えるもの)を展開しようとすると、何も書き込まれずに拒否されること。(R-365 L-2)
- **[AC-376]** ZIP 内の ZIP は展開後も ZIP ファイルのまま置かれ、再帰的に展開されないこと。(R-365-3)
- **[AC-377]** 事前検証で拒否された場合、展開ダイアログが閉じずにダイアログ内へエラーが表示され、問題のエントリのアーカイブ内パス(該当する場合)が表示されること。展開先を変更して再度確定できること。(R-395-1。第2版で表示先を入力ダイアログ内へ変更、ISS-0113 で確認)
- **[AC-378]** 大文字小文字のみが異なるファイルエントリ(例: `A.txt` と `a.txt`)を含む ZIP を展開しようとすると、何も書き込まれずに `zip_entry_rejected` で拒否されること。大文字小文字のみが異なるディレクトリエントリどうし(例: `Dir/` と `dir/`)の重複だけでは拒否されないこと。(R-364。第3版で期待値を確定)
- **[AC-378-1]【第2版】** 完全に同一の名前のファイルエントリ(例: `a.txt` が2件)を含む ZIP を展開しようとすると、何も書き込まれずに `zip_entry_rejected` で拒否されること。同一名のディレクトリエントリ(例: `d/` が2件)の重複だけでは拒否されないこと。(R-364-1)
- **[AC-378-2]【第2版】** ファイルエントリ `a` とエントリ `a/b.txt` を両方含む ZIP を展開しようとすると、エントリの順序に関わらず、何も書き込まれずに `zip_entry_rejected` で拒否されること。(R-364-2)

### 14.9 エラーハンドリングと完了後

- **[AC-380]** 書き込み権限のない展開先へ展開しようとすると、`permission_denied` として汎用 I/O エラーとは異なる専用メッセージが表示されること。(R-395-3)
- **[AC-380-1]【第2版】** 事前の空き容量検査(L-3)を通過した後に書き込み先の容量が不足した場合、エラーコードが `io_error` として報告され、途中まで展開した旨が通知されること。(R-395-2, R-351)
  - 検証方法: 展開開始後に別の書き込みで空き容量を埋められる小容量ボリューム(VHD / RAM ディスク)を用いるか、書き込み処理にディスクフルのエラーを注入できるバックエンドの単体テストで検証する。
- **[AC-381]** ZIP 由来のエラー(破損・未対応・暗号化・不正エントリ・上限超過)がいずれも `unknown` ではなく R-395 のコードで分類されること。(R-394, R-395)
- **[AC-382]** 翻訳の無いコードが返った場合に元のメッセージが表示されること(表示が空にならないこと)。ライブラリ由来の詳細メッセージが翻訳文言で置き換えられて失われないこと。(R-394, R-395-4)
- **[AC-383]** ZIP 作成の成功後、出力ファイル名を含む成功メッセージがステータスに表示され、一覧に作成した ZIP が現れること。(R-396, R-397)
- **[AC-384]** ZIP 展開の成功後、展開先と展開件数を含む成功メッセージがステータスに表示され、一覧に展開先フォルダが現れること。「スキップ」したエントリがある場合はその件数も表示されること。(R-396, R-397)
- **[AC-385]** 作成した ZIP / 展開先フォルダが現在のディレクトリの直下にある場合、成功後にそのエントリへフォーカスが移り、選択が解除されていること。出力先 / 展開先を別のディレクトリに変更した場合は、表示中のディレクトリが変わらないこと。(R-398。**ISS-0101 で完了後のフォーカスの扱いが確定した後に検証する**)
- **[AC-386]** 展開が途中で中断・キャンセルされた場合も、現在のディレクトリが再読み込みされ、展開済みの内容が一覧に反映されること。(R-397)
