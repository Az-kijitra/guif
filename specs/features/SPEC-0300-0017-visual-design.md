## 0. 位置づけと表記

- 本仕様は Phase 9 = **画面の見た目**(ISS-0158)を、実装と検証が可能な粒度で規定する。振る舞い(キー操作・選択・移動)は変更しない。
- **承認済み仕様の本文は変更しない。** 抵触する条項は §18 に列挙し、ISS-0175 に起票した。新版の作成・承認は人間が判断する。
- 表記:
  - **【確定 #n】** = 発注者決定(2026-10-01、ISS-0173 の #n)。**【確定 En】** = 発注者の追加決定(2026-10-01、ISS-0178 の En)。いずれも変更不可。
  - **【main】** = `main` の値・挙動を踏襲する(出典は main調査(Phase9)の §n、または ISS-0177 の確認結果)。
  - **【提案 P-nn】** = spec-writer の推奨案。人間の判断待ち(§17、ISS-0174)。推奨案を本文に書き、代案を §17 に記す。
  - **【導出】** = 確定事項・承認済み仕様から spec-writer が導いた帰結。
  - **【要確認】** = `main` の値を確定できていない箇所(ISS-0177)。
- 色の値は本文中で CSS 変数名で書く。値は §4 の表を正本とする。

## 3. 全体レイアウト

- **[R-900]【確定 #1 / main §1】画面は上から「パスバー / オーバーレイ領域(表示中のみ)/ 本体(左にツリーパネル、右にファイル一覧)/ ステータスバー」の順に並べる。** メニューバーとその場所を占める帯は置かない(【確定 #2】、SPEC-0300-0009 R-10-11 / AC-631)。オーバーレイ領域の位置は SPEC-0300-0012 R-104 / SPEC-0300-0013 R-216 と同じ(パスバーの直下)。
- **[R-901]【main §1】`html` / `body`(メインウィンドウ)の `margin` は 0、`overflow` は `hidden` とする。画面全体のコンテナ(`<main>`)は縦方向の flex とし、`height: 100vh`、`padding: 2px`、`gap: 3px`、`overflow: hidden`、`box-sizing: border-box` とする。** ページ(document)自体はスクロールしない。ビューアの `html` / `body` には適用しない(R-913)。
- **[R-902]【main §1】本体は `flex: 1`、`min-height: 0` とし、パスバー・オーバーレイ・ステータスバーを除いた残りの高さをすべて占める。本体の内部は横方向の flex、`gap: 3px` とし、ツリーパネルは幅 220px(枠を含む。SPEC-0300-0009 R-12)、ファイル一覧は `flex: 1`、`min-width: 0` で残りの幅をすべて占める。** ツリー非表示中はファイル一覧が本体の幅をすべて占める。
- **[R-903]【main §1】各領域(パスバー、検索バー、履歴一覧、ツリーパネル、一覧の外枠、ステータスバー)は `1px solid var(--ui-border)` の枠を持つ独立したブロックとし、領域の角丸は付けない(`border-radius: 0`)。** すべての領域は `box-sizing: border-box` とする。
- **[R-904]【main(ISS-0177 (a))/ 提案 P-02】背景色は、ページ(`html` / `body`)と画面全体のコンテナを `--ui-bg`、バー類(パスバー・検索バー・ステータスバー)を `--ui-surface-2`、ツリーパネル・一覧の外枠・履歴一覧を `--ui-surface` とする。** 前段(`--ui-bg`)は `main` で確認済み(`PageShell.svelte:65,74`)。バー類の `--ui-surface-2` は `main` の使用箇所(`:207/215/233`)からの推測、ツリー・一覧の `--ui-surface` は推奨案。
- **[R-905]【導出】画面の各領域は、ウィンドウの内寸の外周から 2px の位置まで広がり(上端はパスバー、下端はステータスバー、左右は各領域)、ウィンドウを満たす。** 領域の間の隙間は縦横とも 3px とする。
- **[R-906]【提案 P-17】ファイル一覧の読込中表示とエラー表示は、一覧の外枠の内側の左上(上 4px・左 4px)に重ねて表示し(`position: absolute`)、一覧本体の大きさ(§9 の W / H)を変えない。** 見た目: `padding: 2px 6px`、背景 `--ui-surface`、`border: 1px solid var(--ui-border)`、基本フォント 12px、最大幅は一覧の外枠の幅 − 8px(超える文字は折り返す)。エラー表示の文字色は `--ui-error`。
  - 表示・消去のタイミングは現行の状態に従う: 読込中表示は一覧の読込中(`loading`)の間、エラー表示はエラー(`error`)が設定されている間(次の読込の成功で消える)。表示中も一覧の行のクリック・キー操作を妨げない(`pointer-events: none`)。【タイミングは導出(現行の状態の定義どおり)】

## 4. 色(CSS 変数)

- **[R-910]【確定 #3】メインウィンドウの色はすべて CSS 変数で指定する。** 変数は全体のスタイルシート(例 `app/src/app.css`)の `:root` に定義し、各コンポーネントは変数を参照する。メインウィンドウのコンポーネントのスタイルに色の値(`#rrggbb`、`rgb()`、`rgba()`、`hsl()`、色名。ただし `transparent` / `inherit` / `currentColor` を除く)を直接書かない。

  2. 名前の全体の表示幅(等幅 12px で実測。`canvas` の `measureText` 等、方式は設計工程)が `avail` 以下なら、そのまま表示する。

  4. それ以外(ディレクトリ、拡張子なし、拡張子が長すぎる)は、末尾を `…` で省略する(CSS の `text-overflow: ellipsis` に委ねてよい)。

  - 実測はフォントの読込後に行い、列幅(§9)・表示項目が変わったときに再計算する。サロゲートペアの途中で切らない。【導出】
  - 3 の結果は CSS の省略で再び切られない(拡張子が必ず見える)。`main` の式 `nameMaxChars = max(8, floor((colWidth − size − time − 8 × (k − 1) − 32 − 12) / 6) + 4)`(ISS-0177 (b))は1文字 6px を仮定しており、実際の文字幅(約 7.2px)より小さいため CSS の省略で拡張子が切れうる(P-04 の代案)。
  - 省略は表示のみであり、`Entry.name`・ソート・検索の対象(SPEC-0300-0012)・`title` は全体の名前とする。

## 9. 多列レイアウトの寸法

- **[R-955]【main §3】一覧本体は `display: grid`、`grid-auto-flow: column`、`grid-template-rows: repeat(rows, var(--list-row-height))`、`grid-auto-columns: var(--list-col-width)`、`column-gap: 16px`、`row-gap: 0`、`padding: 2px 0 4px`、`box-sizing: content-box` とする。** エントリは縦に `rows` 件埋めてから右の列へ進む(SPEC-0300-0009 R-15)。
- **[R-956]【main(ISS-0177 (b)、`main:app/src/lib/utils/list_layout.ts:28-80`)】列の寸法は、W / H(§2)、表示中のエントリ数 n(検索の絞り込み後)から次のとおり求める。**

```
rows     = max(1, floor(H / 28))                        // SPEC-0300-0009 R-16-1
k        = 1 + (showSize ? 1 : 0) + (showTime ? 1 : 0)  // 行の項目数
minCol   = 140 + (showSize ? 72 : 0) + (showTime ? 140 : 0) + 8 × (k − 1) + 32
needed   = max(1, ceil(n / rows))                       // 総列数(n = 0 でも 1)
maxFit   = max(1, floor((W + 16) / (minCol + 16)))      // 幅に収まる列数
cols     = min(maxFit, needed)                          // 表示列数(SPEC-0300-0009 R-16-2)
colWidth = needed > maxFit
             ? minCol
             : min(720, max(minCol, floor((W − 16 × (cols − 1)) / cols)))
一覧本体の幅 = cols × colWidth + 16 × (cols − 1)          // 表示列の内容幅ちょうど
```

  - `minCol` は 172(名前のみ)/ 252(+サイズ)/ 320(+日時)/ 400(両方)px となる。**承認済み SPEC-0300-0009 R-16-3 / AC-11 / AC-12(+72 / +140px)との関係は【提案 P-05】(推奨: `main` の式どおり、R-16-3 に注記)。§18、ISS-0175**。
  - 全件が収まる場合(`needed ≤ maxFit`)は、`needed` 列で W を分け合い、列幅を最大 720px まで広げる(空の列を作らない。SPEC-0300-0009 AC-05)。
  - 収まらない場合(`needed > maxFit`)は、列幅を `minCol` とし、一覧本体の幅を `maxFit` 列ちょうどの幅とする。W との差(余り)は一覧本体の右側の空き(一覧の外枠の背景)となる。
  - **一覧本体の幅を表示列の内容幅ちょうどにすることで、横スクロールの最大値 `scrollWidth − clientWidth` は `(needed − cols) × 列ピッチ` となり、列ピッチの倍数になる**(右端の列まで欠けずにスナップできる。レビュー M-3)。
  - 一覧本体の高さは `rows × 28` px とする(上下の padding を除く)。
  - **`main` との差分**: `main` は `rows = floor(clientHeight / rowHeight)` と、padding を含む clientHeight を用いる(ISS-0177 (b))。本仕様は padding(6px)を除いた H を用い、最後の行が padding と重なって欠けないようにする。【導出】
  - 計算は一覧の外枠の大きさ・エントリ数・表示項目が変わるたびに行う(SPEC-0300-0009 R-17)。
  - **[R-956-2]【第3版・発注者決定 2026-10-01(G8、設計工程からの申し送り)】W が minCol 未満の場合は、上の式によらず、`cols = 1`(表示列数)、`colWidth = W`、一覧本体の幅 = W とする。** 総列数(`needed`)・`rows`・列ピッチ(`W + 16`)・横スクロール(R-958)・端マーカー(R-959)は上の規則のまま(列幅だけを W に置き換える)。

## 16. 受入基準

### 16.0 検証方法【確定 E3】

- **[R-995]【確定 E3】見た目の受入基準は、実アプリ(Tauri + WebView2)を WebView2 のリモートデバッグ(Chrome DevTools Protocol。以下 CDP)で接続して計測する自動テストで検証する。** テストはリポジトリに追加する(~~例 `tests/e2e/`~~ **【第3版承認時・発注者決定 2026-10-02】置き場所は `app/e2e/`**(SPEC-0400-0001 第2版 R-07)の Node スクリプト)。**新しい依存は追加しない**(Node の標準機能〈組込みの `WebSocket` / `fetch`〉で CDP に接続する。組込みの `WebSocket` が既定で使える **Node 22 以上**を前提とする)。
  - 接続: アプリを環境変数 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=<port>` を付けて起動し、`http://127.0.0.1:<port>/json` からメインウィンドウのページを選んで接続する。テスト用のビルド・起動方法の細部は設計工程。【導出】
  - **表示倍率の固定**: 計測前に `Emulation.setDeviceMetricsOverride`(`width` / `height` = AC が指定する内寸、`deviceScaleFactor: 1`、`mobile: false`)を送り、OS の表示スケールに関わらず CSS px の寸法と表示倍率 100% で計測する。AC に内寸の指定が無い場合は 1000 × 700 とする。
  - 計測: `Runtime.evaluate` で `getComputedStyle` / `getBoundingClientRect` / `scrollLeft` 等を取得する。位置・寸法の許容誤差は ±0.5px。色は計算済みの `rgb()` / `rgba()` 表記で比較する。
  - **CSS 変数**は `getComputedStyle(document.documentElement).getPropertyValue('--name')` の文字列を、前後の空白を除き英字を小文字にして比較する(例 `#fff`)。
  - **outline** は `outline-width` / `outline-style` / `outline-color` / `outline-offset` を個別に比較する(短縮形の文字列では比較しない)。
  - テスト用の状態(エントリ数、遅延、ドライブ列挙等)は、テスト用のディレクトリを作る、または既存のテスト用差し替えの仕組みで用意する(方式は設計工程)。
  - これにより ISS-0008(E2E の要否)のうち「見た目の検証は CDP による自動計測で行う」部分が決着する。CI での自動実行の要否は ISS-0008 に残る。
- 各 AC の末尾に検証区分を記す: **[CDP]** = CDP 自動計測、**[単体]** = vitest の単体テスト(純粋関数の計算)、**[静的]** = ソースツリーの検索、**[目視]** = 実機での目視確認(自動化しない)。複数の区分を併記したものは両方で検証する。
