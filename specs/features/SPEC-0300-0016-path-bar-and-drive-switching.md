## 1. 適用範囲

対象:
- パスバーの表示、編集状態への出入り、入力の正規化、確定(移動)、失敗時の扱い、フォルダ名の補完、編集中のキー処理
- `focus_path` アクション(SPEC-0300-0010 §4.2 #15、既定 `Ctrl+L`)の振る舞い
- ツリー最上位のドライブ一覧と、ドライブの列挙
- ディレクトリ移動の要求が重なった場合の競合規則(経路を問わない。R-726)
- パスバー / ドライブ一覧による移動と、訪問履歴・ツリー追従・フォーカス・検索バーとの関係

対象外:
- ディレクトリ移動の処理そのもの(列挙・表示更新・選択 / フォーカスのリセット・ファイル監視の再スケジュール)。正本は SPEC-0300-0009 R-70 / R-72 / R-76-1(SPEC-0300-0013 R-236 と同じ責務境界)。ただし R-726 の競合規則は本仕様で定め、SPEC-0300-0009 の新版へ移す(§12.1)
- 訪問履歴 / ジャンプリストの一覧の内部の振る舞い(正本は SPEC-0300-0013)
- 見た目(フォント・余白・色・パスバーの高さ等)。Phase 9(ISS-0158)
- パンくず表示、ドライブのボリュームラベル・容量・種別アイコンの表示、デバイスの着脱の自動検出、`refresh`(F5)

## 2. 用語

| 用語 | 意味 |
|---|---|
| パスバー | 画面上部(SPEC-0300-0009 R-10 / AC-631)の現在パスを表示・編集する入力欄 |
| 編集中 | パスバーの入力欄にキーボードフォーカスがある状態 |
| 現在パス | ファイル一覧が表示しているディレクトリのパス(最後に反映された移動の移動先) |
| 確定 | 編集中に Enter を押して、入力したパスへの移動を要求すること |
| 移動の要求 | 経路(パスバーの確定、一覧の `open` / `go_parent`、ツリーのノード選択、ドライブノードの選択、訪問履歴 / ジャンプリストの確定)を問わず、ディレクトリ移動を開始すること |
| ドライブノード | ツリー最上位に並ぶ、ドライブのルート(例 `C:\`)を表すノード |
| 現在のドライブ | 現在パスのドライブ。SPEC-0300-0009 R-40 / R-40-0 の「ルート」と同じ規則で決まる(`\\?\C:\X` なら `C:\`、`\\?\UNC\server\share\X` と `\\server\share\X` なら `\\server\share\`) |
| ルート | R-721-1 で定める、それより上へ移れないパスの先頭部分 |

## 3. パスバーの構成と表示

- **[R-700] パスバーは単一のテキスト入力欄で構成する。パンくず・ボタン・ドロップダウンの開閉ボタンは設けない。**【main: `main:app/src/lib/components/PathBar.svelte`(76行、単一 input、パンくずなし)】
- **[R-701]【確定 D3】編集中でない間、入力欄は常に現在パスを表示する。** 移動が反映されるたびに表示を更新する。
  - **[R-701-1]【確定 D3】** 表示する文字列は現在パスの文字列そのもの(`\\?\` 接頭辞を含む場合もそのまま、大文字小文字も移動時の文字列のまま)とする。ツリーのノード名で接頭辞を隠す規定(SPEC-0300-0009 R-40-0)はパスバーには適用しない。(理由: パスバーは実際に開いているパスを示す場所であり、複写して他で使えることを優先する)
- **[R-702]【確定 #2】パスバーは Tab / Shift+Tab によるタブストップの巡回に含めない。** タブストップの順序(SPEC-0300-0009 R-14-11-2: ツリー → 〈検索バー表示中のみ〉検索入力欄 → ファイル一覧)は変更しない。パスバーに入る手段は `focus_path`(R-710)とマウスのクリック(R-703)とする。
- **[R-703]【確定 D3】パスバーをクリックすると編集中になる。** 入力は現在パス(R-701 により既に表示中)のままとし、キャレットはクリック位置に置く(入力欄の既定動作)。クリックで入った場合、R-710-5(検索バーを閉じる)は適用しない。【後段は導出。D2 は `Ctrl+L` についての決定であり、クリックは検索バーを閉じる経路(SPEC-0300-0012 R-106)に加えない】
- **[R-704]【確定 D3】編集中に、アプリ内の他の要素へフォーカスが移った場合(一覧・ツリー・検索入力欄のクリック等)は、編集内容を破棄して現在パスの表示へ戻す。** 移動は行わない。ウィンドウの切替(他のアプリへ移る)ではフォーカスを失ったものとして扱わず、編集内容を保つ。
  - **[R-704-1]【導出。レビュー m-3】編集中に、フォーカスを受けない領域(ステータスバー、パスバーの行の余白、一覧・ツリーの外の余白等)をクリックした場合も、編集内容を破棄し、フォーカスをファイル一覧へ移す(SPEC-0300-0013 R-225-1 と同じ優先順)。フォーカスを `document.body` に落とさない。**(SPEC-0300-0012 R-107 / SPEC-0300-0013 R-225 と同じ方針)
- **[R-705]** 編集中であることが分かる表示(フォーカスの表示)を行う。見た目の詳細は Phase 9(ISS-0158)で定める。【導出】

## 5. 入力の正規化と確定

- **[R-720]【main】編集中に Enter を押すと確定する。** 入力文字列を R-721 で正規化し、R-722 の形式検査に通ったものについて、SPEC-0300-0009 の移動処理(R-70 / R-72 / R-76-1)で当該パスへの移動を要求する。
- **[R-721]【確定 D3。順序はレビュー m-1】確定時の正規化は次の順に行う。**【`main` は前処理を持たない(`main:app/src/lib/page_dir.ts:49-77`)】
  1. 前後の空白文字(空白・タブ・改行)を除く。
  2. 全体が二重引用符で囲まれている場合は、両端の引用符を除く(エクスプローラーの「パスのコピー」の結果を貼り付けた場合に対応する)。
  3. `/` を `\` に置き換える。
  4. ドライブ文字とコロンのみ(例 `d:`)の場合は、そのドライブのルート(`d:\`)とする。
  5. 区切り文字の連続を1つにまとめる(UNC の先頭 `\\` を除く)。
  6. `.` / `..` の構成要素を字句的に解決する(シンボリックリンク・ジャンクションは辿らない)。ルート(R-721-1)より上へは出ない(`C:\..` は `C:\`、`\\server\share\..` は `\\server\share\`)。
  7. **【承認時に確定・ISS-0171 (a)】各構成要素の末尾のドット・空白を除く**(例 `C:\A.`、`C:\A ` は `C:\A`)。Win32 と同じ扱いである。除いた結果が空になる構成要素があれば `invalid_path`(R-731)とする。理由: Win32 はこれらを除いて開くため、除かずに移動すると現在パスの文字列(`C:\A.`)と実体(`C:\A`)が食い違い、ツリーの強調・訪問履歴の重複判定が一致しなくなる。(`..` の解決〈6〉の後に行うため、`.` / `..` の構成要素はこの時点で残っていない)
  8. ルート以外の末尾の区切り文字を除く(`C:\A\` は `C:\A`)。ルートは末尾の区切りを保つ(`C:\`、`\\server\share\`、`\\?\C:\`、`\\?\UNC\server\share\`、`\\?\Volume{GUID}\`)。
  - 大文字小文字は入力のまま保つ(ドライブ文字も変えない。**第1版の「ドライブ文字の大文字化」は D3〈m-8〉により削除**)。現在パス・パスバーの表示・訪問履歴の記録値(SPEC-0300-0013 R-207-2)はこの文字列とする。比較は大文字小文字を区別しない(SPEC-0300-0009 R-40-6、SPEC-0300-0013 R-207)。
  - 例外: `\\?\` / `\\.\` で始まるパスには 3・5・6・7 を適用しない(これらの名前空間では OS が字句処理を行わないため、書かれたとおりに扱う)。8 は適用する(ルートの末尾の区切りは保つ)。【導出】
- **[R-721-1]【導出。レビュー m-1】ルートは次のとおりとする。** ドライブ `X:\` / UNC `\\server\share\` / `\\?\X:\` / `\\?\UNC\server\share\` / `\\?\Volume{GUID}\` / `\\.\X:\` / `\\.\Volume{GUID}\`。UNC の共有のルート `\\server\share\` からは `..` 等で上がれない(`\\server\` は列挙できるディレクトリではない)。
- **[R-722]【確定 D3】受け付けるパスの形式は、ドライブの絶対パス(`X:\…`)、UNC パス(`\\server\share\…`)、`\\?\` で始まるパス、および `\\.\X:\…` / `\\.\Volume{GUID}\…` の形の `\\.\` パスとする。** 次は受け付けず、移動処理(バックエンド)を呼ばずに R-730 の失敗(`invalid_path`、R-731)として扱う。
  - 相対パス(`foo`、`.\foo`、`..`)、ドライブ相対パス(`C:foo`)、ルート相対パス(`\foo`)、`~` で始まるパス、`file:` 等の URL、共有名の無い UNC(`\\server`、`\\server\`)、上記以外の `\\.\` パス(`\\.\PhysicalDrive0`、`\\.\pipe\…` 等。レビュー m-6)。
  - 環境変数(`%USERPROFILE%` 等)は展開しない。絶対パス中に含まれる場合は文字どおりのフォルダ名として扱う(存在しなければ R-730)。
- **[R-722-1]【確定 D3】** 正規化後の文字列が空の場合、Enter では何もしない(編集中のまま、入力も変えず、通知もしない)。
- **[R-722-2]【確定 D3。レビュー m-9】相対パスを拒否する点は、ZIP 作成の出力パス(SPEC-0300-0014 R-322-1: 相対パスを現在表示中のディレクトリ基準で解釈する)と異なる。** 差異は意図したものとする。理由: ZIP の出力パスは現在のディレクトリ内に作ることが主な用途であるのに対し、パスバーは移動先の指定であり、相対パスの誤解釈(意図しない場所への移動)を避けるため。

## 10. ドライブの列挙

- **[R-780]【確定 D1】列挙は、OS が論理ドライブとして認識しているドライブ文字の集合(Windows の `GetLogicalDrives` が返すもの)とする。** 固定・リムーバブル・ネットワーク割当・光学・RAM ディスク・`subst` を含み、メディア未挿入・準備未完了のドライブ、**切断中のネットワークドライブも表示される**(選択したときに R-773-1 の失敗となる)。
  - 注記【承認後の再確認 Minor】: 「切断中のネットワークドライブも `GetLogicalDrives` の結果に含まれる」ことは AC-754 の実機確認で裏付ける。裏付けが取れない場合(含まれない構成がある場合)は、本条項の記述を見直す(表示されないことを許容するか、他の手段を加えるかを人間が判断する)。
- **[R-781]【確定 D1】列挙のタイミングは、(1) ツリーを作るとき(起動時にツリーが表示状態の場合、`toggle_tree` で表示へ切り替えたとき)、(2) 別のドライブへ移動したとき、とする。**(`GetLogicalDrives` は低コストのため、移動のたびに再列挙しても負担にならない)列挙の後に接続・取り外されたドライブは次の列挙まで反映しない(その間もパスバーから移動できる)。デバイスの着脱の自動検出は行わない。
- **[R-782]【確定 D3】** 列挙は非同期(IPC 経由)に行い、ファイル一覧の読込・表示とツリーの経路展開を待たせない。列挙が終わるまでは、現在のドライブのノード(R-778)のみを表示してよい。
- **[R-783]【確定 D1】列挙は、存在するドライブ文字を即座に返し、各ドライブの内容(ルートの列挙)・ボリューム情報(ラベル・容量・種別)に触れない。** 列挙によって、ディスクの起動(スピンアップ)、SMB の接続、OS の「ディスクがありません」等のダイアログが生じてはならない。
- **[R-784] 列挙はバックエンドの新しいコマンド1つで行う(コマンド名は設計工程)。** ドライブの列挙はディレクトリの列挙ではないため `fs_list_dir`(SPEC-0300-0009 R-70)は変更しない。SPEC-0300-0009 R-41 後段「ツリー専用のバックエンドコマンドは設けない」は子ノードの取得についての規定である旨を、同仕様の新版で明記する(§12.1)。capability / ACL 整合テスト(`app/src-tauri/src/acl_consistency.rs`)への登録は設計工程。【導出】
- **[R-785]【確定 D1】実現方式は `windows-sys` の `GetLogicalDrives`(方式 B)とする。** `GetLogicalDrives` の呼び出しに要する `unsafe` は、`archive/win_fs.rs` と同じ方式の隔離モジュール(`#[allow(unsafe_code)]` を当該モジュールに限り、呼び出しごとに `// SAFETY:` を付ける)に限定する。`lib.rs` の `#![deny(unsafe_code)]` は維持する。
  - `unsafe` の例外範囲の拡大(現行は `archive/win_fs.rs` の2関数に限る設計判断: SPEC-0200-0001 §3.4.13-7 / §3.4.14 C2、境界テスト `archive/boundary_tests.rs`)、隔離モジュールの配置(`archive/win_fs.rs` への同居か、別モジュールか)、`windows-sys` の feature の追加要否は、設計工程で architecture-guardian が扱う(ISS-0161)。
  - **不採用(D1)**: 方式 A(安全なコードで `A:\`〜`Z:\` のメタデータ取得を試みる。切断中ネットワークドライブでの待ち、光学ドライブのスピンアップ・ダイアログのおそれがあるため)、方式 C(その他の代替方式)。記録は ISS-0161 / ISS-0169。
