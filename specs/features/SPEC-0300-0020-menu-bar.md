## 0. 経緯・出典

### 0.1 発注者方針・決定(2026-10-09、変更不可)

- **方針**: スモークテストで品質は問題なし。機能性・操作性の改善は多いが、まず基本機能を完成させ品質を確認してから。基本機能として必須とするもの: (1) メニュー、(2) ビューアのキー操作、(3) ビューアのテキスト表示の見た目(本仕様は (1) を扱う。(2)(3) は SPEC-0300-0015 第8版 / SPEC-0300-0017 第8版)。
- **【確定 #1】メニューは「実在する機能だけ + キー操作対応」とする。** メイン画面にメニューバー(ファイル / 編集 / 表示 / 移動 / ヘルプ。ヘルプは中身があるかで要否を【提案】)を置く。
- **【確定 #2】項目はこのアプリに実在する機能だけとする。** 旧製品の `main` にあって本プロダクトに無いもの(元に戻す、やり直し、複製、日付プレフィックス、プロパティ、外部ツール起動、URL のジャンプ追加、テーマ切替、設定画面、キー一覧、マニュアル、バージョン情報)は出さない(SPEC-0100-0005 R-08 のプレースホルダ禁止と整合)。
- **【確定 #3】本プロダクトにあって `main` のメニューに無い機能(名前の変更、新規作成、サイズ・日時列の切替、ZIP に圧縮 / 展開、パス欄へ移動 Ctrl+L、パスのコピー、OS の関連付けで開く 等)も項目に加える。**
- **【確定 #4】項目にショートカットを併記する。値は現在のキー割り当て(利用者の上書き〈`input_keymap_custom`〉を含む)から取る。**
- **【確定 #5】キー操作**: Alt / F10 でメニューバーにフォーカス、←→ でメニュー間、↓ / Enter で開く、↑↓ で項目、Enter で実行、Esc で閉じて元のフォーカスへ。アクセスキー(下線文字)の要否は【提案】。
- **【確定 #6】無効化の条件と理由は、右クリックメニュー(SPEC-0300-0018)の有効条件・理由と揃える。**
- **【確定 #7】見た目は `main` の寸法・変数(バー padding 3px 6px、見出しのボタン 12px、ドロップダウンの min-width 260px、項目の padding 6px 12px・13px、ショートカットの色 `--ui-muted`)を SPEC-0300-0017 と整合させる。**
- **【確定 #8】文言は SPEC-0300-0019 の用語表に従い、同仕様に W 行を追加する。**
- **【確定 #9】ビューアウィンドウにはメニューバーを設けない(SPEC-0300-0015 R-510 を維持)。**
- **【確定 #10】改訂が必要な既存条項**: SPEC-0300-0009 R-10-11 / AC-01 / AC-631(メニューバーを置かない → 解除)、SPEC-0300-0017 R-900 と対象外の欄、SPEC-0300-0010 の R-12 の優先4「メニューバー」、SPEC-0300-0013 R-222 #3 / AC-214-2、SPEC-0300-0012 R-102 #2 / SPEC-0300-0014 R-306 の注記、SPEC-0300-0019(W 行と用語)。新規の横断仕様を起こすか既存に置くかは慣例で判断する(→ 本仕様を新規に起こした。理由は §0.4)。

### 0.2 旧製品の `main` の事実(オーケストレーター経由の調査結果)

- メニューバーは画面の最上部(パスバーの上)にある(`PageShell.svelte:28`)。メニューは `menus/{file,edit,view,navigate,help}.ts` の5つで、グループの順は `ui_constants.ts:916`、訳は `ui_constants.ts:534-573`。
- 項目は `ActionItem.svelte:33-73` で描かれ、ショートカットは `page_keymap.ts:101-106` で現在のキー割り当てから併記する。
- **全項目が `enabled: true` 固定**(無効化の仕組みが働いていない)。**キー操作は Esc で閉じるだけ**(`keyboard_menu.ts:7-12`)。区切り線の判定に不整合がある。→ いずれも踏襲しない(§4、§7、R-1312)。
- 寸法・変数: バー `padding: 3px 6px`、見出しのボタン 12px、ドロップダウン `min-width: 260px`、項目 `padding: 6px 12px`・13px、ショートカットの色 `--ui-muted`(【確定 #7】)。
- 検索は「編集」メニュー(`main:app/src/lib/menus/edit.ts:118-119`。SPEC-0300-0012 R-102 の根拠)、履歴 / ジャンプリストは「移動」メニュー(`main:app/src/lib/menus/navigate.ts:51-62`。SPEC-0300-0013 R-222 の根拠)にある。

### 0.3 本リポジトリの現状(起票時の確認。規範ではない)

- メニューバーは無い(SPEC-0300-0009 R-10-11)。キー入力のディスパッチの優先順位表(SPEC-0300-0010 R-12)には優先4「メニューバー」の行があるが、実体は無い(SPEC-0300-0014 §0.4 の記録では `isMenuBarActive: false` 固定)。
- 実装済みのアクション(SPEC-0300-0010 §4.2 のうち区分「後続」以外): 移動・選択、`open`、`go_parent`、`exit`、`focus_path`、`toggle_hidden`、`toggle_tree`、`copy` / `cut` / `paste` / `delete` / `rename` / `new_file` / `new_folder`、`search`、`sort_menu`、`history_jump_list` / `jump_add` / `history`、`toggle_size` / `toggle_time`、`zip_create` / `zip_extract`。固定キーの `Shift+Enter`(OS の関連付けで開く)。右クリックメニューだけの機能「パスのコピー」(SPEC-0300-0018 R-1060)。
- 未実装(区分「後続」): `settings`(Ctrl+,)、`help_keymap`(F1)、`refresh`(F5)。→ メニューに出さない(【確定 #2】、R-1311)。

### 0.4 本仕様を新規に起こした理由(【導出】)

メニューバーは項目・有効条件・キー操作・マウス操作・見た目・文言を持つ独立した UI 部品であり、右クリックメニュー(SPEC-0300-0018)を新規の詳細仕様として起こした前例と同じ規模になる。既存仕様(SPEC-0300-0009 の画面構成、SPEC-0300-0017 の見た目)に分けて置くと、項目の表と有効条件の正本が分散するため、新規の Spec ID とした。キーの優先順位(SPEC-0300-0010)、画面の構成(SPEC-0300-0009 / 0017)、文言(SPEC-0300-0019)は各仕様の新版で本仕様を参照する。

## 1. 適用範囲・用語

対象: メインウィンドウのメニューバー、その見出し(メニュー名)とドロップダウン(項目の一覧)、項目の有効 / 無効、ショートカットの併記、項目の実行、キー操作・マウス操作、見た目、アクセシビリティ、ステータスバーとの関係。

対象外: ビューアウィンドウ(メニューバーを設けない。【確定 #9】、SPEC-0300-0015 R-510)、右クリックメニュー(SPEC-0300-0018。本仕様は変えない)、各項目が呼ぶ処理そのもの(各機能仕様が正本)、設定画面・キー一覧・マニュアル・バージョン情報(存在しない。【確定 #2】)、メニューのカスタマイズ。

| 用語 | 意味 |
|---|---|
| メニューバー | 画面の最上部の横長の帯。見出しを横に並べる |
| 見出し | メニューバー上のメニュー名(`ファイル` 等)。押すとドロップダウンを開く |
| ドロップダウン | 見出しの下に開く項目の一覧 |
| メニューバーがアクティブ | キーボードフォーカスがメニューバー(見出し)にある状態、またはドロップダウンが開いている状態 |
| 強調 | キーまたはマウスで現在指している見出し・項目の状態 |
| 元のフォーカス | メニューバーをアクティブにする直前にキーボードフォーカスがあった要素(ファイル一覧・ツリーパネル・検索入力欄) |

## 2. 構成と位置

- **[R-1300]【確定 #1 / main】メインウィンドウの最上部(パスバーの上)にメニューバーを常に表示する。** 画面の構成は上から「メニューバー / パスバー / オーバーレイ領域(表示中のみ)/ 本体 / ステータスバー」となる(SPEC-0300-0017 第8版 R-900、SPEC-0300-0009 第17版 R-10-11)。メニューバーの表示・非表示を切り替える操作は設けない。【導出】
- **[R-1301]【確定 #1 / 確定 T-01】メニューは左から `ファイル` / `編集` / `表示` / `移動` の4つとする。ヘルプは設けない(【確定 T-01】: 中に置ける実在の機能が無い)。**
- **[R-1302]【確定 #9】ビューアウィンドウにはメニューバーを設けない。**

## 7. キー操作

### 7.1 アクティブにする・やめる

- **[R-1350]【確定 #5 / 導出】次のキーでメニューバーをアクティブにする。** アクティブにした直後は先頭の見出し(`ファイル`)を強調し、ドロップダウンは開かない。
  1. **F10**(修飾キーなし)の keydown。
  2. **Alt 単独**: Alt の keydown から keyup までの間に他のキーの keydown が無かった場合の、Alt の keyup。左右の Alt を区別しない。Alt を押したまま他のキー(`Ctrl+Alt+Z`、`Alt+F4`、`Alt+Tab` 等)を使った場合や、Alt を押したままマウスを押した場合は、アクティブにしない。IME の変換中(`isComposing` が真、または `keyCode` 229)は対象外。
  3. **【確定 T-04】アクセスキー**: `Alt` + 見出しのアクセスキー(`F` / `E` / `V` / `G`)で、そのメニューのドロップダウンを直接開く(先頭の有効な項目を強調)。

    - 元のフォーカス(R-1352)は、検索バーのボタンにあった場合はそのボタン、どの要素にも無かった場合はファイル一覧とする(戻すときにフォーカスを `document.body` に落とさない)。【導出】

    3. WebView 側の `preventDefault` で抑止できない場合の代替(例: Rust 側でメインウィンドウのウィンドウ プロシージャをサブクラス化し `WM_SYSCOMMAND` の `SC_KEYMENU`〈`lParam` が 0 のキーボード由来のもの〉を握りつぶしてフロントエンドへ通知する、Tauri / tao の既存の設定・イベントで代替する 等)を設計工程が提案する。**代替が `unsafe` の追加(SPEC-0300-0015 R-523 の方針)・新しい外部依存・Alt+Space(システムメニュー)など OS の標準操作への影響を伴う場合は、人間(発注者)の判断事項とし、判断が得られるまで Alt 単独の割り当てを実装しない(F10 とアクセスキーだけで先に進めてよい)。**
    4. Alt+F4・Alt+Tab・Alt+Space(OS のシステムメニュー)の OS の標準の動作は妨げない(R-1355)。

- **[R-1351]【確定 #5】メニューバーがアクティブなとき、Esc を押すとメニューバーを非アクティブにし(ドロップダウンが開いていれば閉じ)、元のフォーカスへ戻す。** Esc は1回で元のフォーカスへ戻る(Windows の標準の「ドロップダウンを閉じて見出しに戻る」の2段階にはしない)。Alt 単独(R-1350 の 2 の条件)・F10 を押した場合も同じく非アクティブにして元のフォーカスへ戻す。
- **[R-1352]【確定 #5 / 導出】非アクティブにしたとき(Esc、項目の実行、メニュー外のクリック、ウィンドウが非アクティブになった、ウィンドウのサイズ変更 等)は、元のフォーカスへキーボードフォーカスを戻す。** 元のフォーカスの要素が無くなっていた場合(検索バーが閉じられた等)はファイル一覧へ戻す。フォーカスを `document.body` に落とさない(SPEC-0300-0018 R-1086 と同じ)。マウスでアクティブにした場合も、その直前のフォーカスを元のフォーカスとする。
  - **[R-1352-1]【レビュー S-4・導出(SPEC-0300-0016 R-704 の当てはめ)】パスバーの編集中に見出しをクリックした場合は、SPEC-0300-0016 R-704(編集中にアプリ内の他の要素へフォーカスが移ったら、編集内容を破棄して現在パスの表示へ戻す)のとおり編集を終え、ドロップダウンを開く。** この場合の元のフォーカスはファイル一覧とする(編集中のパスバーには戻さない。編集内容は戻らない)。キー(Alt / F10)ではパスバーの編集中にメニューバーをアクティブにしない(R-1350-1)。

### 7.2 アクティブな間のキー

- **[R-1353]【確定 #5】見出しを強調していてドロップダウンが閉じているとき**: ← / → で前 / 次の見出しへ強調を移す(端では回り込む)。↓ / Enter / Space で強調中のメニューのドロップダウンを開き、先頭の有効な項目を強調する。【Space は導出】Enter / Space は修飾キーなしの場合に限る(【再レビュー m-a】Alt+Space は OS のシステムメニューであり R-1355 のとおり止めない。Ctrl / Shift 等を伴う Enter / Space は R-1355 の「上記以外のキー」として何もしない)。
- **[R-1354]【確定 #5 / 導出】ドロップダウンが開いているとき**:
  1. ↑ / ↓ で前 / 次の有効な項目へ強調を移す(無効の項目・区切り線は飛ばし、端では回り込む)。強調が無い状態(マウスで開いた直後)では、↓ は先頭、↑ は末尾の有効な項目を強調する(SPEC-0300-0018 R-1081 と同じ)。
  2. Home / End で先頭 / 末尾の有効な項目を強調する。【導出】
  3. ← / → で前 / 次のメニューのドロップダウンに切り替え(端では回り込む)、その先頭の有効な項目を強調する。
  4. Enter で強調中の項目を実行する(R-1340)。強調が無ければ先頭の有効な項目を実行する。有効な項目が無ければ何もしない(SPEC-0300-0018 R-1082 と同じ)。
  5. 【確定 T-04】`Alt` + 他の見出しのアクセスキーで、そのメニューへ切り替える。
- **[R-1355]【導出。SPEC-0300-0018 R-1084 と同じ】メニューバーがアクティブな間、上記以外のキー(Tab / Shift+Tab、文字キー、Delete、Ctrl+C 等)は、メニューバーを非アクティブにせずに何もしない(処理済みとし、既定動作も抑止する)。** ファイル一覧・ツリー・検索のアクションは発火しない。キーマップ経由の `exit`(SPEC-0300-0010 R-12 優先2)も評価しない(同 R-14-3 と同じ考え方。第16版 R-14-5)。優先1 の `Ctrl+Q` / `Ctrl+,` は有効。OS が処理するキー(Alt+F4、Alt+Tab、Alt+Space〈システムメニュー。【再レビュー m-a】〉、Windows キーとの組合せ 等)は止めない。
- **[R-1356]【導出】メニューバーのキー処理は SPEC-0300-0010 R-12 の優先4「メニューバー」で行う。** アクティブにするキー(R-1350)の判定位置と分類は SPEC-0300-0010 第16版 R-14-5 / §3.1 #13 / #14 を正本とする。

## 14. 受入基準

- 検証区分: [CDP] = 実アプリ(`tauri dev` または release ビルド)を WebView2 の CDP で操作・計測する E2E(`app/e2e/`)。キー入力は `Input.dispatchKeyEvent` で送る。[単体] = vitest の単体テスト。[静的] = ソースの走査。[目視] = 実機での目視確認(チェックリストに項目 ID で列挙)。**[E2E・OS 入力]【レビュー S-6】= OS のキー入力の経路(物理キーボードと同じく OS のメッセージ キューを通る入力)でアプリにキーを送る E2E。新しい依存を追加せず、PowerShell から Win32 の `SendInput` を P/Invoke で呼ぶ(`Add-Type`)等の方法で送り、送る前にアプリのウィンドウが前面にあること(`GetForegroundWindow` のウィンドウがテスト用に起動したアプリ本体のプロセスのものであること)を確かめ、前面でなければ1つも送らない。テスト側から前面にする操作をしてよいのは AC が明示的に許す場合だけで、アプリが自分で前面を得ることを判定する AC(AC-1348)では前面でなければその時点で失敗とする。送ってよいキーは許可リストに限る。手順と安全の規則の正本は SPEC-0400-0001 第5版 R-12(DRAFT)。** CDP の `Input.dispatchKeyEvent` はページへ直接届き OS のメニュー モード・ウィンドウのフォーカスを経由しないため、OS の経路に関わる AC(AC-1348)は [E2E・OS 入力] で判定する。SPEC-0400-0001 / SPEC-0300-0017 §16.0 に従う。
