| 1 | ISS-0047 | **完全削除の起動手段は、既存の `delete` アクションのハンドラ内で Shift 修飾の有無を判定する固定分岐として実現する。** 新規アクションIDは追加しない。キーマップ(`config.toml`)のカスタマイズ対象は `delete` アクションのキー割当のみとし、「Shift 修飾を伴う場合は完全削除」という意味づけはハンドラの固定仕様とする。機構としては、**キーマップ照合が成立した後にハンドラ内で追加の修飾キーを検査して分岐する**方式(SPEC-0300-0010 §3.1 の分類 (b))を採る | R-56-4(確定条項化), R-56-4-1〜R-56-4-3, AC-46-5(差し替え), AC-46-6, AC-46-7, AC-76-1, §12-j。機構側の正本は SPEC-0300-0010 R-18 / R-18-1 / §3.1 #4 |

## 13. 受入基準

Phase 2(ファイル操作)の完了判定に用いる。すべて「〜できること」形式でテスト可能な粒度とする。

**受入基準の役割分担(ISS-0025 の再発防止)**: 「当該キー(Ctrl+C / Ctrl+X / Ctrl+V / Delete / **Shift+Delete** / F2 / Ctrl+N / **Ctrl+Shift+N**)を押すと当該アクションが発火する」ことの検証は **SPEC-0300-0010 §9.7(AC-41〜AC-44、`new_folder` に対応する AC-49、`delete` の Shift 修飾分岐に対応する AC-50 / AC-51、および `delete` のカスタム割当に対する Shift 禁止に対応する AC-53)を正本**とする。本仕様の受入基準は**発火後の結果**のみを検証し、キー発火の検証を二重に持たない。フォーカス/選択状態そのものの検証は SPEC-0300-0009 を正本とする。

### 13.8-2 データ安全(第4版で新設、MUST-59)

- **[AC-78]** 大文字小文字のみが異なる表記で同一のディレクトリを貼り付け先としてコピー / 移動した場合、当該項目が R-25 の除外として扱われ、コピー元 / 移動元のファイルが失われていないこと(上書きのための削除が行われないこと)。(R-37, R-37-1, R-25)
- **[AC-79]** ジャンクション(またはシンボリックリンク)経由の別表記で同一の実体を指す項目へのコピー / 移動で「上書き」を選択しても、コピー元 / 移動元が失われていないこと。(R-37, R-37-1)
- **[AC-80]** 8.3 形式の短縮名、またはドライブ文字と UNC パスなどの別表記で指定した同一の項目が、同一の実体として判定されること(衝突として上書きされず、または事前検証の `same_path` / `destination_inside_source` として検出されること)。(R-37-1, R-24)
- **[AC-81]** コピー元 / 移動元が、上書き対象の宛先既存項目の配下にある場合(例: `X\foo\foo` を `X` へ貼り付け、宛先 `X\foo` が衝突する場合)、上書きが行われず `overwrite_ancestor` として失敗(UI を持たない経路では拒否)し、コピー元と宛先の既存項目のいずれも変更されていないこと。UI 経路では確認ダイアログに「上書き」の選択肢が提示されないこと(R-37-4 部分は【導出】・実装後レビューで確認)。(R-37-2, R-37-4, R-85-1)
- **[AC-82]** 別表記(大文字小文字違い・ジャンクション経由等)で指定した自身の配下への移動 / コピーが、事前検証で `destination_inside_source` として拒否され、再帰的な自己コピーが発生しないこと。(R-37-1, R-24)
