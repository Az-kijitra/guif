## 0. 改訂の位置づけ

- 前版 SPEC-0300-0002 は「維持対象であること」と「既存実装の参照点」のみを記録した骨組みであり、前版§3で「表示カラム・ソート・連動仕様・性能要件」を未確定として ISS-0006 に送っていた。
- 本改訂は、ISS-0001(RESOLVED、発注者確認 2026-09-22)で **Phase 1 = SPEC-0300-0002 + SPEC-0300-0003** と確定したことを受け、基準ブランチ `main` を対象とした検証済み調査(上記一次出典)に基づいて、実装着手可能な粒度(画面仕様・操作仕様・受入基準)へ詳細化したものである。
- 前版の確定条項(R-01〜R-03)は §2 にそのまま継承する。矛盾は生じさせていない。
- **記法**: 各条項の末尾に【根拠: 調査§x.y / main:<パス>:<行>】を付す。調査資料に記述がない事項は条項化せず「TBD: 要確認」として §9 に列挙し、`specs/_issues.md` に起票する。調査資料から直接読み取れないが仕様として必要な補完は【導出】と明示する(ISS-0016の教訓を踏まえた運用)。
- 既存コードの扱いは ISS-0013(RESOLVED、発注者確認 2026-09-22)に従い、**機能単位でのロジック移植を許容する**(参照専用ではない)。ただし SPEC-0100-0002 に従い、無条件のコピーやスコープ外機能の残骸の持ち込みは行わない。

## 1. 適用範囲

- 本仕様はファイル一覧(マルチカラムリスト)とディレクトリツリーの表示・操作を対象とする。
- ファイル一覧上で起動される個別機能の中身(検索=SPEC-0300-0004、ファイル操作=SPEC-0300-0005、ZIP=SPEC-0300-0006、ジャンプリスト/履歴=SPEC-0300-0007、ビューア=SPEC-0300-0008)は本仕様の対象外であり、各仕様に委ねる。
- キー割当そのものは SPEC-0300-0010(SPEC-0300-0003 改訂版)で定義する。本仕様では動作の意味のみを規定し、既定キーは参考として括弧書きする。

- **[R-15] ファイル一覧は固定列ヘッダーを持つ表形式ではなく、「縦優先・列送り」のマルチカラムグリッドとする。** すなわち CSS Grid の `grid-auto-flow: column` を用い、画面の高さに収まる行数を先に埋め、それを超える件数は右方向へ新しい列を追加していく。【根拠: 調査§1.2 / main:app/src/lib/components/FileList.svelte:130-136】
- **[R-16] 行数・列数・列幅はJavaScript側で動的に計算する。**【根拠: 調査§1.2 / main:app/src/lib/utils/list_layout.ts:28-80】
  - **[R-16-1] 行数 `rows` = コンテナ高さ ÷ 行高(CSS変数 `--list-row-height`、フォールバック 32px)。**【根拠: 調査§1.2 / main:app/src/lib/utils/list_layout.ts:28-80】
  - **[R-16-2] 列数 `cols` = 「コンテナ幅に収まる最大列数」と「全件数 ÷ rows で必要となる列数」の小さい方。**【根拠: 調査§1.2 / main:app/src/lib/utils/list_layout.ts:55-57】
  - **[R-16-3] 1列の最小幅は表示項目の有無で変化し、名前 140px を基準に、サイズ表示時 +72px、更新日時表示時 +140px を積み上げて算出する。**【根拠: 調査§1.2 / main:app/src/lib/utils/list_layout.ts:40-51】
- **[R-17] コンテナのリサイズ時はレイアウトを再計算する(ResizeObserver相当)。**【根拠: 調査§1.2 / main:app/src/lib/effects/list_layout.ts:22-35】
- **[R-18] 表示しきれない列がある場合は水平スクロールを提供し、スクロール停止後に列単位でスナップする。**【根拠: 調査§1.2 / main:app/src/lib/effects/list_layout.ts:36-58】
- **[R-19] 画面外に隠れている列が存在する場合、一覧の先頭セル/末尾セルに方向を示すオーバーフローマーカー(矢印)を表示する。**【根拠: 調査§1.2 / main:app/src/lib/components/ListRow.svelte:47-52, main:app/src/lib/utils/list_layout.ts:107-118】

## 4. ソート

- **[R-30] ソート対象は `name` / `size` / `type` / `modified` の4種類とする。**【根拠: 調査§1.3 / main:app/src/lib/ui_constants.ts:1, main:app/src/lib/components/SortMenu.svelte:17-40】
- **[R-31] ソートは昇順/降順のトグル式とする。** 現在のソートキーと同じキーを再選択すると `asc` ⇔ `desc` を反転し、別のキーを選択した場合は `asc` にリセットする。【根拠: 調査§1.3 / main:app/src/lib/page_sort_menu.ts:36-47】
- **[R-32] ソートの実処理はバックエンド(ディレクトリ列挙時)で行い、ソート済みの配列をフロントエンドがそのまま表示順として用いる。フロントエンド側で再ソートしない。**【根拠: 調査§1.3, §1.6 / main:app/src-tauri/src/fs_query.rs:194-224】
- **[R-33] 各ソートキーの比較規則は次のとおりとする。**【根拠: 調査§1.3 / main:app/src-tauri/src/fs_query.rs:200-215】

| キー | 比較規則 |
|---|---|
| `name` | 大文字小文字を無視した名前比較 |
| `size` | バイト数の数値比較 |
| `type` | ①ディレクトリを先頭にグループ化 → ②拡張子(小文字)比較 → ③名前(小文字)比較 の3段階 |
| `modified` | 更新日時文字列としての比較(文字列フォーマットは TBD、§9-b) |

- **[R-34] ソートメニューはキーボード操作可能なポップアップ(`role="menu"`)とし、上下矢印で項目移動、Enter で確定、Escape で閉じる。開閉は `sort_menu` アクション(既定 `S`)でトグルする。**【根拠: 調査§1.3 / main:app/src/lib/page_sort_menu.ts:62-102, main:app/src/lib/utils/keyboard_list.ts:358-366】
- **【ISS-0022-c解消済み・発注者確認 2026-09-22】初期表示時の既定ソートキーは`name`、既定ソート順は昇順(`asc`)とする(暫定既定値として確定)。**

## 5. ツリービューとファイル一覧の連動

- **[R-40] ツリーはルートパスから開始し、子ディレクトリをオンデマンドで取得する(展開時に初めて取得する)。**【根拠: 調査§1.4 / main:app/src/lib/page_tree.ts:72-114】
- **[R-41] ツリーの子ノード取得はファイル一覧と同一のディレクトリ列挙APIを用い、`sortKey: "name" / sortOrder: "asc"` 固定・ディレクトリのみ抽出で行う。ツリー専用のバックエンドコマンドは設けない。**【根拠: 調査§1.4, §1.6 / main:app/src/lib/page_tree.ts:77-89】
- **[R-42]【ISS-0022-d解消済み・発注者確認 2026-09-22】ツリー構築時の自動展開は行わない。** main はディレクトリ列挙時に閾値ベースの自動展開(`autoExpandDepth`/`autoExpandEntryLimit`)を行うが(根拠: 調査§1.4 / main:app/src/lib/page_tree.ts:90,106-113)、新プロダクトでは暫定既定値として自動展開なしを採用する(`autoExpandDepth`=0相当)。ツリーの各ノードはユーザーが手動で展開するまで折りたたまれた状態とする。
  - **【ISS-0022-d解消済み 2026-09-22】** `autoExpandDepth` / `autoExpandEntryLimit` はR-42により新プロダクトでは不使用(自動展開なし)。
- **[R-43] ツリー ⇒ 一覧の連動: ツリーノードを選択(クリックまたは Enter)し、そのパスが現在のパスと異なる場合、当該パスを開いてファイル一覧を更新する。**【根拠: 調査§1.4 / main:app/src/lib/page_tree.ts:142-149】
- **[R-44] 一覧 ⇒ ツリーの連動: ディレクトリを開いた際、ツリー表示中であれば対象パスを基準にツリーを再構築して追従させる。ツリー非表示中はツリー状態をクリアするのみとする。**【根拠: 調査§1.4 / main:app/src/lib/page_dir.ts:71-75】
- **[R-45] 連動は「ツリー選択 → 一覧のディレクトリ読み込みをトリガーする」片方向の依存関係として実装する。** 一覧側からツリーへは、ディレクトリ読み込み処理の一部としてツリー再構築を呼び出す形とする。【根拠: 調査§1.4(「すなわち『ツリー選択 → リスト側の`loadDir`をトリガー』という一方向の連動」)/ main:app/src/lib/page_tree.ts:142-149, main:app/src/lib/page_dir.ts:71-75】
  - 後段(【導出】): ツリーと一覧が相互に更新を呼び合う双方向バインディングにはしない。これは調査資料が記述する一方向構造から spec-writer が導出した設計上の禁止規定であり、`main` に「双方向バインディングを禁じる」旨の記述があるわけではない。ISS-0030(RESOLVED)により、移植容易性のため仕様として維持する。

## 6. 操作仕様(選択・フォーカス・展開/折りたたみ)

### 6.1 選択

- **[R-50] 単一選択: 行をクリックすると当該エントリのみを選択状態にし、範囲選択の起点(アンカー)を更新する。**【根拠: 調査§1.5 / main:app/src/lib/components/FileList.svelte:83-97】
- **[R-51] 範囲選択: Shift + クリックで、アンカーからクリック位置までを範囲選択する。**【根拠: 調査§1.5 / main:app/src/lib/components/FileList.svelte:87-90, main:app/src/lib/utils/selection.ts:35-48】

## 10. 受入基準

本節はチェック可能な受入項目である。Phase 1 の完了判定に用いる。

**SPEC-0300-0010 との役割分担(ISS-0025 解消、2026-09-22)**: 本仕様の受入基準は「アクションが発火したときの**表示・選択・フォーカスの結果**」のみを検証する。「特定のキーを押すと当該アクションが発火する」ことの検証は SPEC-0300-0010 を正本とし、本仕様では持たない。初版で重複していた項目は、対応する SPEC-0300-0010 の AC への参照に置き換えた(AC番号は追跡性のため欠番にせず維持する)。

### 10.1 画面構成

- **[AC-01]** メニューバー / パスバー / ツリーパネル / ファイル一覧 / ステータスバー の5ブロックが表示されること。(R-10, R-11)
- **[AC-02]** ファイル一覧が、画面の高さに収まる行数まで縦に埋まった後、右方向へ新しい列を追加する「縦優先・列送り」で表示されること。(R-15)
- **[AC-03]** ウィンドウの高さを変更すると1列あたりの行数が再計算され、表示が追従すること。(R-16-1, R-17)
- **[AC-04]** ウィンドウの幅を変更すると表示列数が再計算され、表示が追従すること。(R-16-2, R-17)
- **[AC-05]** 全エントリが1画面に収まる場合、余分な空列が生成されないこと(列数が「必要列数」を超えないこと)。(R-16-2)
- **[AC-06]** 表示しきれない列がある状態で水平スクロールすると、スクロール停止後に列の境界へスナップすること。(R-18)
- **[AC-07]** 画面外に隠れた列があるとき、一覧の先頭/末尾にオーバーフローマーカー(矢印)が表示され、隠れた列がなくなると消えること。(R-19)
- **[AC-08]** 初期起動時にツリーパネルが表示されていること(既定 `ui_show_tree: true`)。(R-13) ※`toggle_tree` のキー操作による表示/非表示切替の検証は **SPEC-0300-0010 AC-17** に一本化(ISS-0025)。
- **[AC-09]** ツリーパネル内にフォーカスがある状態で `toggle_tree` により非表示にすると、フォーカスがファイル一覧へ移ること。(R-14)

- **[AC-20]** `name` ソートで、大文字小文字を無視した名前順に並ぶこと。(R-33)
- **[AC-21]** `size` ソートで、バイト数の昇順/降順に並ぶこと。(R-33)
- **[AC-22]** `type` ソートで、ディレクトリが先頭にまとまり、その後が拡張子順、同一拡張子内が名前順に並ぶこと。(R-33)
- **[AC-23]** ソート結果がバックエンドから返る順序どおりに表示され、フロントエンドでの再ソートが行われないこと。(R-32)

### 10.4 ツリーと一覧の連動

- **[AC-24]** ツリーノードをクリックまたは Enter で選択すると、右側のファイル一覧が当該ディレクトリの内容に更新されること。(R-43)
- **[AC-25]** 現在表示中と同一のパスのツリーノードを選択した場合、ディレクトリの再読み込みが発生しないこと。(R-43)
- **[AC-26]** 一覧側でディレクトリを開いたとき(Enter / Backspace)、ツリー表示中であればツリーが当該パスを基準に再構築され追従すること。(R-44)
- **[AC-27]** ツリー非表示の状態で一覧側のディレクトリを移動しても、ツリー再構築処理が走らないこと。(R-44)
- **[AC-28]** ツリーの子ノードが、展開されるまで取得されない(オンデマンド取得である)こと。(R-40)
- **[AC-29]** ツリーの子ノードにディレクトリのみが表示され、名前の昇順で並ぶこと(一覧側のソート設定の影響を受けないこと)。(R-41)
- **[AC-30]** ツリー構築直後、いずれのノードも自動展開されておらず、全ノードが折りたたまれた状態であること。(R-42。ISS-0022-d解消済み・2026-09-22: 自動展開なしに変更)
- **[AC-31]** ユーザーがノードを手動展開するまで、その子ノードは表示されないこと。(R-42)

### 10.5 選択

- **[AC-32]** 行をクリックすると、その1件のみが選択状態になること。(R-50)
- **[AC-33]** ある行をクリックした後、別の行を Shift+クリックすると、その2行を含む範囲が選択されること。(R-51)
- **[AC-34]** Ctrl(Cmd)+クリックで、既存の選択を保ったまま個別に選択を追加/解除できること。(R-52)
- **[AC-35]** **SPEC-0300-0010 AC-13 に一本化**(ISS-0025)。`select_toggle` の発火による「選択のトグル + フォーカス1行下移動」は R-53 として条項のみを規定し、検証は SPEC-0300-0010 で行う。
- **[AC-36]** **SPEC-0300-0010 AC-14 に一本化**(ISS-0025)。`select_all` の発火は SPEC-0300-0010 で検証する。選択対象範囲の結果検証は AC-39 を参照。
- **[AC-37]** **SPEC-0300-0010 AC-15 に一本化**(ISS-0025)。`clear_selection` による選択解除は SPEC-0300-0010 で検証する。
- **[AC-38]** 選択の反転を実行すると、表示中エントリのうち選択済みが非選択に、非選択が選択済みになること(対象は表示中〈フィルタ適用後〉のエントリのみ。非表示エントリの選択状態は変化しない。R-54。起動手段は TBD §9-e)
- **[AC-39]** 検索/フィルタで表示件数が絞られている状態で `select_all` を実行すると、**表示中のエントリのみ**が選択対象となり、非表示のエントリは選択されないこと。選択の反転も同様に表示中エントリのみを対象とすること。(R-55。ISS-0029解消済み・発注者確認 2026-09-22: mainの「全件」挙動から意図的に変更)
- **[AC-40]** 別のディレクトリを開くと、選択状態・フォーカス・アンカーがリセットされること(選択なし、フォーカス先頭)。(R-72)

### 10.6 フォーカス移動・展開

- **[AC-41]** **SPEC-0300-0010 AC-06 に一本化**(ISS-0025)。`move_up` / `move_down` による表示順1行ずつの移動(R-57)は SPEC-0300-0010 で検証する。
- **[AC-42]** **SPEC-0300-0010 AC-07 に一本化**(ISS-0025)。`move_left` / `move_right` による列単位ジャンプ(R-58)は SPEC-0300-0010 で検証する。
- **[AC-43]** **SPEC-0300-0010 AC-08 に一本化**(ISS-0025)。`page_up` / `page_down`(R-59)は SPEC-0300-0010 で検証する。
- **[AC-44]** **SPEC-0300-0010 AC-16 に一本化**(ISS-0025)。Shift 併用時の範囲選択拡張(R-60)は SPEC-0300-0010 で検証する。
- **[AC-45]** 検索/フィルタで一部のエントリが非表示の状態でも、フォーカス移動が表示中のエントリのみを辿ること(非表示エントリを経由しないこと)。(R-56)
- **[AC-46]** **SPEC-0300-0010 AC-09 に一本化**(ISS-0025)。Enter によるディレクトリを開く操作(R-61)は SPEC-0300-0010 で検証する。ファイルに対する Enter は Phase 1 対象外(§8.1)。
- **[AC-47]** 一覧が空のディレクトリでも `go_parent` が機能すること。(R-63) ※Backspace でのアクション発火の検証は **SPEC-0300-0010 AC-10**(ISS-0025)。
- **[AC-48]** ツリーのキャレットボタンのクリックで、ノードの展開/折りたたみが切り替わること。(R-64)
- **[AC-49]** ツリーにフォーカスがある状態で `move_right` が発火したとき、未展開ノードが展開されること。(R-65) ※キー(→)での発火検証は **SPEC-0300-0010 AC-11**(ISS-0025)。
- **[AC-50]** ツリーにフォーカスがあり、対象ノードが既に展開済みで子を持つ場合、`move_right` で最初の子ノードへフォーカスが移ること。(R-65。SPEC-0300-0010 AC-11 は展開/折りたたみのみを検証するため、本項の「最初の子へのフォーカス移動」は本仕様が正本)
- **[AC-51]** ツリーにフォーカスがある状態で `move_left` が発火したとき、展開中のノードは折りたたまれ、折りたたみ済み(または子を持たない)ノードでは親ノードへフォーカスが移ること。(R-66。「親ノードへのフォーカス移動」は本仕様が正本)

### 10.7 アクセシビリティ
