## 1. 適用範囲

- 本仕様はファイル一覧に対する**名前の絞り込み検索**(部分一致および正規表現)の起動・入力・マッチング・結果反映・終了を対象とする。
- キー割当そのもの(「どのキーを押すと `search` アクションが発火するか」)の正本は **SPEC-0300-0010** である。本仕様は発火後の振る舞いを規定する。§4.2 #25 の windows 既定値について Phase 3 調査が当初 `Ctrl+F` と誤引用していた件は ISS-0055 として起票されたが、オーケストレーターの `main` 直接確認により RESOLVED 済み(windows/vim とも `/` で SPEC-0300-0010 と一致、§10-e参照)。
- 検索結果として表示されるファイル一覧そのものの表示仕様(マルチカラム、ARIA、選択・フォーカス)の正本は **SPEC-0300-0009** である。本仕様は「絞り込み結果をどう渡すか」までを規定する。
- ファイル内容の全文検索、再帰(サブディレクトリ横断)検索、ジャンプリスト/履歴(SPEC-0300-0007)は本仕様の対象外である(§7、§9)。

| 2 | メニューバー(Edit メニューの検索項目) | メニュー項目にはキーボードショートカットを併記する |

### 3.2 起動時のフォーカス(ISS-0053)

- **[R-105]【ISS-0053 RESOLVED・発注者確認 2026-09-24】検索バーが表示された時点で、起動経路によらず常に検索入力欄へフォーカスを移す。**【発注者確認 2026-09-24。`main` はグローバルキー経由では `searchActive` を立てるだけでフォーカス処理を行わず(調査§2.1 / main:app/src/lib/utils/keyboard_list.ts:353-357)、Edit メニュー経由では `await tick()` 後に入力欄へフォーカスする(調査§2.1 / main:app/src/lib/page_menu_runtime_inputs_from_state.ts:17-20)という不整合があった。新プロダクトでは**この不整合を踏襲せず統一する**】

### 3.3 終了経路と終了時のフォーカス復帰(ISS-0054)

- **[R-106] 検索バーが閉じる(DOM から外れる)経路は次の3つに限定する。**【根拠: 調査§2.3 / main:app/src/lib/actions/history.ts:79-101, main:app/src/lib/components/SearchBar.svelte:9-38】

| # | 経路 | 契機 |
|---|---|---|
| 1 | キャンセル(Escape) | 検索入力欄で Escape を押す |
| 2 | キャンセル(Clear ボタン) | 検索バー内の Clear ボタンを押す |
| 3 | 空クエリでの確定 | クエリが空(trim 後)の状態で Enter または Apply ボタンで確定する |

- **[R-107]【ISS-0054 RESOLVED・発注者確認 2026-09-24】R-106 のいずれの経路であっても、検索バーが閉じる際に明示的にファイル一覧へフォーカスを戻す。** ブラウザ既定動作(`document.body` へフォーカスが落ちる)に委ねてはならない。【発注者確認 2026-09-24。`main` には明示的なフォーカス復帰処理が存在しない(調査§2.4 / main:app/src/lib/page_mount_dom_handlers_inputs_from_state.ts:128-131)】
  - **[R-107-1] フォーカス復帰先は次の優先順で決定する。**【導出。発注者確認は「現在フォーカス中の行、無ければ適切なフォールバック」までを指示しており、フォールバックの具体順序は spec-writer の導出である】
    1. 現在フォーカス中の行要素(`focusedIndex` が指すエントリの行)が表示されている場合は当該行。
    2. 当該行が存在しない/表示されていない場合はファイル一覧のルート要素(`role="listbox"` を持つ要素、SPEC-0300-0009 R-24)。
    3. 一覧が空(エントリ0件)の場合もファイル一覧のルート要素とする。
  - **[R-107-2]** フォーカス復帰後、追加の操作を要さずに一覧のキー操作(フォーカス移動・選択等)が機能すること。【導出。R-107 の目的(キーボード中心操作の連続性、SPEC-0300-0010 R-01)から導かれる要件】

- **[R-108] キャンセル(R-106 #1 / #2)では、クエリ文字列と正規表現エラー文言をリセットし、検索状態を非アクティブにする。**【根拠: 調査§2.3 / main:app/src/lib/actions/history.ts:91-101】
  - 正規表現モードのトグル状態をキャンセル時にリセットするかは調査資料に記述がない → TBD(§10-f、ISS-0059)。
- **[R-109] 確定操作(Enter または Apply ボタン)の挙動は次のとおりとする。**【根拠: 調査§2.3 / main:app/src/lib/actions/history.ts:79-88, main:app/src/lib/components/SearchBar.svelte:9-14】

  - **[R-109-2]【ISS-0061 RESOLVED・発注者確認 2026-09-24】** クエリが非空の場合は、当該クエリを検索履歴に追加した上で、**検索バーは開いたまま(絞り込みも維持したまま)、フォーカスをファイル一覧側へ移す。** 絞り込み自体は R-110 により既にライブ反映済みであるため、確定操作によって `filteredEntries` は変化しない。
    - **[R-109-2-1]** フォーカス移動先は R-107-1 の優先順に準ずる: ① 現在フォーカス中の行が `filteredEntries` に含まれていればその行、② 含まれない(絞り込みで非表示になっている)場合は `filteredEntries` の先頭行、③ `filteredEntries` が0件の場合は移動を行わず、検索入力欄にフォーカスを残す。【導出。R-107-1 との整合、および ISS-0061 の発注者確認(Enter 確定で一覧へフォーカスを移す)を具体化したもの】

    - **[R-109-2-3]** 検索入力欄へ戻るには、`search` アクションを再度発火する(R-105-2。クエリ・絞り込みはリセットしない)。【導出】
    - **[R-109-2-4]** 検索バーが開いている間は、フォーカスが一覧側にあっても Escape は検索のキャンセル(R-108)として扱い、検索バーを閉じて絞り込みを解除する(発注者の実機確認 2026-09-24 により、当初の「一覧側キーマップ〈clear_selection〉に従う」を訂正)。【導出→訂正】

## 4. クエリ入力とマッチング

### 4.1 ライブ絞り込み(デバウンスなし)

- **[R-110] 検索クエリは入力のたびに即時反映する(ライブ絞り込み)。デバウンス・スロットリングは実装しない。**【発注者確認 2026-09-24(§0.2 #3): `main` と同様、デバウンス無しでキー入力ごとに同期的に即時再計算する方針を踏襲する。根拠: 調査§5.2(リポジトリ全体に `debounce` / `throttle` の実装は0件)/ main:app/src/routes/+page.svelte:394】
- **[R-111] クエリは前後の空白を除去(trim)した上で評価する。trim 後が空文字の場合は絞り込みを行わず(全件表示)、正規表現エラー文言もクリアする。**【根拠: 調査§3 / main:app/src/lib/utils/history.ts:84-86】

### 4.2 部分一致(既定モード)

- **[R-112] 部分一致は、エントリ名を小文字化した文字列に対し、小文字化したクエリが含まれるかどうかで判定する(大文字小文字を区別しない部分一致)。**【根拠: 調査§3.1 / main:app/src/lib/utils/history.ts:100-104】
  - **[R-112-1] 検索対象はエントリの名前(`Entry.name`)のみとし、パス(`Entry.path`)は対象に含めない。**【根拠: 調査§3.1 / main:app/src/lib/utils/history.ts:100-104, main:app/src/lib/types.ts:19-26】

### 4.3 正規表現モード

- **[R-113] 検索バー上のトグルで正規表現モードに切り替えられる。トグルはクリックで即座に反映し、確定操作(フォーム送信)を必要としない。**【根拠: 調査§3.2 / main:app/src/lib/components/SearchBar.svelte:26-31】

- **[AC-104]** 1文字入力するたびに一覧の表示件数が絞り込まれ、確定操作(Enter / Apply)を必要としないこと。(R-110)
- **[AC-105]** 入力から絞り込み反映までに遅延(デバウンス/スロットリング)が挿入されていないこと。判定方法: 入力イベント直後の同一評価タイミングで絞り込み結果が観測できること、およびソースツリーに検索経路のデバウンス/スロットリング実装が存在しないこと。(R-110, R-133)
- **[AC-106]** 部分一致が大文字小文字を区別しないこと(例: 名前 `ABC.txt` がクエリ `abc` で一致し、クエリ `ABC` でも一致すること)。(R-112)
- **[AC-107]** パス部分にのみ現れる文字列(例: 親ディレクトリ名)をクエリにしても、名前が一致しないエントリは絞り込み結果に残らないこと。(R-112-1)
- **[AC-108]** クエリの前後に空白を付けても、trim された内容で一致判定されること。また空白のみのクエリでは全件が表示されること。(R-111)
- **[AC-109]** 正規表現モードで、大文字小文字を区別しない一致が行われること(例: `^a` が `Apple.txt` に一致すること)。(R-113-2)
- **[AC-110]** 正規表現モードで不正なパターン(例: `[`)を入力した場合、検索バー内にエラー文言が表示され、一覧は全件表示に戻り、続けて文字入力・Escape・モード切替が行えること(アプリがブロックされないこと)。(R-113-3, R-113-4)
- **[AC-111]** 不正パターンを有効なパターンに修正するとエラー文言が消え、絞り込みが再開されること。(R-113-5)
- **[AC-112]** 正規表現モードの既定がオフ(部分一致)であり、起動直後は部分一致として評価されること。(R-113-1)

### 11.3 確定・キャンセル・終了時フォーカス

- **[AC-113]** 確定操作(Enter / Apply)でクエリが検索履歴に追加され、検索バーが開いたままであり、かつ絞り込み結果(表示件数・表示順)が確定操作の前後で変化しないこと。(R-109-2)
- **[AC-113-1]** **確定操作(Enter / Apply)の直後、フォーカスがファイル一覧側(絞り込み後の一覧内の該当行、R-109-2-1 の優先順)に移り、追加のクリックやフォーカス操作なしで一覧のキー操作(移動・選択・開く等)が機能すること。操作対象は絞り込み後の `filteredEntries` の範囲に限られること。**(R-109-2, R-109-2-1, R-109-2-2。**ISS-0061**)
- **[AC-113-2]** 確定操作でフォーカスが一覧側へ移った状態で `search` アクションを再度発火すると、クエリと絞り込みを保持したまま検索入力欄へフォーカスが戻ること。(R-109-2-3, R-105-2)
- **[AC-113-3]** 確定操作でフォーカスが一覧側へ移った状態で Escape を押すと、検索がキャンセルされ検索バーが閉じ、一覧が全件表示に戻ること。(R-109-2-4)
- **[AC-114]** クエリが空(trim 後)の状態で確定操作を行うと、検索バーが閉じること。(R-109-1, R-106 #3)
- **[AC-115]** Escape および Clear ボタンで、クエリとエラー文言がリセットされ検索バーが閉じ、一覧が全件表示に戻ること。(R-108, R-117)
- **[AC-116]** **R-106 の3経路(Escape / Clear ボタン / 空クエリでの確定)のいずれで検索バーが閉じた場合も、フォーカスがファイル一覧へ戻ること**(`document.body` 等にフォーカスが落ちていないこと)。フォーカス先は R-107-1 の優先順(フォーカス中の行 → 一覧のルート要素)に従うこと。(R-107, R-107-1。**ISS-0054**)
- **[AC-117]** 検索バーが閉じた直後に、追加のクリックやフォーカス操作なしで一覧のフォーカス移動キー(↑ / ↓)が機能すること。(R-107-2)

### 11.4 結果の反映

- **[AC-118]** 検索で絞り込み中に列挙結果の配列(`entries`)が書き換えられていないこと。判定方法: 検索を解除した際に、絞り込み前と同一の件数・同一の並び順が復元されること。(R-115, R-117)
- **[AC-119]** 検索結果が0件のとき、汎用の「項目なし」表示のみが表示され、検索結果0件専用のメッセージが表示されないこと。(R-118)
- **[AC-120]** フォーカス中のエントリが絞り込みにより非表示になった場合、ファイル一覧に `aria-activedescendant` が付与されないこと(非表示行の ID を指し続けないこと)。(R-119)
- **[AC-121]** 検索の開始・クエリ変更・終了によって、選択済みエントリの集合が変化しないこと。(R-119-1)
- **[AC-122]** 検索フィルタ適用中の `select_all` / 選択の反転の対象範囲の検証は **SPEC-0300-0009 AC-39 に一本化**する(本仕様では重複して持たない)。本仕様は R-123 として規則の適用を明記するに留める。
- **[AC-123]** 検索入力欄にフォーカスがある間、vim プロファイルの `j` / `k` / `h` / `l` や windows プロファイルの `S`(ソートメニュー)等を入力しても一覧側のアクションが発火せず、入力欄に文字として入ること。Escape / ArrowUp / ArrowDown / Enter のみが検索バーの操作として働くこと。(R-120, R-121)
- **[AC-124]** 検索入力欄で ArrowUp を押すと直近の検索クエリが入力欄に読み込まれ、ArrowDown を押すと入力欄が空になること。履歴を2件以上遡る手段が存在しないこと。(R-121, R-122)

### 11.5 スコープ・アーキテクチャ

- **[AC-125]** 検索がサブディレクトリの内容を対象にしないこと(現在のディレクトリ内のエントリのみが絞り込み対象であること)。(R-125)
- **[AC-126]** 検索クエリの入力・確定・モード切替・キャンセルのいずれによっても、バックエンドへのコマンド呼び出し(ディレクトリ再列挙を含む)が発生しないこと。(R-127-1)
- **[AC-127]** Rust 側に検索専用のコマンド・モジュールが存在しないこと。判定方法: `app/src-tauri/src` 配下に検索用 `#[tauri::command]` が0件であること。(R-127)
- **[AC-128]** `app/src/lib/features/search/` が他の feature ディレクトリ(`app/src/lib/features/<other>/`)を直接 import していないこと。判定方法: ソースツリーに対する import 文の検査。(R-129)
- **[AC-129]** マッチングロジックが DOM / Tauri に依存しない純粋関数として単体テストされていること(部分一致・正規表現・不正正規表現・空クエリの各分岐を含む)。(R-128-1、SPEC-0400-0001)
- **[AC-130]** 検索の実装に Storage Provider 抽象化・`*_by_ref` 系コマンドが用いられていないこと。(R-131、SPEC-0100-0005 R-06)
