- 前版 SPEC-0300-0007 は「登録したパスへ素早く移動するジャンプリストを提供する(R-01)」「訪問したディレクトリの履歴を提供する(R-02)」「既存データの移行は行わない(R-03)」という3条項のみの骨組みであり、§3 で「ジャンプリストの登録/編集方法・上限数・並び順」「履歴の保持件数・永続化の有無・セッションをまたぐ復元の有無」「履歴とジャンプリストの永続化先・ファイル形式」を未確定として ISS-0006 に送っていた。

### 15.6 永続化

- **[AC-235]** 訪問履歴・ジャンプリスト・検索履歴が単一のファイルに保存されること。判定方法: 保存後に生成・更新されるファイルが1つであること。(R-239)
- **[AC-236]** 保存先が既存 ReflexFiles の `history.toml` / `jump_list.toml` / `config.toml` のいずれでもなく、旧ファイル・旧フィールド名を読み込む処理が存在しないこと。(R-239-2, R-239-3, R-202)
- **[AC-237]** 保存処理が一時ファイルへの書き出しとリネームによって行われ、保存対象ファイルを直接上書きしないこと。判定方法: 保存経路の実装検査、および書込途中で中断した場合に既存ファイルの内容が失われないこと。(R-241)
- **[AC-238]** 永続化ファイルを壊れた内容に書き換えて起動した場合に、(i) 元ファイルが退避され、(ii) 3種のリストが空の状態で起動し、(iii) 読込に失敗したことが状態メッセージで通知されること。かつ退避されたファイルがその後の保存で失われないこと。(R-242)
- **[AC-239]** 永続化ファイルが存在しない状態で起動した場合に、退避も通知も行われず、空の状態で正常に起動すること。(R-242-1)
- **[AC-240]** 上限を超える件数(訪問履歴 51 件以上 / ジャンプ 21 件以上 / **検索履歴 21 件以上**)および重複を含む永続化ファイルを用意して起動した場合に、読み込まれたリストが上限以内であり重複を含まないこと。(R-205-2, R-245-1, R-248-3)
- **[AC-241]** 訪問履歴・ジャンプリストを変更した後にアプリを終了し再起動すると、変更後の内容が復元されること。空のリストを保存した場合に、再起動後も空であること(既定値で埋められないこと)。(R-245)
- **[AC-242]** `exit` アクション(既定 Ctrl+Q)による終了後に再起動した場合、終了直前の変更が永続化ファイルに反映されていること。(R-244)
- **[AC-243]** 一覧の開閉状態・モード・選択位置が永続化されていないこと(再起動後に一覧が開いた状態にならないこと)。(R-226)
- **[AC-244]** 検索を確定して検索履歴を更新した後にアプリを再起動し、検索バーで ArrowUp を押すと直近のクエリが読み込まれること。(R-247, R-249。SPEC-0300-0012 R-121 / R-122)
- **[AC-245]【発注者追加回答 2026-09-25・第1版から変更】** 21 個の異なるクエリを順に確定した後、永続化される検索履歴が 20 件であり、最初のクエリが含まれていないこと。(R-205, R-248, R-248-1)
- **[AC-245-1]【新設】** 同一クエリを再度確定した場合に、当該クエリが検索履歴の先頭へ移動し、件数が増えないこと。(R-248-2)
- **[AC-245-2]【新設】** 検索履歴が20件保存されている状態でも、検索バーの ArrowUp で読み込まれるのは直近1件のみであり、2件目以降を呼び出す UI が存在しないこと。(R-248-4。呼び出し UI 自体の正本は SPEC-0300-0012 R-121 / R-122)
