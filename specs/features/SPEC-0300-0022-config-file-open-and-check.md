## 0. 経緯・出典

### 0.1 発注者の要望(2026-10-18、原文)

> 設定ファイルを簡単に編集できるようにしたい。ただし、設定画面などは作らない。設定ファイルをVS Codeで素早く開くだけでよい。メニューに「設定ファイルを開く」の機能があれば良い。
> ポイントは、設定ファイルに詳細なコメント（設定の説明、取り得る値、デフォルト値）があること。起動時に設定ファイルの形式をチェックして問題があれば、デフォルト設定で起動し、ステータスバーにエラーに関する情報（行、設定項目）を表示する。
> メニューには「設定ファイルのチェック」機能がある。これは起動時のチェックと同じであり、任意のタイミングで実行できるようにしたものである。

要望の要素(本仕様での呼び方):

- **【要望 a】** 設定画面など、設定の値を変える画面は作らない。
- **【要望 b】** メニューの「設定ファイルを開く」で、設定ファイルを VS Code で素早く開く。
- **【要望 c】** 設定ファイルに詳細なコメント(設定の説明、取り得る値、既定値)がある。
- **【要望 d】** 起動時に設定ファイルの形式をチェックし、問題があれば既定の設定で起動し、ステータスバーにエラーの情報(行、設定項目)を表示する。
- **【要望 e】** メニューの「設定ファイルのチェック」は起動時のチェックと同じで、任意のときに実行できる。

### 0.2 発注者決定(2026-10-18、AskUserQuestion、オーケストレーター経由で伝達。変更不可)

- **【確定 #1】雛形の用意は「両方」。** 「設定ファイルを開く」を実行したとき `config.toml` が無ければ、全項目の説明・取り得る値・既定値をコメントで書いた雛形の `config.toml` を作ってから開く。**既にある `config.toml` は一切書き換えない。** さらに、`config.toml` とは別に、最新の内容のコメント付きの見本ファイル(例: `config.sample.toml`)を設定フォルダーに置く(版が上がって項目が増えたとき、見本で新しい項目を確かめられるようにする)。
- **【確定 #2】VS Code が見つからないときは「関連付けで開く」。** `.toml` に関連付けられたアプリで開く(関連付けが無いと Windows の「アプリを選択」画面が出る)。VS Code の場所は、外部アプリの既定(`app/src-tauri/src/external_apps/defaults.rs`)と同じ `%LOCALAPPDATA%\Programs\Microsoft VS Code\Code.exe` を想定として示した。
- **【確定 #3】誤りがあったときに既定値にする範囲は「誤りのある項目だけ」(今と同じ)。** TOML として読めないときは全部を既定値、読めるときは誤りのある項目だけを既定値とし、正しい項目は使う。
- **【確定 #4】「設定ファイルのチェック」は「チェックだけ」。** 結果をステータスバーに出すだけとする。設定の反映は今と同じく再起動のとき。

### 0.4 本リポジトリの現状(spec-writer が 2026-10-18 にソースを読んで確かめた。規範ではない)

1. **設定フォルダー**: `config/paths.rs` の `config_path` = アプリ設定ディレクトリ直下の `config.toml`。release ビルドでは `%APPDATA%\dev.guif.app`(マニュアル §3)。debug ビルドでは `REFLEXFILES_CONFIG_DIR` で上書きできる(SPEC-0400-0001 R-06)。設定フォルダーには `config.toml`(利用者が書く)、`navigation.toml` / `ui-state.toml` / `viewer-window.toml`(アプリが管理する)がある。
2. **読み込み**: `config/config_toml.rs` の `load` が1回の TOML 解析で `input_keymap_custom` / `ui_theme` / `external_apps` の生の値を返し、`config/commands.rs` の `StartupConfig::load` が起動時に1回だけ呼んで結果を保持する(R-917-8)。`config.toml` が無いときは既定の結果で、ファイルを作らない(テスト `missing_file_returns_empty_entries_and_no_parse_error`)。
3. **検証の場所**: `ui_theme` は Rust の `interpret_ui_theme`、`external_apps` の要素は Rust の `external_apps/registry.rs`、登録のキーは TypeScript の `buildRegistry`、`input_keymap_custom` の要素は TypeScript の `features/keyboard/keymap-validate.ts`(設計 MUST-86: Rust にキーの文法を二重に持たない)。起動時の通知の文は `routes/startup-wiring.ts` の `loadKeymapForStartup` が「キー割り当て → テーマ → 外部アプリ」の順に半角スペースでつなぎ(同じ関数が `externalAppsState.hydrate` で状態の書き込みも行う)、`runStartupHydrate` が `config.toml` → `ui-state.toml` → `navigation.toml` の順に ` / ` でつなぎ、`statusMessage.showPriority(…, 6000)`(`STARTUP_NOTICE_DURATION_MS`、設計 SHOULD-119)で 6 秒表示する。
4. **状態メッセージの仕組み**(`shared/state/status-message.svelte.ts`): `showPriority` は表示中の文を**置き換え**、指定の時間の間「優先」とする。優先の表示中に通常の `show` が呼ばれると、置き換えずに ` / ` で**後ろに足す**(時間は延びない)。優先でないときの `show` は置き換え、既定 2.5 秒。
5. **行番号**: 得られるのは TOML の構文エラーの行だけ(`line_number_from_span`。SHOULD-121)。`input_keymap_custom` の型違いは `line: None`。項目単位の誤り(キー割り当ての要素、`ui_theme`、外部アプリの登録・キー)には行番号が無い。
6. **知らないキー**: 最上位の知らないキー(例 `ui_them`、旧製品の `ui_show_hidden`、`input_keymap_profile`)は `load` が読まないため、何も通知されない(テスト `a_config_with_no_input_keymap_custom_table_yields_empty_entries_without_error` は `some_future_setting = 1` が誤りにならないことを確かめている)。`external_apps` の要素の知らないフィールドは SPEC-0300-0021 R-1503 / AC-1507 により通知しない。`input_keymap_custom` の知らない操作 ID は W-32 で通知する。
7. **書き込み**: アプリに `config.toml` を書く経路は無い(`config_toml.rs` 冒頭のコメント、`paths.rs` の `config_path` のコメント、`acl_consistency.rs` の `config/io.rs` 削除の検査〈MUST-92〉、`config_toml_external_apps_tests.rs` の R-1501、E2E `theme.mjs` の `checkConfigUntouched`〈`config.toml` で始まる別の名前のファイルが無いこと〉)。
8. **`Ctrl+,`**: `keymap-defaults.ts` の34種の操作 ID に `settings`(既定 `Ctrl+Comma`)がある。`key-dispatch.ts` の `matchesHardcodedShortcut` が `Ctrl+Comma` を `settings` として先取りし(SPEC-0300-0010 R-12 優先1、§3.1 #1)、`+page.svelte` の `onHardcodedShortcut: exitOnly` により何もしない。この先取りを続けるか(`settings = ""` で無効にできない副作用を許すか)は **SPEC-0300-0010 §8-a / ISS-0021 (a) で未決定(PENDING_HUMAN_REVIEW)** である。先取りは、検索入力欄(R-14-2-3)、オーバーレイ(R-14-3-2)、パスバーの編集中(SPEC-0300-0016 R-760-1)、右クリックメニューの表示中(SPEC-0300-0018 R-1084「`Ctrl+,` は設定画面が無い間は何もしない」)、メニューバーがアクティブな間(SPEC-0300-0020 R-1355)も働くと定められている。`fixed-keys.ts` の `RESERVED_FIXED_KEYS` は `Ctrl+Q`、`Ctrl+Comma`、`Shift+Enter`、`Shift+Delete`、`Tab`、`Shift+Tab`、`F10`、`Alt+F` / `E` / `V` / `G`。SPEC-0300-0010 §4.2 #13 は区分「後続(設定画面の仕様が未作成)」、R-44 は「設定アクションは設定画面を開く」、R-14 / AC-04 は「設定画面の表示中はグローバルのキー処理をしない」(実装に `isSettingsOpen` がある)。マニュアル §6 は「Ctrl+,(設定)に対応する機能はありません」。
9. **メニューバー**: 「ファイル」「編集」「表示」「移動」の4つ(SPEC-0300-0020 R-1310)。R-1311 は「設定」の項目を設けないとしている。併記は `exit = ""` でも `Ctrl+Q` を出す(`menu-bar-shortcuts.test.ts`。`Ctrl+Q` は先取りで働き続けるため)。

11. **E2E の `config.toml`**: SPEC-0400-0001 R-08-1 の 1 / SPEC-0300-0021 R-1585 の 2 により、E2E と CDP で使う `config.toml` には例外なく `external_apps` を書く(テスト用の実行ファイルだけ、または `[]`)。唯一の例外は意図して壊した `config.toml` を使う `theme.mjs` の S8。起動時に読んだ登録は再起動まで変わらないため、起動後に `config.toml` を消したり書き換えたりしても既定の4つは有効にならない。

13. **TOML のライブラリ**: `Cargo.toml` は `toml = "0.8"`(`Cargo.lock` で 0.8.23)。
14. **ステータスバー**: 1行で、状態メッセージは収まらなければ末尾を省略し、`title` に全文を入れる(SPEC-0300-0017 R-970 / AC-937)。
15. **マニュアル**: §3(設定フォルダーのファイルの表)、§4.1(メニューの項目)、§6 / §6.1(キー割り当て。操作 ID は31個を列挙し、`settings` / `help_keymap` / `refresh` を載せていない)、§6.2(テーマ)、§7(外部アプリ。§7.2 に既定の4つの TOML)。

### 0.5 本仕様を新規に起こした理由(【導出】)

「設定ファイルを開く」「設定ファイルのチェック」は、3つの設定項目の仕様(SPEC-0300-0010 / 0017 / 0021)にまたがる横断の機能であり、雛形・見本・表示・入口を持つ。どの項目の仕様に入れても他の2つとの関係が書きにくいため、外部アプリ起動(SPEC-0300-0021)を新規に起こした前例に合わせて独立の詳細仕様とする。各項目の検証規則・既定値は各仕様に残し、本仕様は参照する。

## 1. 適用範囲・用語

対象: 「設定ファイルを開く」(VS Code で開く、関連付けで開く)、雛形の作成、見本ファイルの書き出し、雛形と見本の内容と、その既定値がコードと食い違わない仕組み、起動時のチェックの表示(行・設定項目、知らない設定)、「設定ファイルのチェック」、入口(メニューバー・キー)、表示の文言、安全、テスト、マニュアル。

対象外:

- アプリが管理するファイル(`ui-state.toml`、`navigation.toml`、`viewer-window.toml`)を開く・チェックすること。

## 3. 雛形

- **[R-1610]【確定 #1 / 確定 (1)】雛形は `config.toml` が無いときだけ作る。** 作るときは、既にファイルがあれば失敗する「新規作成だけ」の開き方で作り、確かめてから作るまでの間に別のプロセスが作った場合も上書きしない(その場合は「ある」として開く)。
- **[R-1611]【確定 T-10 / レビュー MINOR-7】雛形の内容は見本の原本から作る(R-1637)。文字コードは UTF-8(BOM なし)、改行は CRLF とする。** 原本の改行(git の `autocrlf` 等でリポジトリの取り出し方により変わりうる)には依らず、雛形・見本を作るときに改行を CRLF にそろえる。受入基準のバイト単位の比較は、この「そろえた後」の内容と比べる。
- **[R-1612]【確定 T-06 / 導出】雛形を作った直後の `config.toml` は、`config.toml` が無い場合と同じ設定になる。** すべての設定の行はコメントである(R-1631)。起動時のチェック・設定ファイルのチェックで誤りも知らない設定も0件となる(AC-1631)。
- **[R-1613]【導出】雛形の作成に失敗した場合は、開かず、W-A6 を出す。** 自分が新しく作ったファイルの途中で書き込みに失敗した場合は、そのファイルを消し、作りかけのファイルを残さない。既にあったファイルには触れない。方式は設計工程。
- **[R-1614]【確定 #1 / 導出】本機能が書き込むのは、雛形の `config.toml`(無いときだけ)、見本ファイル `config.sample.toml`、見本の書き出しのための一時ファイルだけとする。** 設定フォルダーの他のファイルに触れない。退避ファイル(`.bak` 等)を作らない。一時ファイルの名前は `config.toml` で始まらないものとする(E2E `theme.mjs` の検査と同じ考え方。R-1622)。

## 5. 雛形と見本の内容

- **[R-1630]【第2版: 設定項目は `[theme]`(最上位の `theme` を含む)、`[colors]`、`[font]`、`[layout]`、`input_keymap_custom`、`external_apps` とする。`ui_theme` は廃止(SPEC-0300-0023 R-1748 / R-1830)】【要望 c / 確定 #1】雛形と見本には、すべての設定項目(`ui_theme`、`input_keymap_custom`、`external_apps`)について、説明・取り得る値・既定値をコメントで書く。**

  1. **説明の行は `## ` で始める**(`#` を2つ)。説明の空行は `##` だけの行とする。

- **[R-1680]【導出 / レビュー MINOR-6】アプリが開くのは設定フォルダーの `config.toml` だけ、書き込むのは R-1614 のとおり雛形の `config.toml`(無いときだけ)・`config.sample.toml`・見本の書き出しのための一時ファイルだけとする。** アプリは `config.toml` を TOML として読むだけで、その中の値を実行しない(外部アプリの登録の起動は SPEC-0300-0021 のとおり)。

  - `config.toml` が無い状態・壊れた状態・書き換えた状態を確かめる E2E(AC-1601、AC-1608、AC-1610、AC-1650、AC-1653 (ii)(iii) ほか)は、`external_apps = []` を書いた `config.toml` で起動した後に、テスト側で `config.toml` を消す・壊す・書き換える。起動時に読んだ登録は再起動まで変わらないため、既定の4つは有効にならない(§0.4 の 11)。

  - TOML の構文の誤りの起動時の表示(AC-1641)は、既存の例外 `theme.mjs` の S8 の中で確かめる(新しい例外を作らない)。
  - **新しい例外は次の1つだけとする**: AC-1645(`config.toml` が無い状態で起動し、通知が無く `config.toml` が作られないことを確かめる E2E)。起動時に `config.toml` が無いことそのものを確かめるため、`external_apps` を書けない。この E2E には SPEC-0300-0021 R-1585 の 2 の例外の守り((i) ページ側で外部アプリの起動の呼び出しを止める、(ii) バックエンドの範囲の検査、(iii) 許可リスト)を同じく適用し、外部アプリのキー・メニューを操作しない。SPEC-0400-0001 R-08-1 の 1 と SPEC-0300-0021 R-1585 の 2 / AC-1506 の許可リストに加える(各仕様の新版。ISS-0233 (d)(h))。
