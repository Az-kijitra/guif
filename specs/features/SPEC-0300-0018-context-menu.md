- 本仕様は、**メインウィンドウ**のファイル一覧で開く右クリックメニュー(以下「メニュー」)の開閉・項目・有効条件・実行・見た目・キー / マウス操作、および WebView 標準の右クリックメニューの抑止を対象とする。

- 用語:
  - **行メニュー**: 一覧の行を右クリックして開くメニュー。
  - **余白メニュー**: 一覧の余白を右クリックして開くメニュー。

  - **WebView 標準メニュー**: WebView2 が既定で表示するネイティブの右クリックメニュー(戻る・再読み込み・印刷・検査・コピー等)。

## 2. 開く契機

- **[R-1000]【確定 #2】メニューは、メインウィンドウのファイル一覧の行または一覧の余白を、マウス(ポインター)で右クリックしたときにのみ開く。**
- **[R-1001]【確定 #2】ツリーパネルの右クリックではメニューを開かない。** ツリーの強調ノード・展開状態・キーボードフォーカスも変えない。【後段は導出】
- **[R-1002]【確定 #2。レビュー M-2 で明確化】キーボード(Shift+F10、ContextMenu キー)由来の `contextmenu` ではメニューを開かない。マウス(ポインター)の右クリックでは必ずメニューを開く(R-1000)。** キーボード由来の場合も、入力欄(R-1011)以外では WebView 標準メニューを出さない(R-1010)。キーボード由来とポインター由来を判別する手段は設計工程に委ねる(候補: 直前の右ボタンの `pointerdown` を記録しておき、それに続く `contextmenu` だけをポインター由来とする / `PointerEvent` としての `pointerType` を参照する。実機確認は ISS-0191 (b))。【導出】
- **[R-1003]【提案 P-1022】右クリック時の修飾キー(Shift / Ctrl / Alt)は無視し、修飾なしの右クリックと同じに扱う。**

## 3. WebView 標準メニューの抑止

- **[R-1010]【確定 #3】メインウィンドウでは、入力欄(R-1011)以外のどこを右クリックしても WebView 標準メニューを出さない。** 一覧・ツリー・ステータスバー・パスバーのラベル・検索バーのボタン・オーバーレイ・ダイアログの入力欄以外の部分・本仕様のメニュー自身を含む。
- **[R-1011]【確定 #3】入力欄(パスバーの入力欄、検索入力欄、ダイアログの入力欄〈リネーム・新規作成・ZIP の出力先等〉)の右クリックでは、WebView 標準メニュー(切り取り・コピー・貼り付け等)を従来どおり出す。** 本仕様のメニューは出さない。
- **[R-1012]【導出】抑止は、入力欄の判定を除き、ほかのフェーズの UI を追加しても自動的に適用される方式(画面全体で一括して抑止し、入力欄だけを除外する)とする。** 具体的な方式(`contextmenu` の `preventDefault`、WebView2 の設定等)は設計工程に委ねる。
- **[R-1013]【確定 D3 / P-1019】ビューアウィンドウでも、WebView 標準メニューを出さない(ビューアには入力欄が無いため例外なし)。** 本文のコピーは従来どおり範囲選択と Ctrl+C で行う(SPEC-0300-0015 R-464)。画像のコピー・保存はできなくなる。正本は SPEC-0300-0015 第4版 R-502-1(理由・失うものは ISS-0190)。

## 4. 対象(選択・フォーカス)

- **[R-1020]【確定 #4-a / main】行を右クリックしたとき、その行が選択に含まれていなければ、選択をその1件に置き換え、範囲選択のアンカーをその行にする。含まれていれば選択とアンカーを変えない。** いずれの場合もフォーカス行をその行にする。
- **[R-1021]【main】余白を右クリックしたときは、選択・アンカー・フォーカス行を変えない。**
- **[R-1022]【導出】行メニューの各項目の対象は、メニューを開いた時点の「表示中の対象」(§1)とする。** 行メニューでは右クリックした行が必ず選択に含まれるため、対象は 1 件以上である(SPEC-0300-0011 R-10 の「選択 0 件ならフォーカス行」の分岐には入らない)。選択に含まれるが絞り込みで非表示のエントリは対象にしない(SPEC-0300-0011 R-10-1)。
  - **【第5版注記・例外。SPEC-0300-0021 R-1532 の 1(【確定 #4】)】外部アプリの登録の項目(R-1030-1)の対象は、選択の件数によらず、右クリックした行(R-1020 によりフォーカス行になる)の1件とする。** 余白メニューの登録の項目(R-1031-1)の対象は現在のフォルダー。
- **[R-1023]【導出】ペースト・新規作成の対象ディレクトリは、現在表示中のディレクトリとする(SPEC-0300-0011 R-13)。** 行メニューでフォルダの行を右クリックした場合も、そのフォルダの中ではなく現在のディレクトリへ貼り付ける(`main` どおり)。
- **[R-1024]【提案 P-1007】右クリックしたとき、キーボードフォーカスをファイル一覧へ移す(左クリックと同じ。行の無い部分・一覧本体の外の空きのクリックでも一覧へフォーカスを移す SPEC-0300-0017 R-956-1 と同じ扱い)。** ツリー・検索入力欄・パスバーにフォーカスがあった場合も一覧へ移る。メニューの表示中、キーボードフォーカスはメニューにある(R-1085)。

  - パスバーの編集中に一覧を右クリックした場合は、SPEC-0300-0016 R-704(他の要素へフォーカスが移ったら編集を破棄)に従って編集を破棄する。【導出】

## 7. 実行

### 7.1 共通

- **[R-1050]【導出。SPEC-0300-0015 R-401 経路 3 / R-402-2 / R-403 / R-404】「開く」は、対象の 1 件を、ダブルクリックで開く場合と同じ処理で開く。** フォルダならそのフォルダへ移動し、ファイルなら SPEC-0300-0015 §4 の判定によりビューアまたは OS の関連付けアプリで開く。
- **[R-1051]【提案 P-1003】「OSの関連付けで開く」は、対象のファイルを、`Shift+Enter`(SPEC-0300-0015 R-401-2)と同じ処理(バックエンドの起動コマンド `viewer_os_open_path`、R-405 系)で開く。** ビューアの判定(§4)を経ずに常に OS の関連付けアプリで開く。実行形式も追加の確認なしに起動する(R-405-4)。起動の失敗はステータス表示(R-405-5)。開く処理は訪問履歴に記録せず、選択・フォーカス・表示中のフォルダを変えない(R-407)。
- **[R-1052]【導出】コピー / カット / ペースト / 名前の変更 / 新規作成... は、対応するキー操作(SPEC-0300-0010 の `copy` / `cut` / `paste` / `rename` / `new_file`)が呼ぶものと同じファイル操作の処理を、R-1022 / R-1023 の対象で呼ぶ。** 確認ダイアログ・衝突確認・進捗・エラー表示・ステータス表示は SPEC-0300-0011 のとおり。「名前の変更」の対象は表示中の対象の 1 件(キー操作のフォーカス行ではない)。「新規作成...」は種別 = ファイルでダイアログを開く(R-72-3)。
- **[R-1053]【確定 #4-f / 提案 P-1012】「削除」は、ごみ箱への移動(SPEC-0300-0011 R-50)とし、Shift を押しながら実行しても完全削除にしない。** 完全削除はキーボード(`Shift+Delete`、SPEC-0300-0011 R-56-4)からのみ起動できる。確認ダイアログは SPEC-0300-0011 のとおり。
- **[R-1054]【導出】「ZIPに圧縮」「ZIPを解凍」は、キー操作(`zip_create` / `zip_extract`)と同じ処理を R-1022 の対象で呼ぶ(SPEC-0300-0014 R-307 / R-308)。** ダイアログ・進捗・エラー表示は SPEC-0300-0014 のとおり。メニューでは無効条件を R-1040 で表示するため、SPEC-0300-0014 R-308-1 の理由のステータス表示は、実行時に条件が変わった場合(R-1056)にのみ起こる。
- **[R-1055]【確定 #4-c / 導出】項目を実行するときは、メニューを閉じて一覧へフォーカスを戻して(R-1086)から、処理を呼ぶ。** 処理がダイアログを開く場合のフォーカスと、ダイアログを閉じた後のフォーカスは既存の仕様のとおり。
- **[R-1056]【提案 P-1011】メニューの表示中にディレクトリの再読込(ファイル監視による自動反映 SPEC-0300-0009 R-76 等)があっても、メニューを閉じない。** 実行時、対象はメニューを開いた時点のパスのうち、実行時に表示中の一覧に存在するものとする。対象が 0 件になった場合、または有効条件(R-1040)を満たさなくなった場合は、処理を呼ばずに、同じ処理をキー操作で起動したときと同じステータス表示を行う(コピー / カット / 削除 / 名前の変更 / パスのコピー: SPEC-0300-0011 R-10 の「選択がありません」相当、ZIP に圧縮: SPEC-0300-0014 R-307 の「対象がありません」相当、ZIP を解凍: R-308-1 の表の理由、開く / OSの関連付けで開く: 何もしない〈SPEC-0300-0015 R-402-1 と同じ〉)。表示中のディレクトリそのものが変わった場合(フォルダの削除による退避等)はメニューを閉じる(実行しない。R-1086 に従い一覧へフォーカスを戻す)。
  - **【第2版で追記】「ペースト」は、実行時にキー操作の `paste` と同じく OS クリップボードを読み直して取得元を決める(SPEC-0300-0011 第8版 R-19-2)。** メニューを開いた後に OS が変わっていればその内容に従う。OS にファイルが無くアプリ内も空になっていた場合は、処理を呼ばずにキー操作と同じステータス表示 `貼り付ける項目がありません` を出す。【導出】
  - **[R-1056-1]【承認後の追補・発注者決定 2026-10-03(設計監査 MUST-116 への回答)】メニューを開いた後に再読込等で選択が変わった場合は、項目を実行する直前に、選択をメニューを開いた時点の対象(R-1022)に戻してから実行する。** 選択は画面上で目に見えて戻る。戻すときは、実行時に存在しなくなった(表示中の一覧に無い)対象を除外する。対象がすべて無くなっていれば、選択を戻さず、本条項の前段(R-1056)どおり実行しない。行メニュー以外の項目(余白メニューの「新規作成...」「ペースト」)は選択を対象としないため本条項を適用しない。【選択を戻す範囲・フォーカス行の扱いの細部は設計工程】
    - **【第5版注記・例外。SPEC-0300-0021 R-1532】外部アプリの登録の項目(R-1030-1 / R-1031-1)には、本条項と R-1056 の後段(対象が無くなれば実行しない・ステータス表示)を適用しない。** 選択を戻さず(選択を変えない)、メニューを開いた時点の対象が消えた・種別が変わった場合は SPEC-0300-0021 R-1536 / R-1572(`「{name}」を起動できませんでした。対象が見つかりません。`)による。

### 7.2 パスのコピー

- **[R-1060]【確定 #1 / 提案 P-1004】「パスのコピー」は、表示中の対象のパスを、テキストとして OS のクリップボードへ書き込む。**
  - **[R-1060-1]** 各パスはエントリのパスの文字列そのもの(パスバーの表示と同じ。`\\?\` 接頭辞・大文字小文字もそのまま。SPEC-0300-0016 R-701-1)とする。引用符で囲まない。フォルダの末尾に区切り文字を付けない。
  - **[R-1060-2]** 複数のときは、一覧の表示順に並べ、`CRLF`(`\r\n`)で区切る。末尾に改行を付けない。
  - **[R-1060-3]** 成功したらステータス表示に `パスをコピーしました({n} 件)` 相当を表示する。書き込みに失敗した場合は、失敗した旨をステータス表示に出す(黙って失敗しない)。**【承認後の追補 G-1・【導出】(承認済みの設計 §3.9.15 で採用)】失敗時の文言は `パスをコピーできませんでした` とする。**
  - **[R-1060-4]【第2版で改訂】** アプリ内クリップボード(コピー / カットで保持する対象)を変えない。ただし OS クリップボードの内容はテキストに置き換わる(ファイル〈`CF_HDROP`〉は無くなる)ため、その後のペーストは SPEC-0300-0011 第8版 R-19-2 / R-19-4 / R-19-5 により次のとおりとなる。(1) アプリ内が空でなければ、ペーストは有効のままで、貼り付ける対象はアプリ内の対象。(2) アプリ内がカット由来でも、貼り付けはコピーになる(OS が別の内容になったため。元のファイルは残り、ステータスにその旨を併記)。**【承認時・発注者決定 E2】この扱いは「パスのコピー」に限らず、ビューアの本文のコピー(SPEC-0300-0015 R-464)、パスバー等の入力欄での Ctrl+C、他アプリでのコピーなど、OS クリップボードを変えるすべての操作で同じであり、発注者が安全側として確認した。**(3) 「パスのコピー」の前に OS にあった他アプリのファイルは貼り付けられなくなる(アプリ内が空ならペーストは無効になる)。

## 9. キー操作・閉じ方・フォーカス

- **[R-1080]【確定 #4-b】メニューの表示中、メニューが処理するキーは ArrowUp / ArrowDown / Enter / Escape のみとする。** これらはオーバーレイ内ローカルキー処理(SPEC-0300-0010 §3.1 分類 (c))であり、キーマップのカスタマイズ対象外である。→ SPEC-0300-0010 §3.1 への追記が必要(ISS-0187)。
- **[R-1081]【main / 提案 P-1018】開いた直後は、どの項目も強調しない。** ArrowDown は次の有効な項目へ、ArrowUp は前の有効な項目へ強調を移し、末尾の次は先頭、先頭の前は末尾へ回り込む(無効の項目・区切り線は飛ばす)。強調が無い状態での ArrowDown は先頭の有効な項目、ArrowUp は末尾の有効な項目を強調する。
- **[R-1082]【main】Enter は強調中の項目を実行する。強調が無い場合は先頭の有効な項目を実行する。** 有効な項目が無い場合は何もしない(メニューは開いたまま)。【後段は導出】
- **[R-1083]【main】Escape はメニューを閉じる(何も実行しない)。** 検索バーの表示中も、Escape はメニューを閉じるだけで、検索のキャンセル(SPEC-0300-0012 R-109-2-4)は起こさない(SPEC-0300-0010 R-13 によりオーバーレイが先に処理する)。
- **[R-1084]【確定 #4-b / 提案 P-1018】それ以外のキー(Tab / Shift+Tab、ArrowLeft / ArrowRight、Home / End、文字キー、Delete、Ctrl+C 等)は、メニューを閉じずに何もしない(処理済みとし、既定動作も抑止する)。** 一覧・ツリーのアクションは発火しない(SPEC-0300-0010 R-13)。Tab でフォーカスをメニューの外へ出さない(SPEC-0300-0010 R-10-1-2 と同じ)。優先1 の `Ctrl+Q` / `Ctrl+,` は有効(SPEC-0300-0010 R-14-3-2。~~`Ctrl+,` は設定画面が無い間は何もしない~~)。OS が処理するキー(Alt+F4、Windows キー、Alt+Tab 等)は止めない(WebView に届かない、または既定の処理に任せる)。
  - **【第6版・発注者決定 2026-10-18(SPEC-0300-0022【確定 T-25】案 A /【確定 T-26】)】メニューの表示中に `Ctrl+,` を押すと、メニューを閉じて元のフォーカス(R-1024)へ戻してから「設定ファイルを開く」(SPEC-0300-0022 R-1600)を実行する(同 R-1671-1)。** メニューの項目は実行しない。`Ctrl+Q` の扱いは変えない。
- **[R-1085]【導出】メニューの表示中、キーボードフォーカスはメニューの要素にあり、強調中の項目は `aria-activedescendant` で示す(項目は個別のタブストップにしない)。**
- **[R-1086]【確定 #4-c】メニューを閉じた後は、閉じ方(項目の実行、Escape、メニュー外のクリック、ウィンドウのサイズ変更 等)にかかわらず、常にファイル一覧へフォーカスを戻す。** フォーカス行は右クリック時に決めた行のまま(R-1020 / R-1021)。フォーカスを `document.body` に落とさない。(SPEC-0300-0009 R-34-17 のソートメニューと同じ規則)
- **[R-1087]【確定 #4-c】メニューの外を左クリック(または中クリック)するとメニューを閉じる。そのクリックはメニューを閉じるためだけに用い、下の要素(一覧の行、ツリーのノード、パスバー、検索バー等)には渡さない。** 選択・フォーカス行・展開状態・パスバーの編集状態を変えない。ダブルクリックの2回目も渡さない。
  - **【承認後の追補 G-4・【導出】(設計 §3.9.15)】ダブルクリックの2回目を遮断する時間窓は、メニューを閉じたクリックから 600ms とする。** その間に同じ位置付近で続く click / dblclick は下の要素へ渡さない。
- **[R-1088]【提案 P-1020】メニューの表示中にメニューの外を右クリックした場合は、メニューを閉じるだけとし、新しいメニューを開かない(WebView 標準メニューも出さない)。** メニューの中の右クリックは何もしない。
  - **【承認後の追補 G-5・【導出】(設計 §3.9.15)】メニューの表示中に、キーボード由来(Shift+F10 / ContextMenu キー)の `contextmenu`、およびポインター操作に由来しない合成の `contextmenu` が届いた場合は、何もしない(メニューを閉じず、新しいメニューを開かず、WebView 標準メニューも出さない)。**
- **[R-1089]【提案 P-1011】メニューの表示中は、次のとおりとする。** (1) メニューの外でのホイールは無視する(一覧・ツリーをスクロールさせず、メニューを閉じない)。メニューの中でのホイールはメニューが縦スクロール可能なときだけメニューをスクロールする。(2) ウィンドウのサイズ変更、ウィンドウが非アクティブになったとき(他のアプリへの切替)はメニューを閉じる(R-1086 に従い一覧へフォーカスを戻す)。

### 9.1 マウス操作

- **[R-1090]【main / 提案 P-1013】メニューの有効な項目にマウスを乗せると、その項目を強調する(キーの強調と同じ状態を共有する。乗せた後の ArrowUp / ArrowDown はその項目から移動する)。** 無効の項目・区切り線に乗せても強調しない。マウスがメニューから出ても強調は残す。

## 15. 受入基準

判定方法の使い分け(レビュー M-3): **WebView 標準メニューが抑止されるか**は、CDP の `Runtime.evaluate` で対象の要素に `new MouseEvent("contextmenu", { bubbles: true, cancelable: true, button: 2, clientX, clientY })` を `dispatchEvent` し、**戻り値が偽(= `preventDefault` された)であることで判定する**(本物の右クリックではネイティブのメニューが開いてテストを妨げるため)。**本物の右クリック**(CDP `Input.dispatchMouseEvent` で `button: "right"` の押下・解放)は、**アプリのメニューが開くこと・選択が変わることを確かめる AC にだけ使う**。標準メニューが実際に画面に出ないことは [目視] で確認する。

前提(共通): メインウィンドウ、ツリー表示、検索バー非表示、テスト用フォルダ(SPEC-0400-0001 R-06〜R-08)に `a.txt`・`b.txt`・`c.zip`・フォルダ `d` があり、名前の昇順で表示。特記しない限り一覧にフォーカスがあり、選択は空。

### 15.2 WebView 標準メニュー

- **[AC-1010]** Given 次の各要素 / When `contextmenu` の MouseEvent を `dispatchEvent` する / Then (i) パスバーの入力欄・検索入力欄・リネームのダイアログの入力欄では戻り値が真(抑止しない)、(ii) ステータスバー・パスバーのラベル・検索バーのボタン・ツリー・一覧の行・一覧の余白・メニュー自身では戻り値が偽(抑止)。実機の右クリックで (i) は標準メニュー(切り取り・コピー・貼り付け)が出て、(ii) は出ない。(R-1010, R-1011)[CDP][目視]
- **[AC-1012]** Given テスト用に、どのハンドラも持たない要素(例 `div`)をメインウィンドウの画面全体のコンテナに追加する / When その要素へ `contextmenu` の MouseEvent を `dispatchEvent` する / Then 戻り値が偽(個別の対応なしに抑止される)。同じ要素の中の `input` では真。(R-1012)[CDP]
- **[AC-1011]【D3】** Given ビューアウィンドウを表示中 / When 本文・リンク・画像を右クリックする / Then WebView 標準メニューが出ない。範囲選択して Ctrl+C でコピーできる(SPEC-0300-0015 AC-472)。判定方法の詳細は SPEC-0300-0015 AC-503-1。(R-1013)[CDP][目視]
