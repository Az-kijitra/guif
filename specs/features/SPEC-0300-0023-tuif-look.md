### 0.2 発注者決定(2026-10-22、AskUserQuestion、オーケストレーター経由で伝達。変更不可)

### 0.5 本仕様を新規に起こした理由(【導出】)

## 2. 配色の設定の書き方(`[theme]` / `[colors]`)

- **[R-1700]【確定 #1 / tuif】配色は `config.toml` の `[theme]` 表の `preset` で選ぶ(例 `[theme]` の下に `preset = "nord"`)。** `[theme]` の表では `preset` → `name` → `theme` の順に、最初に書かれているキーを使う(tuif と同じ。【確定 T-35】)。最上位の `theme = "nord"`(文字列)も同じ意味とする(【確定 T-35】)。
- **[R-1700-1]【レビュー S-3 / 確定 T-43】`[theme]` の表の `preset` / `name` / `theme` 以外のキーは「不明な設定」(SPEC-0300-0022 R-1643、W-AC)として通知し、無視する。** R-1700 で使ったキーより後の順位のキー(例: `preset` を書いたときの `name` / `theme`)は、既知のキーだが使われないため、「使われない設定」(W-B8)として通知する(【確定 T-43】。【再レビュー MINOR-2】起票時の「W-AC〈不明な設定〉」は、既知のキーには意味が合わないため改めた)。
- **[R-1701]【確定 #1 / tuif】プリセット名は、英字を小文字にし、`-`・`_`・空白を除いてから比べる。** 受け付ける名前(比べた後の形): `default`、`nord`、`monokai`、`catppuccin`(別名 `catppuccinmocha`)、`solarizeddark`(別名 `solarized`)、`light`。例: `"Solarized-Dark"`、`"solarized_dark"`、`"solarized"` はいずれも同じプリセット。
- **[R-1702]【確定 #1】`[theme]` が無いとき、`[theme]` の表に R-1700 のキーが無いとき、`config.toml` が無いときは `nord` とする。** tuif の「`ui_theme` をプリセット名として使う」(§0.3 の 3)は移さない(【確定 #2】)。
- **[R-1703]【確定 T-33 / T-34 / レビュー S-7】プリセット名が R-1701 のどれにも当たらないときは、`nord` を使い W-B0 で通知する。R-1700 で使うキーの値が文字列でないとき、最上位の `theme` が表でも文字列でもないときは、`nord` を使い W-B1 で通知する。** いずれも行番号つき。tuif は黙って `default` にする(§0.3 の 2)。
- **[R-1704]【確定 #1 / tuif / レビュー S-1 / 確定 T-42】`[colors]` の表で、16色の項目を個別に上書きする。** 項目名は §0.3 の 1 の16個と、別名 `background`(= `bg`)、`selected_mark`(= `selected`)。書かない項目はプリセットの値のまま。
  - **同じ項目を名前と別名の両方で書いた場合は、tuif と同じく `bg` と `selected_mark` を使う(【確定 T-42】)。** tuif は `toml` 0.8 の表(`preserve_order` 無し)をキーの名前順に走査し、後に処理した値で上書きするため、ファイルの中の順によらず `background` < `bg`、`selected` < `selected_mark` の順で後の `bg` / `selected_mark` が勝つ(起票時の「後に書いた方」と「表の走査の順」は誤りで、レビュー S-1 で改めた)。使われなかった方は「使われない設定」(W-B8)として通知する(【確定 T-42】。【再レビュー MINOR-2】で W-AC から改めた)。
- **[R-1705]【確定 T-33 / レビュー S-7】`[colors]` の値が R-1710 の書式として解釈できない項目、値が文字列でない項目は、その項目だけプリセットの値を使い、W-B2 で通知する。** 知らない項目名は「不明な設定」(W-AC)として通知し、無視する。`[colors]` が表でないとき(例 `colors = "red"`)は `[colors]` 全体を無視して W-B5 で通知する。
- **[R-1706]【確定 T-26 / tuif】`symlink` は受け付けるが、画面のどこにも使わない(tuif と同じ)。** 誤りの検査は他の項目と同じとする。
- **[R-1707]【導出(SPEC-0300-0022【確定 #3】)】誤りのある項目だけを既定(またはプリセットの値)にし、正しい項目は使う。** TOML として読めないときは、配色・フォント・`[layout]` もすべて既定(`nord`、R-1750 / R-1753 の既定のフォントと大きさ、`min_col_width` = 24、`tree_width_percent` = 24)とする(SPEC-0300-0010 R-45-2 (a) と同じ考え方)。

### 3.2 色の書式

- **[R-1710]【確定 #1 / tuif】`[colors]` の値は次の書式とする(前後の空白を除いてから解釈する)。**
  1. `#RRGGBB` / `#RGB`(`#RGB` は各桁を2つ重ねた値。例 `#0AF` = `#00AAFF`)。英字の大小は問わない。検証は R-1711。
  2. 256色の番号: ASCII の数字 `0-9` だけ(先頭に `+` を1つ置いてよい)で、値が 0〜255 の文字列。先頭の 0 は許す(`"007"` = 7、`"+5"` = 5)。tuif(Rust の `u8` の解析)と同じ扱いとする【レビュー MINOR-2。tuif の扱いは ISS-0238 (l) で確かめる】。`-` 付き・256 以上・空は無効。
  3. 色名: `black`、`red`、`green`、`yellow`、`blue`、`magenta`(別名 `purple`)、`cyan`、`gray`(別名 `grey`)、`dark_gray`(別名 `dark_grey`、`darkgray`、`darkgrey`)、`light_red`(別名 `lightred`)、`light_green`(別名 `lightgreen`)、`light_yellow`(別名 `lightyellow`)、`light_blue`(別名 `lightblue`)、`light_magenta`(別名 `lightmagenta`、`light_purple`、`lightpurple`)、`light_cyan`(別名 `lightcyan`)、`white`、`reset`(別名 `default`、`none`)。英字の大小は問わず、`-` と空白は `_` と同じに扱う(tuif と同じ。例 `"LightRed"`、`"light red"`、`"Light-Red"` はいずれも `light_red`)。【レビュー MUST-1】
  - CSS の色名(`teal` 等)、`rgb()` 等は受け付けない(tuif と同じ)。【導出】
- **[R-1711]【手直し (5) / 導出。起票時は R-1712(レビュー MINOR-4 で改番)】`#` で始まる値は、`#` の後が ASCII の16進の数字(`0-9` `a-f` `A-F`)だけで、ちょうど3文字か6文字のときだけ有効とする。** 全角の文字・その他の文字を含む値は、長さ(バイト数・文字数)によらず無効とし、処理を止めない(tuif の panic を移さない)。番号も ASCII の数字だけのときに限る(全角の数字は無効)。

## 9. 多列表示【確定 #4 / #7】

- **[R-1791]【確定 #4 / 確定 T-30】`config.toml` の `[layout]` の `min_col_width` で、1列の最小の幅を文字数(ch)で変えられる。** 10〜80 の整数、既定 24。範囲外・整数でないときは既定にし、行番号つきで通知する(W-B4)。`[layout]` が表でないときは W-B7。`[layout]` で読むキーは `min_col_width` と `tree_width_percent`(R-1804)の2つとし、他のキー(`time_format` を含む)は「不明な設定」(W-AC)とする(【確定 T-30】2026-10-23 の決定で改めた)。
- **[R-1792]【tuif / 確定 T-31】列の寸法は次のとおり求める。** W / H は一覧の枠の内側(見出しの帯と枠線を除く)の幅と高さ、n は表示中の件数(検索の絞り込みの後)。

```
rows      = max(1, floor(H / 行の高さ))                          // SPEC-0300-0009 R-16-1
minCol    = (min_col_width + (showSize ? 10 : 0) + (showTime ? 20 : 0)) × ch
total     = max(1, ceil(n / rows))                                 // 総列数
maxFit    = max(1, floor(W / minCol))
cols      = min(maxFit, total)                                     // 表示列数
focusCol  = floor(カーソルの位置 / rows)
startCol  = floor(focusCol / cols) × cols                         // ページの最初の列
shown     = min(cols, total − startCol)                           // このページに描く列の数
列の幅    = W を shown 等分(端数は右の列へ)
```

  - 【レビュー MINOR-6】最小の幅に加える数(サイズ +10、日時 +20)は tuif の式のままとし、セルの幅(サイズ 10ch、日時 16ch。R-1781 / R-1782)とセルの間(1ch)の合計(サイズ 11ch、日時 17ch)とは一致させない。日時の差(約 3ch)は名前の余裕になる。意図した差である(tuif の `min_col_width` の値をそのまま写したときに同じ列数になるようにするため)。
  - 列の幅に上限を設けない(SPEC-0300-0017 R-956 の 720px の上限をやめる。tuif と同じ)。
  - W が minCol に満たないときは cols = 1(列の幅 = W)とし、サイズ・日時のセルの幅を保って名前を狭める(SPEC-0300-0017 R-956-2 と同じ考え方)。
  - 計算は一覧の大きさ・件数・表示項目・カーソルの位置が変わるたびに行う(SPEC-0300-0009 R-17)。
- **[R-1793]【確定 #7 / tuif / 確定 T-32】画面外の列はページ単位で切り替える。** カーソルが表示中の列の外へ移ると、そのカーソルを含むページ(R-1792 の `startCol` から `shown` 列)を表示する。列を1列ずつ横にずらす表示(SPEC-0300-0017 R-958 の列単位の自動スクロールとスナップ)はやめる。マウスのホイール等で横に動かさないこと(R-958)と、表示倍率の変更を無効とすること(R-958-1)は変えない。

  - 描くのはそのページの列の行だけでよい(方式は設計工程)。マウスの当たり判定は表示中の列に対して行う。
- **[R-1794]【確定 #4 / tuif】右に隣の列がある列の右端に、縦の 1px の線(`--ui-border`)を列の高さいっぱいに引く。** 列の間の隙間(SPEC-0300-0017 R-955 の 16px)はやめ、線は左の列の幅の中に含める。
