### 3.3 振り分けと OS 関連付けアプリの起動

- **[R-404] 対象がファイルの場合は、§4 の判定に従い、ビューアで開くか OS の関連付けアプリで開くかを決める。**【発注者確定 #9】

  - **[R-405-1] フロントエンド(メインウィンドウ・ビューアウィンドウのいずれ)にも、opener プラグインの権限(任意パスを開けるスコープ `**` を含む)を与えない。** フロントエンドから opener プラグインの API を直接呼べないようにする。【発注者決定 2-#2】

  - **[R-405-5] OS の関連付けアプリの起動に失敗した場合(関連付けが無い、起動失敗等)は、黙って失敗せず、ステータス表示(`shared/state/status-message`)に失敗した旨を表示する。**【導出。`main` は判定の例外を握りつぶして関連付けアプリへ回し、その失敗の扱いは不明(調査§1, §7-6)】→ ISS-0124 (b)

## 4. 開く / 開かない判定(ファイル種別の分類)

### 4.1 判定の順序

- **[R-410] ファイルの種別は次の順に判定する。最初に該当したものを採る。**【発注者確定 #9。根拠: 調査§1 / main:app/src/lib/actions/external_open.ts:4-8, :117-150、調査§2(`detectKind`)】

| 順 | 条件 | 結果 |
|---|---|---|
| 1 | 拡張子が画像リスト(`png` / `jpg` / `jpeg` / `bmp`) | ビューア(画像表示、§10) |
| 2 | 拡張子が Markdown リスト(`md` / `markdown`) | ビューア(Markdown 表示、§9) |
| 3 | 拡張子がテキストリスト(R-411 の15種) | ビューア(テキスト表示、§8) |
| 4 | 拡張子が OS 関連付け直行リスト(R-414)【提案 → 発注者承認 2026-09-27】 | OS 関連付けアプリ(内容判定を行わない) |
| 5 | 上記以外(拡張子なしを含む) | 内容判定(R-412)。テキストと判定 → ビューア(テキスト表示)、バイナリと判定 → OS 関連付けアプリ |

- **[R-410-1] 拡張子の比較は大文字小文字を区別しない**(`README.MD` は Markdown)。拡張子は最後のドットより後ろとする(`a.tar.gz` の拡張子は `gz`)。先頭がドットのみの名前(`.gitignore`)は拡張子なしとして扱う。【導出】→ ISS-0123
- **[R-410-2] 種別の判定はバックエンド(Rust)で行い、ファイラー側の振り分け・ビューアでの表示形式・前後移動先の表示形式(R-493)で同一の判定関数を用いる。**【導出。`main` はファイラー側とビューア側で判定が別実装であり、バイナリがビューアで text 表示される不整合があった(調査§2, §7-4)】

### 4.2 拡張子リスト

- **[R-411] 拡張子リストは `main` の21種を踏襲する。**【発注者確定 #9。根拠: 調査§1 / main:app/src/lib/actions/external_open.ts:4-8、Evaluator所見】
  - 画像(4): `png` / `jpg` / `jpeg` / `bmp`
  - Markdown(2): `md` / `markdown`
  - テキスト(15): `txt` / `log` / `json` / `c` / `h` / `cpp` / `cc` / `cxx` / `hpp` / `hh` / `hxx` / `rs` / `js` / `ts` / `py`
- **[R-411-1] 不整合の整理方針(`mjs` / `cjs` / `tsx` / `html` 等)**: `main` ではビューア側の言語判定(シンタックスハイライト用)と拡張子リストが一致していなかった(調査§1, §7-4)。本仕様では**シンタックスハイライトを MVP 外とする(R-530)ため言語判定自体を持たず、拡張子リストは「内容判定を省略してビューアへ直行させる高速経路」という単一の役割に限定する**。これにより不整合は構造的に解消する。【導出】
  - リストに無いテキスト系拡張子(`mjs` / `cjs` / `tsx` / `jsx` / `css` / `toml` / `yaml` / `yml` / `xml` / `ini` / `csv` 等)は、順5 の内容判定でテキストと判定されればビューアで開く。**リストへの追加は行わない。**【提案 → 発注者承認 2026-09-27】→ ISS-0123
  - **`html` / `htm` は HTML としてレンダリングせず、テキスト(ソース)として表示する**(順5 の内容判定でテキストになる)。HTML レンダリングは MVP 外(R-530)。【導出】
- **[R-411-2] 拡張子リストはキーマップ・設定で変更できない**(固定)。【導出】

### 4.3 内容判定

- **[R-412] 内容判定は、ファイル先頭の最大 65,536 バイトのサンプルに対して次の順で行う。**【発注者確定 #9。根拠: 調査§4 / `fs_is_probably_text`(サンプル 65536B、空=真、UTF BOM=真、NUL を含む=偽、制御文字比率 > 10% =偽)】

| 順 | 条件 | 判定 |
|---|---|---|
| 1 | ファイルサイズ 0 | テキスト |
| 2 | 先頭が UTF-8 BOM(`EF BB BF`)/ UTF-16LE BOM(`FF FE`)/ UTF-16BE BOM(`FE FF`) | テキスト |
| 3 | サンプル中に NUL(`0x00`)を含む | バイナリ |
| 4 | サンプル中の制御文字(R-412-1)のバイト数 ÷ サンプルのバイト数 > 0.10 | バイナリ |
| 5 | 上記以外 | テキスト |

  - **[R-412-1] 「制御文字」は `0x01`〜`0x08`、`0x0B`、`0x0E`〜`0x1A`、`0x1C`〜`0x1F`、`0x7F` とする**(タブ `0x09`、LF `0x0A`、FF `0x0C`、CR `0x0D`、ESC `0x1B` は含めない)。【導出。`main` の厳密な定義は調査資料に無い】→ ISS-0123
  - **[R-412-2] 比率の閾値の比較は「10% を超える」(ちょうど 10% はテキスト)とする。**【発注者確定 #9 の文言「> 10%」】
  - **[R-412-3] 内容判定が I/O エラー(読込権限なし、共有違反等)で行えなかった場合は、OS 関連付けアプリへは回さず、ステータス表示にエラーを表示して何も開かない。**【提案 → 発注者承認 2026-09-27。`main` は例外を握りつぶし黙って関連付けアプリへ回す(調査§1, §7-6)】→ ISS-0123
- **[R-413] 内容判定は判定結果(テキスト / バイナリ)のみを返し、ファイルの内容をフロントエンドへ返さない。** 内容判定はファイラー側(メインウィンドウ)からの要求であり、ビューアの読込許可(§6)の対象外である。判定のコマンドも呼び出し元がメインウィンドウであることを検査する(R-432-3)。【導出】**【第6版注記】判定のコマンドも、渡されたパスが絶対パス(SPEC-0300-0016 第4版 R-722-3)でなければ内容を読まずに `invalid_path` を返す(R-412-3 と同じく関連付けアプリへ回さず、ステータス表示にエラーを表示する)。**

### 4.4 ビューアで扱わない画像形式

- **[R-414]【提案 → 発注者承認 2026-09-27】GIF / WebP / SVG 等の、ビューアが対応しない画像形式は、内容判定を行わずに OS の関連付けアプリで開く(OS 関連付け直行リスト)。** 直行リストの初期値は `gif` / `webp` / `svg` / `svgz` / `ico` / `tif` / `tiff` / `avif` / `heic` / `heif` とする。【導出。`main` は SVG(XML テキスト)をビューアで text 表示、GIF / WebP はバイナリ判定で OS 関連付けへ回すという不統一があった(調査§2, §7-4)】→ ISS-0123
  - **本条項は発注者確定 #9(「対象外拡張子は内容判定」)の追補・例外にあたる**(SVG のようにテキストでも内容判定を行わず OS 関連付けへ回すため)。承認時に確定 #9 の例外として判断を要する。(spec-reviewer M-1)
  - 採用しない場合、SVG は内容判定でテキストと判定されビューアでソースとして表示される。

| 順 | 条件(読み込んだ範囲の先頭 / 全体) | 判定 | BOM |
|---|---|---|---|
| 1 | 先頭が `EF BB BF` | UTF-8 | 除去して表示 |
| 2 | 先頭が `FF FE` | UTF-16LE | 除去して表示 |
| 3 | 先頭が `FE FF` | UTF-16BE | 除去して表示 |
| 4 | 読み込んだ範囲全体が UTF-8 として妥当(R-453 の末尾の扱いを含む。ASCII のみの場合を含む) | UTF-8 | — |
| 5 | 上記以外 | CP932(`encoding_rs` の Shift_JIS デコーダ) | — |

  - **[R-450-1] 順5 で CP932 としてデコードできないバイト列は置換文字(U+FFFD)として表示する**(表示を中断しない)。【導出】
  - **[R-450-2] BOM の無い UTF-16、UTF-32、その他の文字コード(EUC-JP、ISO-2022-JP 等)は判定の対象外とする。** これらは順4 / 順5 のいずれかとして表示され、文字化けしうる。BOM の無い UTF-16 は NUL を含むため、拡張子リスト外であれば R-412 でバイナリと判定され OS 関連付けで開かれる。【導出】
  - **[R-450-3] `encoding_rs` の Shift_JIS デコーダ(WHATWG Encoding Standard の Shift_JIS。Windows の CP932 相当)を用いる。** ZIP のエントリ名(SPEC-0300-0014 R-347、ISS-0099)と同じデコーダとする。【発注者確定 #3】
  - **[R-450-4]【第2版で新設(spec-reviewer L-6)】R-453 (b) / (c) は切り詰めた場合の規定である。切り詰めていない(ファイル全体を読んだ)場合に、UTF-16 のバイト数が奇数、末尾がペアの相手の無い上位サロゲート、または CP932 の末尾が2バイト文字の1バイト目で終わるときは、当該バイトを除かず R-450-1 と同様に置換文字(U+FFFD)として表示する。**【導出】
- **[R-451]【提案 → 発注者承認 2026-09-27】判定した文字コード名(`UTF-8` / `UTF-8 (BOM)` / `UTF-16LE` / `UTF-16BE` / `Shift_JIS`)をヘッダー領域に表示する。** 切替 UI が無いため、文字化け時に利用者が原因を把握できるようにする。→ ISS-0125
- **[R-452] 改行は CRLF / LF / CR のいずれも1つの改行として扱う。**【導出】
- **[R-453] 上限(R-445)で切り詰めた場合の末尾の扱い**:【発注者確定 #4。細部は導出】
  - (a) UTF-8: 末尾に不完全なマルチバイト列(妥当な先頭部分のみで 1〜3 バイト)がある場合はそれを除いて表示する。このとき末尾の不完全な列は順4 の判定を妨げない。**切り詰めていない場合(ファイル全体を読んだ場合)は、末尾の不完全な列は不正とみなす**(順5 へ進む)。
  - (b) UTF-16LE / BE: 読み込んだバイト数が奇数の場合は最後の1バイトを除く。最後のコード単位がペアの相手の無い上位サロゲートの場合はそれも除く。
  - (c) CP932: 最後のバイトが2バイト文字の1バイト目にあたる場合はそれを除く。
  - (d) 除いたバイトは表示せず、置換文字(U+FFFD)も表示しない。
  - (e) 切り詰めていない場合の同種の末尾は (b) / (c) の対象外とし、R-450-4 に従う。
- **[R-454] 文字コードの判定は読み込んだ範囲(最大 2 MiB)に対して行う。** 読み込まなかった範囲は判定に影響しない。【導出】

## 19. 受入基準

- **形式**: すべて Given(前提)/ When(操作)/ Then(期待結果)で記す。( )内は対応条項。【第2版で統一(M-9、ISS-0134)】
- 【承認済み: ISS-xxxx】は、第2版まで【保留】としていた受入基準で、2026-09-27 の発注者承認により提案どおり確定したものである(Phase 6 の受入対象)。【後続フェーズ】は Phase 6 の受入対象外。
- 検証方法の注記が無いものは、バックエンド / フロントエンドの単体テスト、またはビルドしたアプリでの手動確認のいずれかで検証する(手動確認はチェックリストに項目 ID で列挙する。SPEC-0200-0001 SHOULD-84 と同じ運用)。

### 19.1 起動・振り分け(§3)

- **[AC-400]** Given ファイル一覧でテキストファイル `a.txt` にフォーカスがある / When Enter を押す / Then ビューアウィンドウが開き `a.txt` の内容が表示される。(R-401, R-404, R-410)
- **[AC-401]** Given ディレクトリ `d` にフォーカスがある / When Enter を押す / Then ビューアは開かず、ファイル一覧が `d` の内容に切り替わる。(R-403)
- **[AC-402]** Given `a.txt` / `b.txt` / `c.txt` の3件を選択し、フォーカスが `b.txt` にある / When Enter を押す / Then ビューアに `b.txt` のみが表示され、他の2件は開かれない。(R-402)
- **[AC-403]** Given ファイル一覧に `a.txt` とディレクトリ `d` がある / When `a.txt` の行をダブルクリックする / Then ビューアに `a.txt` が表示される。When `d` の行をダブルクリックする / Then ビューアは開かず、一覧が `d` の内容に切り替わる。(R-401 経路 2, R-402-2, R-403)
- **[AC-403-1]【第2版で新設】** Given `b.txt` / `c.txt` が選択されている / When `a.txt` の行をダブルクリックする / Then ビューアに `a.txt` が表示され、ファイル一覧の選択はクリックによる変化(SPEC-0300-0009 R-50 のとおり `a.txt` のみ)の後の状態のまま残り、開く処理によってそれ以上変化しない。(R-401-5, R-407)
- **[AC-403-2]【第2版で新設】** Given ファイル一覧に複数の行がある / When 行をクリック、Shift+クリック、Ctrl+クリックする / Then SPEC-0300-0009 AC-32 / AC-33 / AC-34 のとおり選択が変化する(受入基準の正本は SPEC-0300-0009)。(R-401-5)
- **[AC-404]【後続フェーズ → 第4版で Phase 10 の受入対象】** Given 選択がちょうど1件(`a.txt`)/ When 右クリックメニューを開いて「開く」を押す / Then `a.txt` がビューアで開く。Given 選択が2件以上 / When 右クリックメニューを開く / Then 「開く」は無効である。(R-401 経路 3, R-401-1)
  - **【第4版・D1】** 「選択」は表示中の対象をいう。Given 選択2件のうち1件(`b.txt`)が絞り込みで非表示 / When 表示中の `a.txt` で右クリックメニューを開く / Then 「開く」は有効で、押すと `a.txt` が開く。検証の詳細は SPEC-0300-0018 AC-1022 / AC-1030。[CDP]
- **[AC-405]【第2版で保留を解除】** Given `a.txt` にフォーカスがある / When Shift+Enter を押す / Then ビューアは開かず、バックエンドの起動コマンドが `a.txt` の canonicalize 後のパスで OS 関連付けの起動を行う(起動処理の呼び出しを単体テストで、実際の起動を手動確認で検証)。(R-401-2, R-405, R-405-2)
- **[AC-405-1]【承認済み: ISS-0124 (c)】** Given ディレクトリにフォーカスがある / When Shift+Enter を押す / Then フォルダ移動も外部アプリの起動も行われない。(R-401-3)
- **[AC-405-2]【第2版で新設】** Given アプリのビルド成果物 / When メイン・ビューアの capability を確認する / Then opener プラグインの権限(パスのスコープを含む)がいずれのウィンドウにも付与されていない。When フロントエンドから opener プラグインの API を直接呼ぶ / Then ACL により拒否される。(R-405-1)
- **[AC-405-3]【第2版で新設】** Given ビューアウィンドウ / When OS 関連付け起動のコマンドを呼ぶ / Then 拒否される。Given メインウィンドウ / When 存在しないパス・ディレクトリのパスで起動コマンドを呼ぶ / Then それぞれ `not_found` / `not_a_file` となり何も起動しない。(R-405-2, R-405-3)
- **[AC-405-5]【承認済み: ISS-0124 (d)】** Given ツリーパネルにフォーカスがある / When Shift+Enter を押す / Then フォルダ移動も外部アプリの起動も行われない。Given ファイル一覧でファイルにフォーカスがある / When Shift+Enter を押す / Then AC-405 のとおり起動される。(R-401-6)
- **[AC-405-4]【第2版で新設】** Given `setup.exe` にフォーカスがある / When Enter を押す / Then 追加の確認なしに OS の関連付け(実行)で起動される(手動確認)。(R-405-4)
- **[AC-406]** Given 検索入力欄にフォーカスがある、またはダイアログ / 履歴一覧が表示されている / When Enter / Shift+Enter を押す / Then ファイルは開かれない。(R-401-4)
- **[AC-407]** Given 検索で絞り込み中で、フォーカス行が絞り込み結果に含まれない / When Enter を押す / Then 何も開かれない。(R-402-1)
- **[AC-408]【承認済み: ISS-0124 (b)】** Given 関連付けアプリの無い拡張子のバイナリファイルにフォーカスがある / When Enter を押す / Then 起動に失敗した旨がステータス表示に出る。(R-405-5)
- **[AC-409]** Given ファイル一覧に表示されている `a.txt` を、開く直前に外部で削除した / When Enter を押す / Then ステータス表示に「見つからない」旨が出て、ビューアは(未表示なら)開かれない。Given 既にビューアで `b.txt` を表示中 / When 同じ操作をする / Then ビューアは `b.txt` の表示のまま残る。(R-406)
- **[AC-410]** Given ファイル一覧のフォルダ・フォーカス・選択と訪問履歴の状態を記録しておく / When Enter でファイルをビューアで開く / Then 訪問履歴に記録されず、ファイル一覧のフォルダ・フォーカス・選択は変わらない。(R-407)
- **[AC-411]** Given `a.txt` の読込が遅延するテスト条件 / When `a.txt` → `b.txt` の順に開く要求を行い、`a.txt` の読込が `b.txt` より後に完了する / Then 最終的な表示は `b.txt` である(単体テストで読込完了順を入れ替えて検証)。(R-409, R-431)

### 19.5 文字コード(§7)
